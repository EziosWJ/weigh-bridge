# 按厂区隔离称重业务，共享基础资料

2026-10-21，客户确认两个厂区，每厂各一台地磅及独立工控机、打印机等设备。用户决定使用一套 Server 与数据库，以厂区作为任务、称重记录、单据和设备的归属及操作员业务数据隔离边界，管理人员可跨厂区查询汇总；物料与往来主体等基础资料统一维护并共享，以支持统一资料管理和跨厂汇总。用户可获多个厂区授权，厂区数据范围与现有业务动作权限共同决定可查询和可操作的范围，跨厂查询不自动赋予跨厂操作权。该决定调整原单厂区、单地磅的业务范围；用户随后已授权实施，代码与软件验证结果见[实施记录](../requirements/multi-site-delivery.md)，现场升级尚未执行。

同一运输任务的两次称重在同一厂区完成，跨厂运输分别建立任务；同车未完成任务的唯一性按厂区判断。相比全局车牌占用，这使两厂能够独立办理业务；同时不合并跨厂称重依据。后续数据库归属、权限校验、列表汇总与导出、设备命令和打印均须遵守该边界。完整范围与验收条件见[确认需求](../requirements/multi-site-discovery.md)。

单据显示厂区名称、单号保持系统内唯一，打印与补打固定送往单据所属厂区的打印机。现有数据全部归入原厂区，新增厂区从空业务数据开始；共享资料沿用既有维护权限。新增独立菜单，以厂区面板作为称重台入口，只展示已授权厂区，只有查询权限时不提供操作工作台入口；每个工作台窗口固定对应厂区及地磅，允许获授权用户并行打开不同厂区工作台。

2026-10-22 目标架构调整：因互联网不稳定，用户确认每厂本地独立办理、中心统一资料并自动同步汇总，见 [ADR 0021](0021-local-weighing-authority-and-central-sync.md)。该决定替代本文“一套 Server 与数据库”的部署前提；厂区业务隔离、同厂两次称重、共享资料和权限边界继续保留。新部署与同步尚未实现。

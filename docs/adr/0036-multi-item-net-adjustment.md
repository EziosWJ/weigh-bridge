# 同一单据支持多项净重调整，厂云同步升至 v5

2026-11-07 客户确认：同一单据可同时按比例扣水分、按重量扣杂质等多笔原因，各比例项均以调整前净重为基数、各自四舍五入到 0.001 吨后相加。本决定扩展 [ADR 0035](0035-net-weight-adjustment.md) 的单项净重调整；该 ADR 的毛皮重更正、原始依据保留和版本规则继续有效。

## 决定

- 单据保存零项或多项净重调整明细。每项保存方式（按吨／按比例）、录入值、折算量（正数扣减、负数上调）、类别编码及名称快照、备注；单据同时保存有符号合计，供列表、汇总和纸单使用。
- 多项时各比例项共用调整前净重（最终毛重减最终皮重）为基数，各自独立四舍五入到 0.001 吨后相加；不按前序扣减后的余额累进计算。合计后最终净重须大于零；上限仍为最终毛重。
- 正常回磅、人工补录回磅和更正重开均接受多项；正常出单各项均不得上调，仅更正重开允许。非零项类别必填，各项备注独立保存；历史单项继续按原字段展示，不补造明细。
- 重开时新单完整保存本版明细，原单快照不变；带出上版明细仅供编辑。
- 单据明细整体作为快照列保存，字典后续改名不影响历史单；列表、汇总、现有纸单显示合计，详情和多项目 CSV 追加明细行。
- 厂云同步：新变化使用 `schemaVersion 5`、`digestVersion 3`，`ticket.netAdjustments` 为必填数组，`netAdjustment` 仍为有符号合计；v5 不再以单据级单项字段描述整单。摘要版本 3 覆盖明细内容及顺序。
- 已入队的 v3／v4 变化保留原协议、载荷和摘要，按原版本重试；同一单据不混用协议。云端支持 v5 前，新变化留在厂端队列，不降级、不丢明细，也不阻塞本地出单。

## 取舍

把多笔原因压成一个合计或只保留最后一笔会丢失原因、比例和校对依据，导出与对账也无法还原。用明细列表并保留合计，让业务录入、票面简洁与云端统计各自得到合适口径；代价是新增明细快照列、v5 出队列表和摘要规则版本，云端必须另行实现 v5 才能接收新单。

不按累进方式计算比例，是因为客户按“同一批货的原始净重”统一核扣水分和杂质，累进会因录入顺序改变结果，也可能与现场协商口径不一致。

## 影响

- 新增 schema migration `00039_net_adjustment_items_v5.sql`：`wb_ticket.net_adjustment_items` 与 v5 出队列表；旧表、旧迁移保留，回退需恢复升级前备份。
- 出单、人工补录回磅和更正重开入参新增 `netAdjustments` 数组；旧 `netAdjustment` 单项继续被接受并按一项处理。
- 厂端新增 v5 摘要向量 `server/internal/weighing/testdata/digest_v3_vectors.json`，云端实现时须共同校验。
- 云端必须在发布新厂端前支持 v5 并用共同向量验证；否则含多项调整的新单不会同步，但本地业务与明细不受影响。

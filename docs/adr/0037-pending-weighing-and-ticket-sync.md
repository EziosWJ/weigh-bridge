# 待回磅状态与正式磅单分别上送

总部需要知道厂区哪辆车在等回磅，也需要查到已经终止的任务。厂端继续办理任务和出单，通过 HTTP 分别上送运输任务状态和正式磅单。两类数据可以独立重试，云端按实际收到的数据展示，正式统计使用有效磅单。

如果云端等收到磅单才更新任务，现场已经出单的车辆会继续被算作待回磅；如果收到出单状态就移除任务，总部会在磅单到达前失去查询线索。云端收到出单状态后，先显示「已出单，待上传」并从待回磅数量中排除，收到对应磅单后移出任务列表。若磅单先到，出单状态到达时直接移出。终止任务保留在同一列表供筛选。

两类数据需要用明确的磅单标识关联。任务状态重复投递或乱序到达时，以厂端任务的最新版本为准。首期范围和时效要求见[厂云同步契约](../requirements/cloud-sync-contract.md#待回磅同步首期已确认范围)。

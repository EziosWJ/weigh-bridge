# 柯力 D12 仪表并入单一现场 Agent

2026-10-22，用户授权按[现场接入指导](../device/keli-d12-agent-integration-guide.md)完成柯力 D12 仪表与真实现场 Agent 的对接。本文记录本轮实现与验证边界，不改变[每台地磅只允许一个 Agent](0019-one-agent-per-scale.md)和 Agent 自有模拟的既有决策。

## 背景

现场 `fcc-com-01` 的 D12 通过内置串口 `/dev/ttyS0` 以 9600 8N1、无流控、`tF=05` 连续输出 18 字节报文。2026-10-22 带载抓包 868 帧验证了本机校验规则 `CKS = sum(frame[0:16]) & 0xff`，同时发现状态字 B bit4 的文档含义为 kg，但现场确认显示数值实际为吨。点位另有打印 Agent，已承担 Server 身份、打印账本和 kick 生命周期。

## 决策

1. 串口读取并入现有 `agent-printer` 进程，不另起重量 Agent；共用一个 WSS 连接、一个地磅身份和同一套配置应用／回退。打印在独立工作协程内串行执行，串口采集、状态上报和 kick 不受打印阻塞。
2. 解析器放在独立包 `server/internal/agentscale`。按固定 18 字节和 CR 位置拆帧，校验只接受本机带载验证过的累加规则；错误候选逐字节重同步，缓存有界。坏帧不更新最后有效时间，不提供“忽略校验”的降级模式。
3. 仪表现场源单位显式配置，默认按本机确认的 `t` 解释；不使用 B bit4 自动换算或再次除以 1000。其他仪表或固件另行抓包确认。原始状态位、原始帧和源单位一并保留。
4. 重量用整数／精确十进制换算为 `0.001 t`。`agentproto.Weight(1550)` 表示 1.55 吨；无法无损表示的精度、负值、异常位、净重模式或未知单位明确报告为不可采集，不伪造正常值。
5. 稳定状态只取仪表动态位 B bit3。串口成功打开、WSS 心跳、重复出现的相同重量都不构成稳定或新鲜。打开后必须收到新的完整有效帧；无新帧超过配置阈值（默认 1000 ms）即故障并使稳定失效。连续 3 帧校验／结构错误同样立即故障，收到有效帧后恢复。
6. 维护服务只读 Agent 原子写入的 `scale-status.json`，不打开串口。Agent 停止或状态文件过期时，页面显示过期／未运行，不把磁盘上的 `stable:true` 当作当前重量。
7. 摄像头仍未接入。收到 `capture.request` 时，Agent 以原 `requestId` 回复 `capture.result`、`success:false` 和明确原因，不伪造图片或采集成功。正式称重仍由操作员确认并经 Server 校验。

## 后果

- 现有打印配置、身份、密钥、账本和 kick 行为保持不变；旧 `agent.env` 未配置串口时继续按仅打印运行。
- 现场源单位是本机确认的配置事实，不能推广为所有 D12 的默认单位。部署到其他仪表必须重新核对单位、固件、校验规则和异常分支。
- 真实非零重量、面板稳定灯对照、负值／净重／非零皮重、其他固件、长期运行和重启后的串口权限仍需现场验证；软件测试和零值／故障恢复现场验证不能替代这些项目。
- 完整正式采集闭环仍缺摄像头证据链，当前只提供真实重量预览与稳定判定。

实现、测试、现场部署和回退信息见[交付记录](../requirements/d12-agent-integration-delivery.md)。

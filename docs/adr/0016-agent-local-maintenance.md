# Agent 本地维护与云端业务入口分工

> **2026-10-22 效力：部分被替代，过渡实现继续可用。** 最终维护入口与账号纳入本地业务服务，独立维护服务／密码仅作过渡，替代能力验收后退出；配置来源、明确应用、作业保护、结果核实与审计继续有效。维护 HTTP 取舍不自动扩大到业务服务。当前依据见 [ADR 0023](0023-standalone-site-baseline.md)及[基线索引](../development-baseline.md)；下文历史正文保留。

2026-10-20，用户确认现场 Agent 的管理主要由维护人员执行，现场操作员需查看状态以排查问题，且云端断连时仍要能够维护。为满足断云排障需求，选择由 Agent 电脑提供可独立于云端使用的本地维护页面，现有后台保留状态展示与业务入口；首期不增加云端远程配置或服务控制能力。

完全放在云端后台会使断云时失去维护入口；同时实现本地与云端远程控制则需要扩展运维协议及结果核实机制，超出当前确认范围。

用户进一步确认允许本机与局域网访问，不开放公网；维护入口独立于打印 Agent 进程，以便 Agent 停止、崩溃或无法启动时仍可查看日志、修改配置并启动它。代价是需要分别管理维护服务与打印 Agent 的生命周期；维护服务自身故障通过系统工具处理。

身份验证采用独立于后台账号的本地维护密码，断云仍可维护，首期不建设多用户管理。状态与排障摘要可只读访问，完整日志、配置修改及维护操作需验证维护密码。首期分别通过用户级 systemd 管理维护服务与打印 Agent。

本地维护不改变 Server 的业务权威、人工确认或断网暂停正式称重规则，正式单据打印、补打与结果核实仍沿用现有业务入口。

用户随后授权 GPT-6 Luna 实施并由根代理 review；首期代码已实现并完成审查与受控验证，真实设备部署仍待现场验收。范围见[首期需求](../requirements/agent-maintenance-spec.md)，准确验证结果见[交付记录](../requirements/agent-maintenance-delivery.md)。

2026-10-21 根据现场反馈，用户进一步确认统一打印运行配置来源及默认局域网 HTTP 访问策略，见 [ADR 0017](0017-agent-maintenance-config-and-lan.md)。该后续决策延续本文的本地维护职责边界；页面及验收范围见[改版需求](../requirements/agent-maintenance-revision-spec.md)，后续授权实施及验证结果见[改版交付记录](../requirements/agent-maintenance-revision-delivery.md)。

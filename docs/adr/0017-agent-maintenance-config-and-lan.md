# 本地维护配置来源与局域网访问策略

> **2026-10-22 效力：部分被替代，过渡实现继续可用。** 最终维护入口与账号纳入本地业务服务，独立维护服务／密码仅作过渡，替代能力验收后退出；配置来源、明确应用、作业保护、结果核实与审计继续有效。维护 HTTP 取舍不自动扩大到业务服务。当前依据见 [ADR 0023](0023-standalone-site-baseline.md)及[基线索引](../development-baseline.md)；下文历史正文保留。

2026-10-21，现场反馈发现启动参数与维护页配置不同步，且现有监听／TLS 限制不符合局域网使用方式。用户经需求讨论确认以下决策。决策已接受，用户随后授权实施，改版代码及受控软件验证完成；真实工控机升级和现场验收仍未完成。首期历史见[首期交付记录](../requirements/agent-maintenance-delivery.md)，实施与验收依据见[改版需求](../requirements/agent-maintenance-revision-spec.md)，本次验证结果见[改版交付记录](../requirements/agent-maintenance-revision-delivery.md)。

打印 Agent 的受维护运行参数统一以 `agent.env` 为来源，维护页区分草稿、已保存和当前生效配置。发布的 systemd unit 不再重复传入 Server、Agent 编号、地磅编号及队列等配置参数。保留命令行和环境变量两套可编辑来源会持续造成覆盖关系不透明，故选择统一部署来源；旧 unit 自定义参数由维护人员按升级说明迁入 `agent.env`，不自动解析任意旧启动命令。代价是升级前必须核对有效配置，保留原身份、密钥与打印尝试记录，避免因默认值覆盖或身份变化影响已有账本。

本地维护服务改为默认监听 `0.0.0.0`、通过 HTTP 提供同一可信维护网段访问，允许配置回环监听，TLS 保留为可选能力。此决定替代首期部署要求中的“默认回环、局域网必须指定私网 IP 并强制 TLS、禁止通配监听”，原因是现场希望直接通过局域网访问，减少证书配置与维护负担。代价是 HTTP 不加密维护密码和登录会话；用户明确接受这一可信内网边界。部署必须通过防火墙限制来源至地磅房维护网段，不开放或转发公网端口。本地维护密码、只读／维护权限划分、接口鉴权及敏感信息脱敏继续适用。

上述选择延续 [ADR 0016](0016-agent-local-maintenance.md) 的独立本地维护与断云可用边界。这里的 HTTP 选择仅适用于本地维护入口，不修改 Agent 与 Server 的 WSS 约定；本次设备页仅展示未接入状态，仪表／摄像头实际配置、采集和预览仍随设备驱动阶段实现。

# 本厂编码身份与过磅单号

本地编码固定及作为业务关联键的决定已由 [ADR 0034](0034-editable-local-identity.md) 取代；单号格式和防重复目标继续有效。

2026-10-27：总部为各厂预分配厂区编码，本地安装时填写，编码替代数字厂区 ID、地磅 ID 成为唯一业务身份；过磅单号改为“厂区编码-北京时间出单日期-当日流水号”。取代 ADR 0031 的自动身份与随机单号，身份隔离、权限、设备及 ADR 0032 冻结规则继续有效。

## 身份与初始化

- 厂区编码由总部或实施方预先分配，安装时通过初始化接口在本地填写；正则沿用 `^[A-Za-z0-9_.-]{1,40}$`，跨厂唯一性本地无法验证，未来云端绑定时检查。地磅编码默认 `WB01`，在厂区内唯一；两者确定后不可修改，厂区与地磅名称继续可维护。
- 取消 Server 启动时自动建立身份（ADR 0031 修订）：`wb_local_identity` 不再持有数字 site_id，改存 `site_code` 与 `scale_code`。未配置时 Server 可启动、可登录，但不办理正式业务、不接入 Agent；配置由具备配置管理（`system:config`）或原本厂配置权限（`weighing:site:manage`）的管理员在配置管理完成（后端接受任一权限），首次配置事务建立厂区、地磅、绑定与安装管理员授权，身份缺失但已有业务数据时仍拒绝重建、不清库。旧 `site-config/initialize` 的数字 siteId 字段退役。
- `wb_site` 以 `code` 为主键，删除数字 id；`wb_scale` 以 `(site_code, code)` 为复合主键并删除数字 id。单个数据库只属于一个厂区，地磅编码在此仍保持数据库内唯一，使按 `code` 的既有子表外键保持有效；跨厂唯一性只在云端绑定时检查。所有业务、授权、设备表上的 `site_id`/`scale_id` 列在迁移中回填编码后删除，历史行与引用保留。内部业务主键继续用数字代理键，`wb_local_identity.next_id` 分配器去掉 site_id 乘数，改用纯时间下限（2026-01-01 后毫秒×32，上限 2^45，含超限错误）。
- 业务行主键不再可从厂区推导，换取编码跨厂可读、未来云端直接识别；单库内仍全局唯一。

## Agent 通信

- Agent 仍只填 Server 地址。协议提升到 v3：`agent.hello.ack` 返回 `siteCode`、`scaleCode`，不再返回数字 `siteId`/`scaleId`；Server 在 hello 阶段明确拒绝 v1／v2（`agent_protocol_unsupported`），Server／Agent／mock 须协同升级，旧 Agent 不能继续用于正式称重。
- Agent 打印账本目录改按 `(serverURL, agent, scaleCode)` 隔离：未经身份绑定的历史账本在首次运行时就地绑定，已绑定旧数字地磅 ID 的账本保留在原目录并被新编码身份视为另一份账本（新身份使用独立子目录），不改写历史去重键，也不因此重发历史打印。
- 设备维护接口的 SiteID/ScaleID 数字字段全部改为编码；旧维护连接配置文件里要求数字 ID 的校验退役。Agent 图片编号按 `<scaleCode>_<32位hex>_<view>.<ext>` 结构解析前缀（不按第一个下划线截断），合法含下划线的地磅编码可正常归属与读取。

## 过磅单号

- 新单号 `厂区编码-YYYYMMDD-NNNN`（如 `F001-20261027-0001`），日期按北京时间，流水号按 `(site_code, kind, business_date)` 由 `wb_number_sequence` 原子分配（`INSERT … ON CONFLICT … RETURNING`），与出单同事务，支持并发与断网出单。任务号、测试单号沿用同一结构（`kind` 区分）。
- 流水号容量：至少四位（`%04d` 为最小宽度），超出 9999 后自动扩展，不设固定上限；单号列 VARCHAR(100)，物理上限由单号长度约束。分配沿用 `next_value` 递增语义，超过四位不影响已有历史单号。
- 备份恢复可能导致流水号倒退；正式恢复流程暂缓决策，待实际使用后确定。为避免误用，实现提供只升不降的安全网：分配时以库内当日同前缀最大单号兜底，并在图片数据目录保存 `ticket-watermark.json` 高水位（临时文件写入后原子替换并 fsync，文件损坏或为空时拒绝发号而不是静默归零；仅恢复数据库时仍能防重用）；管理员还可在配置管理“流水号水位”按日期上调水位（只允许上调、留审计，取值须大于 0 且不超过 BIGINT 安全上限）。整体恢复数据目录时该文件也会回退，仍需人工核实已发单号。历史单号不改写，作废重开使用新号、补打沿用原号。
- 历史随机单号（`GB-SITE-01-<hex>` 等）不改写；同一厂区内新旧两种单号通过唯一约束共存。

## 兼容与迁移

- 新增 Goose migration 就地迁移：由现有 `wb_site.code`（如 `SITE-01`）回填所有业务行的 `site_code`，地磅编码沿用 `wb_scale.code`；保留历史行、授权、绑定、图片、账本与启停状态。已初始化的现有库迁移后即视为已配置，不重新走安装填写；新装库才走安装编码填写。
- Web 端 `capabilities.localSiteId`、`?scaleId=`、授权 `siteId` 等契约全部改为编码（`localSiteCode`、`?scale=`、`siteCode`），工作台 URL、窗口标识、会话与设备查询同步；历史单据列表的厂区列改按保存的 `site_name`/`site_code` 显示。

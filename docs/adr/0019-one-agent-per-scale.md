# 每台地磅只允许一个 Agent 在线

2026-10-21，用户确认真实 Agent 与 mock 应当互斥：每台地磅同一时间只允许一个 Agent 在线，由该连接承担采集、识别、抓拍及打印等设备通信，mock 为真实 Agent 的替代实现。为保持一台地磅对应一个现场代理的模型，不采用采集与打印分别绑定不同 Agent 的方案；两个厂区的地磅分别管理连接和状态，互不影响。用户随后已授权实施，代码与软件验证结果见[实施记录](../requirements/multi-site-delivery.md)，现场升级尚未执行。

用户随后明确要求后台提供踢出 Agent 的功能，Agent 接收 kick 后结束运行；同磅已有连接时保留已在线者、拒绝后来者，需要替换时由有权限人员主动踢出后再启动替代 Agent。这调整现有协议“同身份新连接替换旧连接”的规则，以避免真实 Agent 和 mock 自动重连互相抢占。

Q15～Q18 随后确认：kick 立即生效，真实 Agent 与 mock 均正常退出整个进程，停止本轮自动重连且不得被守护立即重启；不永久封禁身份，允许人工启动或工控机重启后再次接入。踢出需要独立动作权限及目标厂区操作授权并记录审计，普通操作员默认无权限。未确认采样失效，无最终回执的打印保留结果未知、人工核实且不自动重发；已提交的业务不撤销，打印机既有作业可能继续出纸。

该决定延续 [ADR 0015](0015-agent-owned-simulation.md) 的统一设备处理链路，不引入模拟与真实两套业务流程。当前真实 Agent 只有打印能力，仪表和摄像头未接入；互斥后不能以 mock 提供采集、真实 Agent 提供打印的方式组合运行，完整真实设备能力需后续交付。范围与验收条件见[确认需求](../requirements/multi-site-discovery.md)。

# 单厂编码可维护与本地业务去关联

每套本地数据库只服务一个厂区和一台地磅。厂区与地磅编码是可维护的业务配置，本地授权、任务、称重、证据及设备记录不以当前编码判定归属；已产生的编号和身份快照保留原值。这样可以纠正安装时填写的编码，同时避免改写历史或遗漏旧记录。此决定取代 [ADR 0033](0033-code-identity-and-ticket-number.md) 中“编码确定后不可修改”和“以编码作为本地业务关联键”的部分，其编号格式及防重复目标继续有效。

单据号使用出单时的厂区编码、北京时间日期和流水号；编码改回后沿用该编码已有水位。修改编码时保留操作授权及成功冻结的采样，等待在途设备采集结束并让 Agent 正常重连；未决打印保持原状态，不阻止修改编码，也不自动重放。Agent 使用数据库安装实例标识隔离打印账本，这个标识只服务于本地打印去重，不作为厂区、地磅或业务数据的归属键。本次从空库部署，不导入旧账本，也不删除已有文件；上线后的账本须持久保留，未知打印先核实，不能自动重放。新协议拒绝旧版 Agent，避免绕过实例级去重。

本地无法验证跨厂编码唯一性。厂云目标改为按厂区编码归属，不使用凭据或云端地磅身份；编码修改及历史单据规则见 [厂云同步契约](../requirements/cloud-sync-contract.md)。此为目标，现有厂端成功同步后仍禁止改码，新协议尚未实现。

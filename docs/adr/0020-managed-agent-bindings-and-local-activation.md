# 后台管理 Agent 绑定，现场明确应用启动配置

2026-10-21，用户在厂区配置需求讨论 Q1～Q8 中确认：后台支持厂区新增、编辑、停用，本期每厂一磅；后台保存的 Agent 与地磅绑定对新连接即时生效，避免增加厂区时修改 Server 文件和重启 API。该决定将此类现场身份映射从固定启动配置转为后台持久管理，既有 YAML 中的其他运行参数继续沿用原职责；旧身份、密钥及打印账本必须保留。

用户随后明确简化 Q9、Q10：本轮目标为厂区内部部署下的现场归属配置。启动配置允许重复下载和使用，沿用现有 Agent 连接机制，不增加一次性签发或凭据轮换流程，也不以离线或无未决打印作为普通配置下载的条件。

后台按厂区和地磅生成连接配置，真实打印 Agent 在现有本地维护台预览、明确应用并启动，mock 读取对应文件启动；不引入后台远程启动进程。相比远程控制，现场继续负责本机队列、打印校准及未结束作业处置，后台不覆盖这些参数或账本。该边界延续 [ADR 0016](0016-agent-local-maintenance.md) 和 [ADR 0017](0017-agent-maintenance-config-and-lan.md) 的现场维护职责，同时补充由后台生成连接配置的流程。

地磅及 Agent 身份不跨厂区改绑，硬件迁移使用目标厂区的新身份，避免历史业务和现场设备归属混淆。厂区停用须无未完成任务、未决打印及在线 Agent；停用阻止新业务和设备接入，但保留历史查询、导出及重新启用能力。用户随后已授权实施并部署至 `fcc-com-01`，代码、受控软件验证及该主机升级已完成，准确结果见[交付记录](../requirements/site-agent-configuration-delivery.md)；完整范围见[需求讨论](../requirements/site-agent-configuration-discovery.md)。

2026-10-22 目标调整见 [ADR 0021](0021-local-weighing-authority-and-central-sync.md)：中心统一管理现场归属与连接身份，各厂 Agent 连接本厂本地 Server，中心管理入口与各厂现场连接地址分别表达。现场仍需明确应用配置，本机设备参数和账本保留；中心提出厂区停用申请，现场满足既有条件并应用后才算停用。新目标尚未实现，本文此前单个 Server 地址的部署背景不能直接沿用到中心与多厂独立实例。

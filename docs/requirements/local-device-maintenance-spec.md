# 单厂设备职责、配置与维护简化规格

2026-10-26 修订：成功采集后冻结依据。本文为[总规格](standalone-site-spec.md)的设备细则，决策理由见 [ADR 0030](../adr/0030-local-device-responsibilities-and-configuration.md)。已确认目标与交付分开：实现、软件／部署验证及现场结果以[当前状态](../next.md)为准，原改造依赖见[工作包档案](../history/requirements/local-device-maintenance-plan.md)。

## 1. 目标与范围

每厂仍为本地 Server（内嵌 Web）、独立 Agent 与 PostgreSQL。默认同机，同时支持同厂局域网分机；安装选择部署哪些进程，不引入新的节点运行角色。当前每厂一台地磅，同磅仅一个真实 Agent 或 mock 在线。

目标是减少维护人员要理解和手工填写的内容：Agent 只填 Server 地址，日常通过网页配置串口与打印；网络摄像头独立由 Server 管理；正常安装、升级不手写配置文件。安装、串口权限、CUPS 队列等首次准备由实施人员完成，后续管理员使用现有账号权限维护。

本期不新增中心、多厂管理、通用设备注册审批、远程启动离线主机、识别引擎或新部署框架；不升级现有技术栈。完整 Server 电脑灾难恢复及单盘保护方案仍属原暂缓议题，不能把 Agent 参数备份当作整套业务系统备份。

## 2. 职责与配置清单

| 内容 | 权威位置 | 配置入口／执行方 |
| --- | --- | --- |
| 本厂及地磅身份 | 受保护的系统配置项 | 本厂身份页面维护编码和名称；历史业务快照及操作授权保留 |
| 单据标题、强制抓拍 | `sys_config` | 同一配置管理入口；标题可自定义，强制抓拍默认开启 |
| 摄像头列表、源地址及凭据、抓拍用途、超时、识别设置 | Server PostgreSQL 的摄像头模块 | 独立摄像头管理页；Server 直接取帧、保存图片及组织测试 |
| MediaMTX 管理地址、凭据、公开 WHEP 入口与本系统流映射 | Server PostgreSQL 的摄像头模块 | 摄像头管理 → 视频预览服务，Server 同步视频源 |
| Agent 连接的 Server 地址 | Agent 本地配置文件 | 安装／本机配置工具生成，从 Agent 主机视角解释 |
| 串口、波特率、打印队列与校准参数 | Agent 本地 `agent.env` 及内部恢复数据 | 仪表与打印维护页，经 Server 通道由 Agent 保存并应用 |
| Agent 生效状态与手动参数备份 | Server 保存最近状态及独立恢复副本 | 设备维护 → 配置备份，手动创建、查看、恢复和删除；日常参数仍在仪表／打印机页编辑 |
| 打印账本、物理执行状态 | Agent 本地持久目录；Server 保留业务尝试及核实记录 | 保留原去重和人工核实机制 |
| 数据库连接、Server 监听、JWT、图片／上传目录、日志等启动参数 | Server 本地配置文件 | 安装工具填写必要项，其余生成；服务无法启动时从主机恢复 |

不得把同一项做成多处可编辑来源。新增结构和配置种子使用新增 Goose migration，保留历史 migration；API 启动不 AutoMigrate。业务数据和历史证据沿用当前数据库，不因这次设备职责调整清空重建。

## 3. Agent 接入与维护

### 3.1 只填连接地址

- Agent 不再要求连接密钥、配对文件、人工 Agent 编号或本地地磅编号；Server 根据本厂唯一地磅建立运行关联。内部厂区、地磅及连接标识由程序管理，不要求人员复制。
- 本厂初始化不再要求生成用于 Agent 鉴权的绑定密钥，设备维护不依赖旧绑定密钥才能定位在线连接；厂区与地磅本身的业务归属继续保留。旧绑定数据的退役／历史关联按新增迁移处理，不能先删除被历史记录引用的身份。
- Server 不再自动建立本厂身份：未配置时 Agent 以 `site_not_initialized` 提示并按正常连接策略重试，不自行创建厂区或地磅。管理员在本厂身份页面填写预分配厂区编码后接入恢复；身份异常时人员检查 Server 日志与数据库。
- 同磅先连接者保持，后连接者收到明确冲突，不自动踢走原连接。真实 Agent 和 mock 使用同一互斥规则；正常断连可重连，用户主动踢出遵循下述独立权限、退出及核实规则。
- 主机名、连接 IP、版本和当前连接状态用于排障，不成为新的配对身份、人工编号或业务确认凭据。
- 设备通道按单厂局域网互信执行，不保留旧 Agent key 校验作为隐含接入门槛。用户登录、JWT、RBAC、操作会话及厂区操作范围不改变；设备通道不能代替用户正式确认。
- 地址变更由本机配置工具明确写入并重连，保留串口、打印与账本。Server URL 只是连接地址，修改地址不能重置同一本厂的打印去重依据；连接不同业务实例时由系统内部识别并隔离，不能误用另一实例的账本。

踢出使用独立动作权限及本厂操作授权，普通操作员默认无权；审计记录人员、目标连接及时间，连接变化不得误踢后来者。收到 kick 后真实 Agent／mock 结束整个进程（含 mock 控制页）、停止本轮重连，守护服务不立即拉起；允许人工启动或主机重启后接入，不永久封禁。正常网络断开仍可重连。未确认客户端退出时只报告断连／退出未确认。踢出使在途采集失败，已成功保存的采集结果仍可按原操作会话核对确认，已提交业务保留；无最终打印回执保持未知，已交 CUPS 的作业可能继续出纸。

### 3.2 进程与配置应用

- Agent 主进程及维护通信常驻，网页控制设备执行的启动、停止、重载。整个进程离线时通过其主机 systemd／日志恢复，网页明确说明无法远程启动离线进程。
- 初装仅有 Server 地址、串口／队列尚未配置或设备不可用时，也须能建立维护连接；显示设备未配置或故障，允许网页完成首次参数配置，不因设备参数校验在通信建立前退出。
- 只开放一次“保存并应用”。对设备参数的校验、称重及打印维护检查、持久化、设备重载、结果核实与必要回退在内部处理；不再要求用户理解草稿、已保存和待应用三套状态。
- 维护条件不满足或校验失败时不改变有效配置，表单保留并说明原因；执行中打印及未决作业沿用原核实保护。应用结果未知时先读取实际状态，不自动重试写操作。
- 应用失败尝试恢复上一成功配置；恢复失败明确显示设备不可用，保留维护连接以便修复，不把保存成功当作设备正常。上一份成功配置可供明确恢复。
- 删除相机、识别、密钥、人工身份及已固定的仪表字段在示例、生成器、读取、校验、摘要、页面及安装工具中的运行依赖。升级清理本工具拥有的废弃行，保留无关现场配置和账本，避免旧字段仍然暗中生效。

## 4. 地磅仪表

| 项目 | 确认行为 |
| --- | --- |
| 串口路径 | 网页填写 Agent 主机实际路径，由 Agent 本地保存；不把默认路径当作所有主机都已配置成功 |
| 波特率 | 网页下拉选择当前驱动支持值，默认 9600，与仪表本体设置一致 |
| 仪表启用开关 | 删除；设备运行且已配置时自动采集。尚未配置时保持维护通信，显示未配置 |
| 协议与串口方式 | 固定已核验 D12 `tF=05`、8N1、无流控；仪表本体由实施人员设置，不在网页假称可改硬件参数 |
| 单位 | 固定按吨解析，取消 kg↔t 选择及对应换算路径；保留报文小数位、原始帧和精确 `0.001 t` 表达，不把整数内部单位误当作吨 |
| 数据超时 | 内部固定 1 秒无新有效帧即故障；新有效帧恢复当前状态，旧采样不会复活 |

仪表故障不导致维护主进程退出。串口打开失败区分权限不足、路径不存在、设备占用及其他原始错误。权限提示使用 Agent 实际运行账号／UID及端口，不使用浏览器账号；提示管理员授予该账号串口读写权限，涉及组变更时说明可能需要恢复服务会话才能生效。常规方案不要求整个 Agent 以 root 运行。

1 秒限制设备数据的新鲜度，不限制操作员点击确认的时间。当前帧约 200 ms 连续上报是已有抓包事实，不能替代现场长期验证；验收观察是否频繁误报。仪表原始单位标志与现场吨制不一致的说明继续保留，固定吨制只适用本次核验设备。

## 5. 打印与现场校准

| 参数 | 入口与含义 |
| --- | --- |
| 打印机／队列 | 下拉选 Agent 主机实际 CUPS 队列，由 Agent 枚举；不是 Server 主机的队列 |
| 单据节长（mm） | 原连续纸表长，支持小数，表示相邻横向撕纸线节距；用于逐单走纸校准 |
| 内容缩放 | 保持比例调整文字与表格大小 |
| 水平／垂直偏移（mm） | 调整单张内的位置，不作为累计走纸误差的替代修正 |
| 基准打印宽度 | 暂保留高级校准，维持现有值；不因本次简化改动已经满意的版面 |

页面按“先节长 → 再位置 → 必要时缩放”说明校准流程。保留打印校准样张、当前生效参数及上一成功配置恢复；样张不是业务单据，不增加业务打印或补打次数。五联是复写层数，一次提交一份任务；三等分每小段容纳一张单据。

偏移沿用当前支持的方向及范围，页面明确正方向；通过增减已有偏移校准位置，不在本轮额外承诺尚未验证的负向打印指令。当前 241×279 mm 三等分穿孔纸的默认基准宽为 175 mm、节长为 93 mm；旧配置的 99 mm 等实际生效值保留，不因升级自动改写。默认不代表现场已校准，升级保留已有实际生效值。

现场反馈为连续打印越来越靠下，尚未测量实际节长、实际生效参数及打印机行为。本规格确认校准能力，不认定故障已定位或已修复。若改变程序节长不影响实际走纸，检查设备表长指令、装纸与撕纸设置；不能承诺靠缩放和偏移解决一切走纸问题。真实连续纸首张定位、累计偏移、撕纸停靠及第五联清晰度仍须实物验收。

## 6. 独立摄像头模块

### 6.1 数据与页面

- 摄像头为可增删列表，数量允许 0..N，不固定两路，不以 `front/rear` 决定含义。每台有系统生成稳定 ID、可编辑名称、完整源 RTSP 地址、独立用户名／密码，以及“用于称重抓拍”选择；其余用于预览。
- 源地址包含主机、端口、流路径，凭据分开填写。秘密不回显到普通响应、图片元数据、日志或预览地址；编辑密码留空保持原值，需要清除时使用明确操作。
- 摄像头配置保存在 Server 数据库；保存后用于后续采集，无用户草稿及 Agent 重载步骤。影响采集内容的修改使受影响的进行中采集失败，已成功样本保留当时配置；并发保存不能混用新旧配置。
- 历史图片保存摄像头 ID、当时名称、来源、时间、内容摘要及实际取得状态。改名、删除、调整用途不改写历史证据；证据中的重量来源与图片来源分别表达，不继续把 Server 图片标为 Agent 上传。
- 复用现有页面 Pattern、登录、适用的管理／查询权限和审计；旧 Agent 维护页移除摄像头、识别及 MediaMTX 配置与执行入口。工作台、核对、历史与维护测试使用列表及真实名称。

### 6.2 抓拍及业务规则

- Server 直接连接摄像头 RTSP，通过当前可复用取帧能力取得新图片；不依赖浏览器正在播放的帧、定时生成的静态旧图或 MediaMTX 的 RTSP 转出。
- 抓拍超时为整次并行取图的统一截止时间，默认 6 秒，在摄像头高级设置中统一维护，不逐台增加超时项；多台不能按数量串行累加等待。资源上限采用适配当前设备的简单有界方式，不引入新调度平台。
- 每次采集冻结摄像头集合及配置版本。强制抓拍开启时，所有指定摄像头均需取得、验证并保存有效新图；任一失败拒绝本次有效采集。指定集合为空时明确阻止，不能以空集合“全部成功”绕过。
- 关闭强制抓拍时仍按已选择摄像头尝试，保存成功图片、逐台失败及无图事实；无抓拍摄像头时可直接采重。该策略仍由 Server 决定，保留当时版本快照。
- 不因放宽图片策略而放宽设备重量、稳定、新鲜、人工确认及本地业务校验；网络或参数恢复不自动重称、确认、出单、补图或重打。

### 6.3 抓拍期间的重量依据

Server 编排一次采集，Agent 负责仪表依据。最小闭环为“开始并确认测量检查 → Server 取得并保存当次图片 → Agent 结束并核实 → Server 保存样本”；所有消息关联本次请求和当前连接。无图策略也必须取得本次有效仪表依据。

必须识别采集期间的重量变化、失稳、串口错误／过期、设备重载、断连或进程重启。即使读数恢复原值，本次已失效依据仍须拒绝。现有 500 ms 上报及 20 ms 快照轮询不能严格覆盖同一读取批次的中间变化；实现须在 Agent 每个已解析帧及故障变化处锁存本次失效，或使用等效的不可回退测量代次，并原子建立起始基线与核实结束结果。

采集成功即冻结本次重量、时间、图片、测量代次与配置依据。Agent 的逐帧失效检查用于采集窗口；成功保存后，后续变重、车辆下磅、失稳、故障、过期、断连、重载或重启不撤销该样本。正式确认不再发起 `measurement.verify.request`，不依赖当前设备在线或读数相等；核对窗口始终使用已采集重量。相同有效稳定帧重复到达不增加失效代次，不引入“必须再稳定若干秒”的门槛。

Server 在采集期间核对连接、新鲜度和维护互斥，不能长时间持有阻止设备状态更新的锁跨越网络取图。采集超时、断连、迟到／重复回复不得形成有效样本。操作员确认不设固定时限，仍校验业务权限、操作会话、车牌与任务绑定、任务版本和重复使用；主动重新采集替换旧样本，主动废弃的样本不可提交。

### 6.4 测试、预览与识别

- 每台显示最近抓拍结果及时间，支持测试抓拍、查看实时画面。未测试不标在线，历史测试成功不等于始终在线。
- 摄像头管理、独立测试和预览不以 Agent 在线或旧 Agent 维护总开关为前提；Agent 离线只阻止依赖仪表的正式采集，不阻止维护网络摄像头。
- 测试取得新图片和具体错误，不创建 sample 或正式称重记录，不进入正式业务证据；抓拍与预览结果分别反馈。
- 保留可选外部车牌识别接口，由 Server 调用；地址允许留空，从指定的一台抓拍摄像头复用本次图片，不额外抓拍。识别失败不阻断其他条件满足的业务，候选仍需人工核对；不新增内置引擎／厂商接入。
- 删除识别源或取消其抓拍用途时，同时清除识别源选择并提示识别已停用；不静默改选其他摄像头，不为保持识别而额外抓图。

## 7. MediaMTX 自由部署与自动同步

MediaMTX 可在任意合适的本厂可达主机部署，不强制与 Agent 或 Server 同机。系统不负责远端进程安装、启动和系统级恢复。Server 必须能访问摄像头和管理接口，浏览器必须能访问 WHEP 及相应媒体网络；互联网断开不影响可达的本厂链路。

在摄像头模块统一配置：公开 WebRTC/WHEP 入口、Server 可达的管理接口地址及凭据。每台流名和播放地址由程序生成，不手填前后流名；不再提供给 Agent 的 MediaMTX RTSP 抓拍入口。

Server 调用管理接口同步本系统视频源；只操作系统持久标识及摄像头 ID 对应的托管路径，不覆盖共享 MediaMTX 中其他流或修改其全局网络设置。源码／部署版本仍采用当前基线，不因接入 API 升级。管理凭据不下发浏览器，不额外建设播放鉴权层。

同步成功、失败或待恢复独立呈现；相机配置保存成功不因远端离线而回滚，直连抓拍仍可使用。预览映射未同步时明确显示不可用／待同步，不能用旧画面冒充新的摄像头配置。

同步操作和结果绑定相机配置版本。连续保存或旧请求迟到时，仅当前版本可标记已同步；按当前期望核对、纠正旧请求留下的漂移，不以路径存在就判成功。使用简单的每路径串行化／版本核实，避免引入通用任务平台。

实现需处理运行配置重建：当前 MediaMTX Control API 变更不自动写入其部署 YAML，重启或文件重载后不能假定路径仍存在。Server 以数据库为本系统路径来源，在保存、启动及轻量检查发现丢失时恢复同步；失败可明确重试，不重放物理业务。删除／改地址时保留必要的旧托管路径清理信息直到远端处理完成，避免离线删除后遗留流；不扫描删除非本系统路径。

事实依据：[官方 Control API](https://mediamtx.org/docs/features/control-api)、[v1.21.2 接口定义](https://github.com/bluenviron/mediamtx/blob/v1.21.2/api/openapi.yaml)、[v1.21.2 配置更新实现](https://github.com/bluenviron/mediamtx/blob/v1.21.2/internal/core/core.go)。同源可以多协议读取，但本次已选择直连抓拍，不增加 Server 的 WebRTC 取帧实现。

## 8. 本厂配置与单据标题

- 本厂及唯一地磅身份由管理员在“系统管理 → 本厂身份”首次填写总部预分配的厂区编码建立；编码与名称可维护，身份变更和审计同事务保存，历史业务快照、授权和启停状态保留。异常库不自动清理或重建。
- 单据标题由可编辑的 `sys_config` 配置维护，新库缺省“酒厂过磅单”，无需在 Server YAML 配置；历史单据／图片等业务快照不因配置变更重写。
- 新单据自本改造启用起保存实际标题快照，后续修改标题不改变其查看和补打。无标题快照的既有单据在升级时使用当前数据库标题固化显示基准；之后也不随新标题变化。
- 强制抓拍开关仍使用原业务策略键、默认开启及非法值按开启规则，集中在同一配置管理入口，不复制到摄像头列表作为另一套总开关。
- “系统管理 → 过磅单标题”提供标题编辑及样张预览；预览使用当前输入，不保存、不出单、不打印。原“本厂称重”页退役，设备执行与断开操作统一在设备维护，旧名称配置链接转到本厂身份页面。
- 标题与通用系统配置继续要求 `system:config`；旧本厂资料权限不自动转为标题修改权限，旧本厂 API 保持原权限与身份保护。

## 9. 备份、安装与恢复

- 安装工具支持默认同机及按需只安装 Server 或 Agent；Agent-only 只要求 Server 地址，不读取、拷贝或要求数据库凭据。Server 端初始化本机运行文件，生成必要秘密并配置目录；Web 随 Server 发布，生产不要求 Vite／Node 常驻。
- Agent 侧安装准备 CUPS、打印队列、串口权限及当前打印依赖；取帧所需 FFmpeg 移到 Server 侧。自由部署的 MediaMTX 由实施人员准备网络与管理接口，不随 Agent 安装强制启动。
- 配置文件生成、更新和升级保留用户有效值，受限权限及原子写入沿用既有做法。旧配置废弃字段不能再成为启动门槛；卸除 Agent 相机运行依赖时先保留、迁出已有有效配置，不能静默丢失源地址及凭据。原 MediaMTX 私有源由其拥有者明确导入／网页维护，不假称可从旧 Agent 的转流地址逆推出相机凭据。
- 升级核对实际 systemd unit、drop-in、环境文件和启动参数；不能只更新新模板，却让旧 unit 继续注入身份或相机参数。保留自定义部署值，通过受控迁移及核实完成启动源更新。
- 设备维护分为运行总览、打印机管理、仪表管理、配置备份及维护记录。打印诊断与未结束打印作业放在“打印机管理”，与队列维护和校准样张相邻；无错误提示不显示警告，维护连接离线或状态未确认不表示检查成功。生效摘要与备份管理集中在“配置备份”，不在两类参数页重复展示恢复入口。
- Server 自动更新最近生效状态用于诊断，但只在管理员明确点击“创建备份”时创建恢复副本。保存应用、重连和恢复都不自动新增备份；Agent 内部应用失败回退不受影响。
- 创建备份须 Agent 在线并已有成功生效参数，核对当前版本、摘要与实际上报快照；仅接受备份名称（必填、不超过 100 字）、备注（不超过 500 字）和核对版本，不接收浏览器表单参数作为备份内容。记录创建人、时间和来源生效版本。
- 生效版本保留原并发控制规则，与手动备份记录分别管理。列表分页展示历史及手动备份；历史自动备份／恢复记录原样保留并标注来源。备份不可编辑，删除后退出可恢复列表，保留底层历史关联及审计。
- 恢复前显示完整仪表与打印参数对比，明确同时覆盖两类参数；执行后形成新的生效版本，原备份不改写。只读维护账号可查看列表与详情，创建／删除／恢复沿用维护管理权限。Agent 离线时可查看既有备份及最近生效状态，不能创建或恢复，不以缓存状态冒充在线。
- 可恢复字段仅串口、波特率、打印队列和校准参数等设备设置；不恢复旧 Server URL、主机排障信息、连接／暂停状态、测量窗口或执行请求。连接信息由新机安装配置，账本独立迁移，不整份复制包含运行状态的旧配置对象。
- 换机无需换编号、换密钥或重绑；旧机运行时先停止，单磅互斥防止双接入。新机可选择恢复上次备份，核对实际端口、CUPS 队列与校准后明确应用；不因连接就自动套用旧主机参数。
- 升级保留本地打印账本；换机可恢复账本，但账本不可读不阻止换机。Server 未确定的打印保持待核实，人员检查纸面后确认结果或明确发起新打印；没有账本不能推断未出纸。
- 任何部署、地址改变、Server／Agent 重启、重连、恢复或配置应用不自动补称、确认、出单或重发旧打印。不得把恢复设备参数等同于恢复执行请求。

本次本厂身份改造按空数据库部署，不要求迁移原有业务、授权、设备配置或旧打印账本，也不自动删除已有数据。上线后的配置、业务证据及打印账本仍须持久保存；以下旧版升级相关描述保留为历史背景，不构成本次验收要求。

## 10. 兼容、验证与完成判定

实施需协同更新 Server、真实 Agent、mock、安装工具、协议和页面。旧版相机归 Agent、前后两图、key／provision 的实现不能继续充当新方案验收依据；正式采集必须识别客户端是否支持所需测量检查，不允许不支持时静默回退到弱校验。协议修订明确不兼容变化和升级顺序，不重写 v1 的历史实现事实。

历史业务数据、图片读取和打印账本必须保留。新图片不能受 `front/rear` 文件名和恰好两图校验限制，旧图片地址、视角与摘要仍能读取；历史快照保留其原来源，不批量改造成新数据。

| 验收组 | 必须可观察的结果 |
| --- | --- |
| AC-01 接入 | 仅填 Server 地址即可接入；未配置时明确返回 `site_not_initialized`，管理员在本厂身份页面填写预分配厂区编码后接入；身份异常明确提示；第二个真实／mock 连接冲突且首连接不受影响；无 key／配对门槛 |
| AC-02 仪表 | 页面仅端口与波特率；固定协议、吨制、1 秒；无配置／打开失败仍可维护，错误原因和实际账号明确 |
| AC-03 应用与打印 | 单次提交区分拒绝／成功／未知／恢复失败；队列来自 Agent；节长小数及校准参数真实传递，原打印去重和未知核实不退化 |
| AC-04 可变相机 | 0、1、3 台以及任意名称可维护、预览、测试、抓拍、核对和查看历史；无前后两图隐性限制 |
| AC-05 策略 | 强制开时指定全部成功且非空；部分失败拒绝；强制关时允许缺图并保留逐台状态；单次并发截止默认 6 秒 |
| AC-06 设备依据 | 采集期间变重再恢复同值、失稳、故障、过期、断连、重载及迟到回复均拒绝，同一批串口帧内变化也被识别；采集成功后变重／下磅／失稳／断连仍按冻结快照确认，不设确认倒计时 |
| AC-07 视频与识别 | MediaMTX 异机、离线、重启、同步失败、删除后恢复、源配置漂移及旧同步迟到正确表达；其他流不受影响；Agent 离线仍可维护／测试／预览；直接抓拍不依赖预览；识别复用图且失败不阻断，删除识别源明确停用 |
| AC-08 权限与入口 | 首次在本厂身份页面填写预分配厂区编码建立身份且已有身份保留，标题从独立页面编辑预览并按原权限生效；Agent 页不再显示相机／身份秘密／草稿 |
| AC-09 安装恢复 | 同机及 Server-only／Agent-only 安装、旧配置升级、手动备份创建／查看／删除、离线只读和换机恢复可核实；仅设备参数恢复，不覆盖新机连接与运行状态；地址变化和缺失账本不触发历史执行 |
| AC-10 历史 | 旧图片、单据及打印尝试可查询；新图片保存实际相机名与来源；新标题快照及旧单基准保留，修改配置不改历史票面 |

代码阶段按改动运行 `task backend:check`、`task frontend:lint`、`task frontend:build`；数据库改动加 `task db:check`（隔离临时 PostgreSQL），工程／安装迁移执行 `task check`、`task build:check` 及受影响的安装发布检查。按行为选择必要单元、集成和浏览器测试，不重复跑等价检查；测试服务超时并清理。

软件回归、隔离模拟、分机部署演练、真实仪表及摄像头、连续纸实物结果分别记录。全部代码／测试通过也不能宣称真实非零称重、相机对应证据和连续纸校准已现场验收。纯文档整理仅检查内容、链接和差异，不产生新的软件或现场验证结论。

# 本厂称重业务规则

2026-10-26 修订：成功采集后冻结依据。本文汇总仍有效的业务与验收要求；术语见[CONTEXT](../../CONTEXT.md)，产品范围见[总规格](standalone-site-spec.md)。旧访谈及阶段规格已归档，条款来源见[收敛记录](../history/document-consolidation.md)。本文表达当前已确认规则，不表示全部现场验收完成。

## 1. 资料、任务与授权

- 当前单机部署阶段，由有权限的本厂人员维护物料分类、物料、往来主体及联系人；操作员办理称重、调整、纠错、重称、终止、作废重开、重新打印及导出，仍须逐项满足真实权限与本厂操作范围。无需主管专办或额外审批；隐藏按钮不能替代 API 校验。
- 单机阶段内置地磅操作员角色默认拥有资料维护权限，可新增、修改及按既有规则维护物料、分类、往来主体和联系人。本厂授权仍控制本厂称重业务范围，不因资料维护权限改变；实际操作仍受账号及角色权限控制。
- 未来接入云端后，物料分类、物料、往来主体及联系人由总部在云端统一维护，下发所有厂；本地资料只通过云端同步更新，取消操作员本地资料维护菜单。本厂发现云端资料有误，通过电话、微信等现有渠道向总部反馈，不新增反馈功能。资料列表不要求展示同步状态。
- 单机阶段已有资料在接入云端时由人工分析和合并，不开发自动分析、匹配或合并功能；具体人工切换操作待接入时确定，历史业务依据保持可追溯。接入云端后，本厂每小时自动同步一次总部资料，并提供主动同步按钮；本厂离线或同步失败时继续使用已同步的本地资料，不因互联网中断阻塞称重。同步更新本地资料不改写已办理业务快照。缺少资料且无法同步时的临时录入场景暂不纳入范围。
- 基础资料页面提供操作员可用的主动同步按钮，一次同步物料、物料分类、往来主体及联系人，并提示本次同步完成或失败；按钮不触发过磅单上传，资料列表不显示逐条同步状态。自动及主动同步均由本地 Server 拉取全量资料，全部下载和校验成功后整体生效；失败保留上次成功资料，不产生部分更新。
- 资料编码按创建位置区分：总部物料 `C-M-0001`、总部主体 `C-P-0001`、总部物料分类 `C-C-0001`；单机阶段本厂分别为 `厂区编码-M-0001`、`厂区编码-P-0001`、`厂区编码-C-0001`。流水号按创建位置及资料类型分别持续递增，不按日期重置，至少四位，超过 `9999` 后自动扩展。联系人随主体同步，联系人稳定标识的具体方式待确定。恢复后流水号倒退的处理暂缓决策，待实际使用后确定。
- 云端接入后，总部分类停用时新物料不能选择该分类，已有物料和历史单据保留原关联；本厂收到总部往来主体或物料的停用状态后，新任务不得选择该资料。已首磅任务按原快照完成回磅；本厂离线时使用最后一次同步的状态。总部可重新启用资料，沿用原编码，各厂收到后可按业务规则再次使用。
- 物料编码自动生成且唯一，名称必填；维护分类、规格／等级、状态、备注。同名不同规格独立建档，选择时显示名称、规格、编码；分类采用简单列表。
- 往来主体为企业或个人，名称必填且允许同名，自动唯一编码只读，业务身份至少一项且可兼具供货商、客户、承运商。简称、联系电话、业务地址、备注及企业信用代码选填；支持多个联系人及一个默认联系人（有联系人时），保存姓名、电话、用途／职务、备注。
- 每趟只对应一种物料、一个必填供收方：入厂卸货选供货方，出厂装货选收货方。承运方选填，可与供收方相同；司机姓名、电话及备注选填，司机与主体联系人分别保存，不自动创建主体。
- 新任务选择有效资料和所需业务身份。已首磅任务按办理时资料快照正常回磅，后续改名、规格／身份调整或停用不改写旧依据；主动纠错按下述流程留痕。已引用资料不可删除，可停用；历史缺失字段如实留空，不从当前资料反填。
- 同厂同车最多一笔未结束任务，两次称重在同厂完成；不同趟次不拼接重量。首磅确认前只存在草稿；首磅确认原子建立任务与称重，二磅确认原子完成任务并出单，失败不显示完成。编号由 Server 生成、唯一且允许不连续，作废不回收，重开使用新号。
- 新过磅单号采用“厂区编码-出单日期-当日流水号”，例如 `F001-20261027-0001`；日期按北京时间，流水号按厂区和出单日期分配，每日从 `0001` 开始，至少四位，超过 `9999` 后自动扩展，不截断、不重号。并发出单不得重复，断互联网不影响本地出单；补打沿用原单号，作废后重开使用新单号，历史单号不改写。恢复备份可能导致流水号倒退及重复，正式处理流程暂缓决策，待实际使用后确定；当前实现以库内当日最大单号和数据目录高水位兜底，并允许管理员在流水号水位页面上调流水号水位（只升不降、留审计）。
- 同磅同一时刻只有持有效操作会话者可采集确认；其他终端可查询，授权接管留痕且旧会话失效。车辆等待装卸／回磅期间不持续占据地磅操作位。
- 厂区停用保留历史和查询／导出，暂停新业务及接入；执行无未完成任务、未决打印、在线 Agent 等既有检查，可重新启用。当前不引入中心停用申请。

### 未来云端过磅单查询与同步（第一版基准）

以下为已确认的第一版业务与操作基准；资料同步规则见本节上方，双方共同边界见[厂云同步契约](cloud-sync-contract.md)。本次各厂正式投入使用时即接入云端，使用前由本厂管理员完成厂区绑定及首次完整资料同步；目前各厂尚未使用，无需历史导入。首次同步成功后断互联网仍可正常办理本厂业务。新版接口按厂区编码归属，不使用厂端凭据；具体字段、重试及编码更正实施细节见契约；恢复旧备份后的倒退处理继续暂缓。本节不表示云端同步已经实现。

- 云端仅接收已出单数据供总部查询和统计，待回磅任务留在本厂。厂区人员在本地查询；云端不得修改、作废或重开本厂单据。
- 云端单据包含纸单信息、原始及最终重量、人工调整前后值及差额、来源、备注、调整人和时间，司机姓名及电话、联系人及联系电话，以及业务发生时的物料和供收方编码与名称快照；缺失值按本地事实保留。统计按原始资料编码分别进行，不自动合并不同编码。
- 称重照片不上传；单据不上传承运方编码及名称、重称和资料纠错过程或被替代称重记录。打印状态、打印尝试、补打次数及原因只保留本厂；承运方基础资料仍由云端统一维护并下发。
- 出单后云端新增对应单据；作废时更新原单状态、原因、操作人和时间，不新增单据或覆盖原单业务和重量快照。重开以新单号新增单据并关联原单；重复同步不得产生重复单据。联网恢复后自动补传断网期间的出单、作废和重开变化，保留各版状态及关联，具体同步机制待设计。
- 出单、作废或重开与对应待上传变化在本地同一数据库事务中保存；后台尽快上传，失败或断网保留并重试，不阻塞本地业务。云端完成保存并确认后，本地才标记对应变化已同步；请求结果未知时可按稳定变化标识重试，云端识别重复并返回已有结果。同一单据的变化按顺序处理，较早状态不得覆盖较晚状态；重开上传须等待原单创建及作废获得云端确认，再上传关联新单，前序失败时后续等待。过磅单列表显示每张单据的同步状态：待同步表示变化尚未得到云端确认，已同步表示最新变化已获确认，同步失败表示最近一次尝试失败且系统继续自动重试。不能仅因初次出单已上传就将尚未同步的作废显示为已同步。
- 单据上传失败由系统自动重试，单据列表不提供手动重试操作。
- 在日志管理下提供同步日志入口，查看权限限管理员；记录总部基础资料的自动及主动同步，以及过磅单出单、作废和重开后的上传尝试。展示时间、同步类型、结果、关联单号或资料范围、失败原因；支持按时间、类型和结果筛选。日志暂不自动清理，管理员可手动清空全部同步日志；清理不删除待上传变化或改变单据同步状态。
- 总部人员可查询所有厂区，不按厂区限制查询范围；总部资料维护权限现阶段不讨论。总部只统计云端已收到且当前有效的单据，作废单不计入，重开后只计有效新单；按最终净重汇总，可区分入厂卸货与出厂装货。接受断网补传造成的滞后和原单作废到重开上传期间的暂时少计，云端页面提示数据可能尚未同步。

## 2. 工作台与人工确认

工作台独立于后台外壳，复用登录和权限；后台顶栏通知图标右侧提供工作台入口，直接打开本厂唯一启用且已授权地磅并复用已有窗口，支持直接地址、回到后台和用户主动全屏。侧栏移除“称重作业”分组，操作员侧栏保留独立工作台菜单；原本厂称重页退役，旧地址转到后台查询。操作员默认菜单与登录首页见[总规格](standalone-site-spec.md)。后台承担完整查询，单机阶段负责本地资料维护，操作员当前车辆留在工作台。布局细则见[工作台 Pattern](../../web/design-system/pages/weighing.md)。

日常路径为：核对车牌并定位首磅／回磅 → 采集重量及按策略取得图片 → 补齐资料 → 一次集中核对 → 明确确认。采集前须定位车牌，确认前须有方向、物料、供收方；单纯采集不建任务、不出单。

- 识别只是候选，失败可人工录入；确认前修正候选不额外要求原因。车牌控件支持省份选择、连续输入、完整粘贴、大写及普通／新能源号牌，查询框仍可自由搜索。每磅保留原候选、人工确认值和录入来源。
- 开始编辑、定位或采集后，新候选只提示，不覆盖当前车辆。修改已定位车牌须重新查找并使旧采样失效；办理下一辆由操作员明确发起。
- 同车补资料、后台新增资料、切换查看或调整画面尺寸不清除仍有效的采样；资料变更使旧核对内容失效，当前任务变化按其影响重新核对或采集，成功采集后的实时设备变化不撤销已保存依据。跨页面不得以旧状态覆盖已保存数据，浏览器不作为权威业务库。
- 核对窗口同时显示车牌、业务、重量及实际图片状态，操作员核对车辆完全上磅；回磅显示首次依据与最终重量。关闭核对不提交，稳定或识别成功不自动采集确认。
- 实时画面支持调整大小和放大，不裁掉核对所需车辆内容；普通 1366×768 桌面关键画面、重量与主操作可见，窄屏可滚动且控件可用。无图、离线、失败及模拟来源如实显示。

## 3. 重量与称重证据

入厂卸货通常先毛后皮，出厂装货通常先皮后毛；运输方向首磅后锁定。不得自动交换毛皮重、取绝对差或简单选较大值掩盖异常。

| 项目 | 规则 |
| --- | --- |
| 单位及精度 | 全部业务重量用吨、精确至 0.001 吨；展示最多三位小数、省略末尾零；设备原始报文、小数位及原单位独立保留 |
| 原始重量 | 只能来自当次有效设备采集，经操作员确认后留存；重量须正、稳定、新鲜且无超量程／故障，原始毛重大于原始皮重 |
| 最终重量 | 初次出单默认原始值，可分别向上或向下人工调整；须为有限正数、最多三位小数，最终毛重大于最终皮重 |
| 差额及净重 | 差额＝对应原始值−最终值，正数下调、负数上调；原始／最终净重各用相应毛重减皮重，均不独立输入 |
| 人工调整 | 标记人工来源并留前后值；高于原始值提示后可继续，原因选填，空白使用“磅精度调整”；无调整不要求调整原因 |

原始异常不能靠调整最终值出单。人工调整不生成新设备采集，不覆盖原始帧、图片、采集与确认时间、人员；实际重称增加替代记录。示例：原始毛／皮 30／9 吨，最终皮重 10 吨时，最终净重 20 吨、皮重差额 −1 吨，原始值仍为 30／9。

采集时核实设备连接、当前版本、稳定、新鲜、维护互斥及本次测量依据；采集期间变重、失稳、故障、过期、断连、重载或重启导致本次采集失败，即使恢复同值也不能放行。采集成功后冻结重量、时间、图片及当时策略，后续重量变化、车辆下磅、失稳、设备故障、过期、断连或配置变化均不撤销该结果；确认时不再次询问 Agent，不设确认倒计时。确认仍校验权限、操作会话、车牌与任务绑定、必填资料、任务版本及重复使用；主动重新采集替换旧结果，主动废弃的结果不可提交。逐帧测量与 Server 编排的细则见[设备规格第 6.3 节](local-device-maintenance-spec.md#63-抓拍期间的重量依据)。

## 4. 抓拍策略

`weighing.capture-required` 为默认 true 的受保护预置布尔配置，仅有配置修改权限者可改值；固定键、名称、类型和启用状态，不允许删除。保存留审计、即时生效；配置缺失、停用或非法按 true，读取失败拒绝新采集。设备、浏览器不能自行放宽策略。

- 开启：本次指定抓拍摄像头集合非空且全部取得、验证、保存有效新图；图片须能支持车牌和车辆与磅台关系核对，失败拒绝本次采集确认。
- 关闭：仍尝试指定摄像头，保留成功图片、逐台失败和无图事实；无指定相机可直接采重。已经提交的图片引用仍须验证，不能把无效引用当作合法缺图。
- 每次采样冻结策略版本、摄像头集合及配置版本，保存当时策略与图片状态；策略切换用于后续采集，不撤销已成功取得的采样；采集中策略变化仍拒绝混用新旧策略。已提交请求按原幂等结果查询，已确认依据不改变。
- 首磅、回磅、重称各按当次策略办理；无图首磅可按当前策略回磅出单，历史补打不重新取图。历史页面明确展示当时状态，不用当前图片补造证据。
- 预览和维护测试不是正式证据。Server 直连 RTSP 取得新图；具体并发截止、可变相机、识别及视频同步见[设备规格](local-device-maintenance-spec.md)。

## 5. 隔日、纠错与重称

- 隔日／过夜车沿用原任务及首次依据，不自动终止或清零，不加审核、额外必填核实说明或最长间隔阻断。操作员核对仍属同次运输，两次实际时间及隔日事实保留。
- 已确认车牌、物料、供收方等资料只能通过有权限的纠错操作修改，记录原因、前后值、人员和时间；改牌须检查目标车牌占用。方向、原始采集、时间与图片不直接改写。
- 重称须指定目标磅次及毛皮含义、记录原因，核实当前装载状态与被替代时一致，并确认另一磅仍有效。卸货后的空车不能替代原毛重；可重称皮重并沿用有效毛重。
- 未出单在原任务中替换目标称重，保留旧记录及替代链；另一磅不重做。仅采集失败时重采当前磅；提交未知须先查原请求。
- 已出单先作废，再在原任务中更正、人工调整或单磅重称后以新号关联重开，不退回普通首磅；同一任务最多一张有效单。无法重采时可用原证据调整最终值，不伪造设备记录。
- 同车已有新未结束任务时，旧任务仍可用留存依据人工更正重开，但禁止实际重称，不恢复旧任务普通回磅占用。
- 作废后重开失败，旧单仍作废且无有效新单；继续办理须幂等。终止释放车牌占用、保留已有依据，终止任务不可恢复。
- 重称、已确认信息纠错、终止、作废、重开和补打保留各自动作原因。人工调整默认备注与作废／重开原因分别记录；免审批不等于免留痕。

## 6. 单据、查询与打印

正式电子过磅单由本厂 Server 生成，效力不依赖中心。每版保留选定称重记录、业务资料、原始／最终重量、差额、操作与证据快照；作废、更正及重称不回写旧版本或旧打印内容。标题快照及旧单显示基准的升级规则见[设备规格第 8 节](local-device-maintenance-spec.md#8-本厂配置与单据标题)。

- “单据查询”包含待回磅任务、原始称重、最终单据三个入口及独立详情。待回磅任务沿用运输任务列表与详情，默认及清空筛选后显示待二次称重，可切换状态查询已完成／已终止任务。原始列表按每个完成两次称重任务一行展示当前有效两磅，历次组合进详情；最终单据每版本一行，显示有效／作废及关联重开。
- 原始列表按当前有效二磅确认日期筛选；只人工调整或重称首磅不改二磅日期，重称二磅使用新时间。最终列表按各版出单日期。北京时间显示，跨日保留实际日期。
- 支持日期、车牌、任务号／单号、方向、物料、供收方和状态查询。原始／最终净重分别汇总，仅计关联当前有效单的任务，作废排除、重开不重复；人工调整不改变原始汇总。CSV 导出全部筛选结果，保留原始／最终含义。
- 详情可查原始、上版最终、本版最终、差额、来源、人员时间、动作原因、图片及替代链。历史缺失信息如实显示，测试／作废性质不伪造。
- 二磅出单后和详情内可主动直接打印，预览可选。查看、预览、刷新及重连不发起打印，不弹浏览器打印对话框。作废单只供查看，不发起新打印。
- 纸单包含标题、单号、车牌、运输方向、供收方、物料及保存的规格、最终毛皮净重（吨）、两次实际确认时间、出单操作员、司机签字位及补打／测试／作废标记；有表格外框与行列线。照片、原始值、调整过程、联系电话及完整资料留在系统。
- 五联为空白复写纸叠放一次打印，不生成五个任务。`weighing-compact-v2`／`printSheet` 沿用精简快照字段，纸张为 241×279 mm 穿孔连续纸三等分，单节设计尺寸 241×93 mm（含两侧孔边）、`layers=5`；真实驱动宽度、节长及偏移按现场校准，设计尺寸不等于已验证走纸参数。Web、Agent 不重新查询当前资料或计算重量。票面仅显示保存的过磅单标题，不追加内部厂名；完整单号独占一行，其后依次为车牌／业务、供收方／物料、毛皮净重、两次完整时间、操作员／司机签字。重量加大加粗，签字行增高，内容在纸张中居中；旧 `weighing-compact-v1` 打印载荷仍可解析。
- Server 校验权限、有效单和去重，先保存尝试再发 Agent。无回执／断连保持待核实，不自动重发；提交未知先查询原请求。已有打印尝试后，无论结果如何，均由有补打权限的操作员填写原因主动重新打印，不要求登记人工核实结果；结果未知时提示可能重复出纸。
- 补打沿用该版单号并记次数、原因及每次尝试；打印不改变任务完成状态。参数恢复、换机或缺失账本不能推定未出纸。校准样张有明显标识且不计业务打印／补打次数。

## 7. 留存、故障与验收

已确认图片、单据及业务审计不自动清理；保存关联关系并纳入备份，保留期限另行确认。互联网断开不阻止正常本地业务；本地链路故障不得通过缓存或手输原始值伪造新采集；Server 与数据库可用时，可确认故障前已成功保存的采集结果。未知结果先核实，恢复不自动重放。模拟通过独立 mock 或设备输入模拟器提供，Server 统一按设备契约处理，不恢复系统内 testMode、模拟／正式两套流程或测试身份登记。模拟环境及验证记录明确其来源，模拟结果不替代现场验收。

| 编号 | 必须保留的可观察行为 |
| --- | --- |
| B-01 资料及授权 | 本厂隔离、真实权限、资料多身份／联系人／规格、引用保护、历史快照及已首磅任务正常回磅 |
| B-02 主流程 | 两种方向、先采集后补资料、人工核对、首磅建任务／二磅出单、单车任务唯一、会话互斥和接管 |

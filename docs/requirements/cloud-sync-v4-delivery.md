# 厂云摘要同步 v4：厂端实现与软件验证

2026-11-01 更新。本文记录厂端对共享[厂云同步契约](cloud-sync-contract.md)摘要目标及云端 v4 发布包的实现与软件验证结果。协议字段与摘要规范以两仓一致的[厂端对接发布包](weighbridge-sync-v4-factory-release.md)和测试向量为准；本文不改变业务规则。现场验收、真实云端联调和部署状态不因本文推定完成。

## 实现范围

### 摘要与变化标识

- 新增摘要规则版本 2 的厂端实现，按发布包第 2 节生成 `wb-change-digest\n` 规范化字节串：固定字段顺序、`名称:字节长度:值\n` 编码、`null` 与空串区分、重量规范为三位小数千吨、时间 UTC 截断到毫秒。
- 12 组共享测试向量原样纳入 `server/internal/weighing/testdata/digest_v2_vectors.json`，测试逐组比对期望摘要；归一化向量（不同重量写法、时区、毫秒截断）结果相同，空字符串调整人与 `null` 结果不同。
- 摘要同时作为变化标识和对账依据；原载荷与摘要写入 outbox 后不再重建，重试和补传均使用保存值。

### 单据变化上传

- 出单、作废、重开仍在原业务数据库事务中写入各自变化；新单据使用 schemaVersion 4、digestVersion 2；作废也携带完整单据快照，重开单作废保留原厂区和原单号。
- 新增独立 v4 outbox `wb_ticket_sync_change_v4`，与旧 v2/v3 outbox 并行保留。已存在 v2/v3 变化的单据，其作废/重开继续走 v2/v3，避免同一单据混用协议；新单据及其后续变化走 v4。
- 同单据按 outbox 顺序处理；重开要求原单作废变化已确认且原单无未完成变化。冲突或未确认前序只阻塞该单据及依赖重开。
- 云端回执必须核对 `digest`、`ticketNo`、`changeType` 和事务接收时间后才标记完成；`duplicate=true` 视为原确认。网络超时、无效回执或无法分类的响应均按结果未知保留原变化。
- 错误分类按云端 `data.category` 处理：`temporary` 退避重试；`predecessor_pending` 设为等待前序；`config_or_data` 设为需管理员处理并停止自动循环；`conflict` 暂停该变化并生成独立核查记录。
- 自动退避按尝试次数指数增长，上限 15 分钟；管理员可立即重试原变化，但依赖查询保证不跳过前序。冲突变化必须先重新核查，不能直接重试。
- 关闭同步开关时不启动上传和自动对账，队列、原载荷和原摘要保留；重新启用且完成首次资料同步后继续处理。首次资料同步成功前不开始上传或对账。

### 对账与异常处理

- 支持单张核对、按日期范围批量对账（每批 1–200 条，自动分批）、旧编码历史确认只读查询。
- 每天按配置的北京时间自动检查最近 7 天发生过变化的单据、更早未确认变化和未关闭核查记录；启动时若当天尚未成功执行则补做。
- 对账结果分为 `consistent`、`pending`、`needs_review`、`conflict`、`unknown`；查询失败、无效响应或逐项错误存为 `unknown`，不会显示一致。
- 云端缺单、创建变化无云端回执且不存在待处理冲突时，按原变化、原摘要和依赖顺序重置为待上传并补传；云端确认过创建变化却缺单时暂停并提示人工核查；缺少创建变化、云端有单但无变化摘要或厂端未知的云端摘要时进入待核查/冲突。
- 云端历史确认同一摘要时自动确认对应变化；后续变化未确认时单据列表仍显示未同步。
- 摘要规则版本缺失或不等于 2 时显示待核查，不判为内容冲突。
- 冲突保存本地与云端摘要、状态、变化历史、逐字段差异和原因；管理员可记录核查结论，明确发起重新核查后，仅当差异消失（一致或待同步）才解除暂停并恢复待上传变化。不提供覆盖或删除云端单据的操作。
- 未实现“云端有、厂端没有”的完整集合对账；只从厂端现有单据出发。

### 同步模块与页面

- 新增“厂云同步”菜单组：单据同步、基础资料同步、同步日志；仅内置管理员角色默认可见，普通操作员的菜单和接口均不授予同步详情权限。
- 单据同步页展示待同步数、需处理数、最近成功时间、最近对账结果，支持同步状态、对账状态、单号/车牌和日期筛选，单张核对和按日期批量对账。
- 单据详情展示各摘要变化状态、类别/原因、尝试与下次时间、云端确认时间、关联原单/重开单、重试、对账差异、核查结论与重新核查、旧编码历史确认查询。
- 普通过磅单列表保留简要同步状态，并单独展示最近对账结果与时间；管理员可跳转同步详情。
- 基础资料同步页保留主动同步入口；原物料资料页入口继续可用。两处执行同一完整资料同步，不触发单据上传。
- 同步日志页记录资料自动/手动同步、出单/作废/重开上传和对账批次，可按时间、类型、错误类别和结果筛选；清空只删除普通日志，不删除变化、对账结果、冲突或核查记录。
- 本厂身份改码前，若当前账号可读取同步模块，页面检查待同步单据数并明确提示；管理员确认后才继续改码。历史单据、待发载荷和原摘要不改写。

## 数据库与配置

- `server/migrations/schema/00036_cloud_sync_v4.sql`：v4 outbox、每单最新对账结果、冲突/核查记录、自动对账状态；普通日志增加 `category` 和 `digest`。回滚被显式拒绝，需恢复升级前备份。
- `server/migrations/schema/00037_sync_review_history.sql`：保留已关闭核查记录，允许同一差异再次出现时生成新的待核查记录。
- `server/migrations/seed/00025_cloud_sync_v4.sql`：厂云同步菜单组、管理员授权、自动对账时间配置 `weighing.sync-reconcile-time`（默认 `02:30`，北京时间）。
- 未修改旧 v2/v3 接口、旧 outbox 数据或历史单据；未自动清理、迁移或重建任何数据库。

- `go test ./...`（包含摘要向量、状态机/对账决策、退避和 sysconfig 校验）。
- `go vet ./...`。
- `npm run lint`、`npm run build`（等价于 `task frontend:lint`、`task frontend:build`）。
- 隔离 PostgreSQL 集成测试 `go test -tags integration ./integration -run TestPostgresWeighingFoundation -count=1`，使用临时数据库和回环假云端，覆盖：
  - 新单据出单/作废/重开的 v4 outbox、摘要与载荷映射、跨编码重开关联；
  - 云端未知回执、配置/数据错误、离线、重试复用原载荷与原摘要、日志清空不影响队列、重启后继续；
  - 最近变化未确认时列表不显示整单已同步；
  - 单张一致、云端缺单补传、未知云端摘要冲突、核查结论记录与保留、重新核查恢复、查询失败显示未知、批量对账、旧编码摘要确认（命中与未找到）；
  - 旧 v2/v3 单据的作废/重开继续走 v2/v3，未与 v4 混用；
  - 管理员可访问同步列表/概览，内置操作员访问同步接口返回 403。
- 历史 v1 隔离双端联调：以云端 8e1c1ee 的干净工作树启动本地云端 API，使用临时 PostgreSQL 和临时上传目录，厂端同一测试通过环境变量 `WB_SYNC_V4_TEST_URL` 指向该云端并执行真实 HTTP 上传与对账。云端实际保存 3 个变化（SITE01 出单、SITE01 作废、F001 跨编码重开），原单为作废、新单有效并关联原单；重复上传未新增变化；两张单据的单张对账均为一致。

## 2026-11-01 协议与异常处理复核

- 以当前云端工作树启动隔离 API 和 PostgreSQL，与厂端使用真实 HTTP 联调通过：跨编码出单、作废、重开及重开单作废共 4 个变化、2 张单，重复上传不产生新变化，两张单对账一致。未连接正式云端。

- 升级为云端当前摘要规则 v2，12 组共享向量通过；无效响应、错单、缺失或矛盾的最新回执均保持结果未知。
- 增加云端完整快照的逐字段对比，按摘要规则归一化重量与时间；摘要相同但字段不同仍暂停并提示核查，普通同步日志不记录完整快照。
- 未处理冲突不会因自动对账或云端缺单而解除；必须先记录结论并由管理员发起重新核查，同一冲突再次发生时保留历史结论。
- 批量对账按单去重，查询失败显示未知；上传、手工重试和对账避免互相覆盖。可信网络快照接口的访问限制见共享契约。
- 空账本及首次资料同步前的同步概览返回空时间；集成测试和发布包启动冒烟覆盖空值与已有同步时间。

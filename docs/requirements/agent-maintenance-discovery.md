# Agent 维护界面需求讨论

> **2026-10-22 效力：部分被替代，过渡实现继续可用。** 最终维护入口与账号纳入本地业务服务，独立维护服务／密码仅作过渡，替代能力验收后退出；配置来源、明确应用、作业保护、结果核实与审计继续有效。维护 HTTP 取舍不自动扩大到业务服务。当前依据见 [ADR 0023](../adr/0023-standalone-site-baseline.md)及[基线索引](../development-baseline.md)；下文历史正文保留。

日期：2026-10-20。状态：逐项需求已确认并收敛；用户已授权首期实现，代码与现场验证状态见 [首期 Spec](agent-maintenance-spec.md) 和[交付记录](agent-maintenance-delivery.md)。

## 已确认需求

- 维护人员是管理功能的主要使用者；现场操作员通过只读状态和排障摘要查看运行情况。完整日志、配置修改及维护操作需本地维护密码。
- 与 Server 断连时，现场仍需通过浏览器进行维护；维护能力不能依赖云端在线。
- 页面部署方案已确认：Agent 电脑提供本地维护页，现有后台保留状态展示与业务入口；首期不增加云端远程配置、服务控制等维护动作。
- 支持 Agent 本机及同一局域网访问，不开放公网。
- 打印 Agent 停止、崩溃或配置错误导致启动失败时，维护页仍应可用，可用于查看日志、修改配置并启动 Agent；维护入口独立于打印 Agent 进程，维护服务自身故障通过系统工具处理。
- 首期聚焦已落地的打印能力：状态与诊断（云端连接、Agent 服务、打印机、CUPS 队列、最近错误及日志）、连接与身份及打印配置、测试打印、服务恢复和队列／作业管理；仪表及摄像头维护随对应驱动接入再增加。
- 本地维护密码独立于后台账号，断云可用；首期不做多用户管理。首次设置及密码遗失恢复方式在实施设计中明确。
- “复位”拆为独立动作：重启打印 Agent、重启 CUPS、恢复暂停的目标打印队列、取消选中的打印作业。重启 CUPS 时说明对本机使用该服务的打印队列的影响。不提供笼统“一键复位”，首期不纳入恢复出厂配置或打印机硬件复位。
- 取消作业不意味着此前完全未出纸；任何维护动作均不删除打印尝试记录。
- 打印配置支持选择已有打印队列，并校准打印宽度、水平／垂直偏移和连续纸表长，以当前已验证参数为默认值，提供明确标记的校准测试页。业务字段与单据内容由 Server 决定；参数可调不代表五联及连续走纸已验收。
- 恢复队列或重启服务前，先展示受影响的未结束作业，由维护人员选择保留并继续或取消指定作业；不自动清队列、重提任务或确认纸面结果。
- 配置先保存，再由维护人员点击“应用配置”生效；目标队列存在排队／执行中作业时先处理作业，应用期间暂停接收新打印请求。失败后维护页仍可用，能恢复上一份配置；打印尝试记录始终保留。
- 断云可打印每次一份、明显标记“测试／校准”的固定样张；不得从本地历史任务重打正式单据，不改变正式单据打印次数，正式补打仍在后台办理。
- 本地记录配置变更、服务恢复、作业取消和测试打印的时间、来源及结果，通过页面查询；使用共用维护密码不推断具体人员身份。用户明确修订 Q13：能查询即可，首期不做诊断包或记录导出。

## 已核实的现状

- 真实打印 Agent 没有本地管理页面，配置来自启动参数和环境变量；由 systemd 管理进程，通过 CUPS 提交打印。
- 现有 Web 提供 Agent 状态及业务打印、补打与结果核实入口，没有设备配置或服务维护页面。
- agent-mock 的页面只服务开发测试，不等同于真实 Agent 维护界面。
- 当前协议没有远程运维命令。真实设备交付仅覆盖最小打印 Agent 与已确认的 A4 单张版面；仪表、摄像头及五联连续纸仍有未实现或待验收范围。

## 已确认：页面部署边界

用户已接受“本地维护＋后台状态展示”方案：Agent 电脑提供独立于云端可用的维护页面，现有后台保留业务操作与日常状态；首期不新增云端远程配置或服务控制能力。决策及取舍见 [ADR 0016](../adr/0016-agent-local-maintenance.md)。

页面允许本机和局域网访问；维护入口独立于打印 Agent 进程。只读状态和排障摘要无需登录，完整日志及所有修改／维护操作需本地维护密码。实际进程管理和配置方式见[部署说明](../device/agent-local-maintenance.md)。

## 已完成的需求讨论

- Q1～Q3：主要使用者、断云要求、页面部署与云端职责。
- Q4～Q6：本机／局域网访问、维护入口独立可用、首期打印范围。
- Q7～Q9：本地维护密码、恢复动作拆分、打印参数校准。
- Q10～Q13：旧作业处置、配置应用、离线样张、维护记录查询（不导出）。

业务范围已收敛；安装方式、维护密码初始化／遗失恢复、服务权限和资源组织等实施细节在开发设计中明确，不将其表述为已实现能力。

## 延续已有约束

- 本地维护不产生正式电子过磅单，断云时仍暂停正式称重确认。
- 重启和重连不得自动重打；不得删除打印尝试记录以绕过去重。恢复 CUPS 队列可能使既有作业继续出纸，必须在维护动作设计中明确旧作业的处置。
- CUPS 接收或完成不等于纸面成功，正式单据的打印结果仍遵循既有核实流程。

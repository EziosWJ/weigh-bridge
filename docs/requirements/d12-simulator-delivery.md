# D12 虚拟串口模拟器交付记录

2026-10-23。用户确认实现“虚拟串口与可控 D12 报文”，并经设计问答确认网页／HTTP 控制、正常重量操作、常见故障及启动／恢复行为。本记录包含后续真实 Agent 本地启动和首次抓拍修正；用户已授权整理为本地节点提交，未推送或部署服务器上的 D12 模拟器。

## 本次实现

- 独立 `server/cmd/d12-simulator` 与 `server/internal/d12sim`，沿用 Go module、现有 `x/sys/unix`，未新增依赖。
- Linux PTY、200 ms 持续输出、现场已验证的 D12 `tF=05` 配置，吨制精确到 `0.001 t`；无 Agent 身份或业务连接。
- 内嵌控制页和 HTTP 接口：设置稳定重量、约 4 秒波动后稳定、下磅、强制失稳／稳定、暂停／恢复、单个坏帧、连续坏帧／恢复正常校验。
- 无读取端时丢弃报文，避免积压数据在 Agent 后接入时被当成新鲜测量；发送非阻塞。页面显示模拟器状态、串口路径、配置片段、计数与最近报文。
- 暂停冻结状态及波动进度；恢复继续剩余过程。进程重启从稳定零值开始，串口路径可能变化，不持久化或恢复旧车辆重量。
- `task device:d12`、`task device:d12:build`；默认 `127.0.0.1:8091`，可显式配置局域网监听。
- `task agent` 自动编译启动真实 Agent，读取根目录忽略的 `agent.env`，开发账本默认在 `.task/agent/state`；提供无真实凭据的配置示例，支持透传配置文件和状态目录。

## 后续本机联调与首次抓拍修正

本机配置曾沿用密钥占位符和示例串口路径，导致 Agent 鉴权 401 及串口不匹配。已将忽略的本地文件与运行中的 API／D12 模拟器对齐；无 WebSocket 升级的探针验证鉴权通过，不抢占已有 Agent 连接，未修改 API 鉴权或数据库绑定。

配置前后 RTSP 并实测单帧：`/front` 与 `/rear` 可用，误填的 `/near` 失败，后路已修正。工作台原要求已有前后预览图才启用采集，与真实 Agent 收到请求才抓拍的流程互相等待。已移除发起采集前的预览图片门槛，允许展示本次返回的前后抓拍；仍保留权限、操作权、设备状态、有效重量、本次两路证据和人工确认要求。

本机配置及打印账本不纳入提交；完整真实 Agent 采集和业务闭环尚未验收。

## 实现范围

- 明确的 `node.role=standalone`，固定本厂 ID、不可变部署身份和独立业务编号。自治不配置中心、不建同步状态、不启动同步任务；旧 center/site 代码和有效测试保留。
- 空业务库显式迁移后以 `weighbridge-standalone-init` 创建现场归属、本地管理员口令及独占创建的私有 `agent.env`。未初始化实例拒绝业务启动；首次启用需要本地实名人员、称重权限及本厂操作授权。身份和凭据不通过重跑初始化覆盖。
- 账号、密码、RBAC、物料分类／物料、正式往来主体与联系人使用现有管理 API。自治只办理本厂，前端展示本机就绪和按权限开放的本地管理，隐藏中心状态、下发和审批入口。
- `/api/system/agent-maintenance/*` 接入本地 JWT、查看／管理权限及实际账号审计。复用本机配置、队列、校准、日志及 systemd 控制，无需 Agent 在线或旧维护服务运行；旧服务仅保留兼容入口。草稿、保存、有效配置及运行摘要分别显示。
- 真实 Agent 新增 HTTP(S)／RTSP 前后抓拍和可选 HTTP 识别适配契约。图片重新采集并上传本地服务核验摘要；采集期间检查仪表稳定及重量，不使用旧图补足证据。识别候选必须人工核对。尚未取得现场摄像头品牌／接口参数，也未安装或验收实际识别引擎。
- `task standalone:package VERSION=<唯一版本>` 生成 Linux amd64 统一包，内嵌 Web，包含业务／设备两个常驻二进制及一次性迁移／初始化工具、manifest、安装器和说明。持久配置、图片与完整打印账本不在发布版本目录内，升级不覆盖。

## 默认开发环境维护入口补齐

默认开发模式保留已有数据库身份，以后端 `maintenanceEnabled` 能力字段和既有维护 RBAC 控制入口；维护已启用时在「系统管理 → 设备维护」显示，自治部署仍使用「本地管理」。未挂载服务时不展示菜单，直接访问页面会说明未启用。

`task dev` 按顺序补齐开发配置、显式迁移，再启动 API/Web；`task init` 为普通开发配置补齐缺失的独立维护目录，保留现有 JWT、数据库、节点角色和设备密钥。显式关闭、自定义维护目录及已命名的部署模式不自动改写。新开发目录只从已有数据库地磅绑定准备草稿，不创建节点身份、不轮换密钥、不写有效设备环境文件、不启动设备；重复启动保留已有维护数据。

验证：`task check`（开发脚本、后端 test/vet、前端 lint/build）及 `task build:check` 通过；浏览器冒烟覆盖默认开发、已禁用、无权限和原自治维护流程；隔离 PostgreSQL 回归覆盖开发 API/RBAC/身份保护及原双厂自治；真实 `cmd/api` 子进程验证就绪、登录、维护能力、配置草稿与保存。测试均不启动真实设备，现场边界不变。当前本机忽略的开发配置已补齐维护目录，校验 JWT、数据库连接、节点角色和设备密钥未变化；现有开发服务需重启并刷新页面以加载新装配。

## 2026-10-23 Agent 持有配置与分机维护

按 [ADR 0026](../adr/0026-agent-owned-device-maintenance.md) 重构：API 经已有 WebSocket 转发配置与维护操作，不再打开本机设备文件或调用本机 Agent 服务；现场 Agent 常驻并管理真实 `--env-file`、草稿、应用、回退及设备执行。页面停止设备不会退出控制进程，Agent 进程离线需宿主机恢复。现有 JWT／维护权限／业务审计及称重、打印规则保留，媒体直接播放方式保持。

先前“API 本机 .data/agent 草稿初始化和 systemd 接管”是历史实现，新默认开发入口为 `maintenance.enabled: true`；旧 data_dir 仅兼容启用标志。软件验证与部署方法见[Agent 远程维护](../device/agent-remote-maintenance.md)，真实双机及现场设备仍待验收。

# 称重强制抓拍配置

2026-10-23，用户已确认并启动实施；决策见 [ADR 0027](../adr/0027-optional-weighing-capture.md)。

## 配置与行为

- 配置管理新增系统预置布尔项“称重强制抓拍”（`weighing.capture-required`），默认 true；沿用配置修改权限，仅可改值，固定名称、键、类型、启用状态，禁止删除。变更保存审计前后值，保存后生效，无需重启。
- 业务服务决定策略并下发至 Agent；旧请求缺省为强制抓拍。配置缺失、停用或值非法按 true 处理，读取失败拒绝新业务操作。
- true：保持车前车后抓拍、上传及服务端引用校验，失败阻止采集确认。
- false：摄像头未启用／未配置时直接取得当次稳定重量；已配置时尝试抓拍和上传，失败不阻止称重，但须保存“未启用抓拍／抓拍失败／上传失败”状态及已有有效图片。已提交图片引用仍须校验；不可将任意无效引用当成正常无图。
- 仪表在线、数据新鲜、正重量、稳定、采集期间重量一致、当前设备版本、会话互斥、车牌及资料核对、人工确认、幂等和单据打印规则保持。

## 记录与页面

每次采样保存策略版本、是否强制抓拍、图片状态及说明；正式记录、单据依据快照沿用。配置变更后旧未确认采样拒绝确认并提示重新采集；已确认依据不改写。首磅、回磅、重称分别使用采集当时策略，已有无图首磅不阻止按当前策略回磅及出单，历史补打不重新要求图片。

工作台显示当前强制抓拍状态，核对窗口无图时明确展示本次状态并允许人工确认，不等待不存在的图片；有图片时可正常查看。历史记录明确显示当时策略和图片状态。普通正式单据及打印版式保持，不伪装图片加载失败为完整抓拍。

## 验证与交付

覆盖默认强制、管理员关闭／恢复、缺失及非法配置、无配置摄像头、抓拍失败、上传失败和部分成功图片、策略切换失效、仪表故障仍阻断，以及无图首磅／回磅／单磅重称／出单／补打。运行后端检查、前端 lint/build 及隔离 PostgreSQL 集成；软件结果和现场验收分别记录。

## 使用与升级

1. 同步升级业务服务（含 Web）和设备 Agent，按既有发布流程显式运行数据库 schema／seed 迁移（开发入口 `task db:migrate`）；旧 Agent 不会自动获得可选抓拍能力。
2. 具备配置管理权限的账号进入“配置管理”，编辑“称重强制抓拍”，将布尔值设为 false；保存后生效，无需重启。该项的固定启用状态不用于切换业务规则。
3. 摄像头未施工时，在设备维护中关闭摄像头并保存应用，使采重直接执行；如果保留已启用摄像头，采重仍会尝试抓拍并等待其超时。
4. 摄像头施工和验收完成后恢复设备配置，再将强制抓拍设为 true。历史无图记录及补打沿用原依据，不回填图片；未确认采样重新采集。

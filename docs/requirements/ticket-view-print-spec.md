# 单据查看与五联针打流程

2026-10-19 访谈确认。本文覆盖旧版要求先进入预览、完整资料及抓拍进入纸单的界面设计；已有单据版本、权限、打印去重及异常规则继续适用。真实打印机驱动和现场走纸尚未实现／验收。

## 已确认范围

- 查看单据以核对本趟业务、打印并交给司机为主。摘要优先展示车牌、方向、供收方、物料、最终毛皮净重；原始重量、调整、抓拍、关联及历史记录在详情中展开。
- 二次称重出单后提供查看单据与直接打印。详情页可直接打印，预览为可选入口；查看、预览、刷新和重连不触发打印，不弹浏览器打印对话框。
- 使用空白五联针打纸，五联叠放一次复写，不分别处理联次或留存方，不生成五个打印任务。单份按 A4 三等分，约 210 × 99 mm 设计；送纸孔是否计入宽度及实际走纸尺寸待现场核实。
- 2026-10-19 现场补充：纸单须有可见的表格外框、行列分隔线，文字位于单元格内，不能只输出字段文字。
- 精简纸单：酒厂名称＋过磅单、单号、车牌、入厂卸货／出厂装货、供收方、物料（含已保存规格）、最终毛皮净重（吨）、两次实际称重确认时间、出单操作员、司机签字位。补打显示次数标记；旧测试单和作废单保留对应标记。
- 重量最多三位小数并省略末尾无效零；时间按北京时间显示，隔日运输保留两个实际日期。只取当版单据快照及其选定称重依据，不从当前物料或主体资料反填。
- 原始重量、调整过程、照片、联系电话、编码及完整业务资料不进入纸单，继续在系统中查阅。

## 打印流程

1. 操作员核对单据后主动打印；Server 校验权限、有效单状态及请求去重，先保存尝试再向 Agent 下发。
2. Agent 回报成功或明确失败；无回执、断连或发起结果不确定时保持待核实，不自动重发。
3. 发起提交结果未知时先查询原请求。明确失败且未出纸允许重试；已出纸或无法排除出纸时，操作员填写原因并以补打权限发起补打。
4. 沿用原单号，记录每次尝试、补打原因及次数；打印不改变运输任务完成状态。作废单只供查看，不发起新打印。

## 实现约定

- 单据详情／预览响应增加可选 `printSheet`；Agent 的既有 `print.request.payload.ticket` 同样携带该字段，保留完整当版快照契约。
- `printSheet` 使用 `weighing-compact-v1` 模板：`widthMm=210`、`heightMm=99`、`layers=5`、标题、标记与精简字段行。`layers` 表示复写纸层数，不是打印份数。Web 与 mock 直接展示同一组服务端字段，Agent 不重新计算重量或查询当前资料。
- `weighing.ticket_title`／`APP_WEIGHING__TICKET_TITLE` 配置完整纸单标题，默认“酒厂过磅单”；部署时填写实际酒厂名称。标题属于当前打印配置，业务字段始终取历史单据快照。
- 三处打印入口复用同一操作组件及原有服务端命令。未知打印结果定时查询，不定时发起打印；核实和补打通过短弹窗办理。
- 五联复写效果、纸张宽度、针打字体、长字段排版、首张定位及连续走纸，需要真实设备联调后验收；网页尺寸和 mock 回执不能证明真实出纸。

## 验收

- 详情默认可核对本趟核心信息；展开后仍可查原始依据与历史。
- 出单结果区和详情直接发起打印，预览可选；仅查看／预览不增加打印尝试。
- 常规内容按 210 × 99 mm 排版，纸单无抓拍、原始重量或调整过程；Agent 收到与 Web 相同的精简字段。
- 覆盖两种运输方向、最终重量及精度、跨日实际时间、选定称重依据、历史缺失字段、测试／作废标记及补打次数。
- 未知结果可核实，补打原因必填，成功／失败回执更新状态；沿用已有去重与权限测试。

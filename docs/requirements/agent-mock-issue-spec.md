# Agent 通信接口与独立 Web mock

## Problem Statement

现场设备尚未联调，现有重量、识别和图片模拟混在系统工作台与服务端测试采集逻辑中，无法用未来真实 Agent 的通信路径独立验证系统，也增加了设备接入时替换模拟逻辑的成本。

## Solution

先建立最小 Agent—Server 通信契约，实现带独立 Web 控制台的 agent-mock。mock 与未来真实 Agent 使用相同协议，系统仅接收设备数据、展示状态及办理人工确认和业务操作。模拟行为全部归属 Agent，系统不区分模拟／正式两套流程。方案以开发和上线前测试为目标，保持简单。

## User Stories

1. 作为开发人员，我希望独立启动带 Web 页面的 agent-mock，以便没有现场设备时验证系统。
2. 作为开发人员，我希望 mock 与真实 Agent 使用同一协议，以便后续替换设备实现。
3. 作为开发人员，我希望通过配置指定 Server、Agent、地磅和密钥，以便快速连接开发环境。
4. 作为操作员，我希望系统显示设备在线和故障状态，以便判断是否可以采集。
5. 作为测试人员，我希望设置目标重量并模拟上磅，以便启动可重复的称重场景。
6. 作为操作员，我希望看到持续 3～5 秒的不稳定重量变化，以便验证车辆尚未停稳的过程。
7. 作为操作员，我希望稳定状态由 Agent 明确上报，以便系统与设备保持一致。
8. 作为操作员，我希望稳定后重量持续刷新，以便确认当前现场状态。
9. 作为测试人员，我希望模拟下磅并让重量归零，以便验证车辆离开。
10. 作为操作员，我希望不稳定、故障、断连或数据过期时禁止采集，以便避免无效依据。
11. 作为操作员，我希望主动采集当次重量和对应抓拍，以便核对后确认称重。
12. 作为操作员，我希望采集后的失稳、重量变化或断连使未确认依据失效，以便避免使用旧数据。
13. 作为测试人员，我希望发送车牌候选及识别失败，以便验证人工核对。
14. 作为操作员，我希望可以手工填写并核对车牌，以便识别异常时继续办理。
15. 作为测试人员，我希望使用示例图片或上传前后视角图片，以便验证预览与抓拍。
16. 作为操作员，我希望历史称重保留当时图片，以便预览更新不改变已有依据。
17. 作为操作员，我希望按现有运输任务流程完成两次称重，以便形成单据。
18. 作为操作员，我希望继续办理重称、作废、更正重开及人工重量调整，以便既有业务规则保持可用。
19. 作为开发人员，我希望系统不区分模拟／正式采集流程，以便减少环境测试复杂度。
20. 作为操作员，我希望系统内不再存在设备模拟按钮，以便业务操作界面保持清晰。
21. 作为操作员，我希望发起打印后由 Agent 接收任务，以便后续接入现场打印机。
22. 作为测试人员，我希望在 mock 查看打印内容并回报成功、失败或暂不回报，以便验证打印处置。
23. 作为操作员，我希望打印结果未知时保留核实和补打流程，以便避免重复出纸。
24. 作为操作员，我希望断线重连后查看当前设备状态，以便恢复办理而不自动确认旧重量。
25. 作为开发人员，我希望重复采集回复和打印回执不生成重复记录，以便安全处理消息重复。
26. 作为操作员，我希望旧测试单据及依据仍可查看，以便保留已有验证记录。
27. 作为维护人员，我希望保留现有用户鉴权、业务权限和审计，以便接入 Agent 不改变业务授权。
28. 作为开发人员，我希望有明确启动命令及端到端验证，以便复现集成流程。

## Implementation Decisions

- 独立 mock 程序与 Web 控制台；本轮单 Agent 对应单地磅，不建设注册审批或设备管理后台。
- Agent 主动使用 WSS 连接 Server，本地允许 WS；配置编号及连接密钥认证，与操作员 JWT 分离。
- JSON 消息首版 version=1，包含类型、消息编号、发生时间和负载；命令与回复通过请求编号关联。
- 重量以吨表达，精确至 0.001 吨；重量报文含 stable、deviceOk，系统不从波动推断稳定。
- mock 每 500ms 上报，先波动 3～5 秒再稳定；5 秒心跳、15 秒无有效消息离线。工作台轻量轮询 Server 状态。
- 上报重量、车牌候选、最近图片及心跳；下发采集和打印命令，并接收对应结果。
- 系统点击采集后取得同次重量与前后抓拍，沿用既有操作会话、任务阶段及业务摘要绑定；稳定不自动确认。
- 稳定报文重复不使依据失效；失稳、故障、重量变化、断连、样本过期或业务绑定变化使未确认依据失效。
- 图片通过 Agent 认证的 HTTP 接口上传，消息引用 Server 图片编号；文件作为称重依据保留，不接受任意 URL 冒充证据。
- Server 先记录打印尝试再下发当版单据，回执按尝试编号关联；结果未知不自动重发，沿用人工核实、明确失败重试及补打规则。
- 重连只恢复当前状态，不补传离线重量、不自动确认、不自动重打；旧连接和已结束请求不能产生新有效结果。
- 调整业务采集模块及工作台，移除测试模式门控、浏览器模拟生成及演示异常开关；保留真实异常处理、业务权限、审计、会话及命令幂等。
- 新单据统一处理与正常编号；历史测试单据、标识及依据保持原貌，不改写旧快照。
- 结构变化使用新 Goose migration，兼容 PostgreSQL 和 SQLite，不升级现有依赖及技术栈。
- 接口契约、mock、系统接入、清理和验证依次实施；文档始终区分已实现与真实设备尚未验收。

## Testing Decisions

- 用户已确认测试边界：沿用现有 HTTP 业务集成测试和浏览器冒烟，用同协议 Agent 客户端驱动输入，验证系统可见结果。
- 测试外部行为，不依赖内部缓存、私有函数或组件实现结构。
- 服务端覆盖连接认证、在线状态、波动到稳定、失效条件、采集与图片关联、重复／过期回复及打印回执。
- 复用既有称重业务 HTTP 集成测试的数据库、认证、迁移与事务约束；新增同协议 Agent 测试客户端作为设备侧输入。
- 复用现有浏览器称重冒烟，验证 mock 操作到工作台实时变化、人工确认、两磅出单及打印未知处置。
- 运行受影响后端、前端和数据库规定检查；无法运行的环境检查如实记录，不以跳过测试伪装通过。

## Out of Scope

真实仪表驱动、真实车牌识别、RTSP／实时视频、物理打印机、设备管理后台、多地磅管理界面、离线队列与补传、离线正式确认、模拟／正式双流程及测试身份审批。不得把协议或 mock 联调通过描述为真实设备验收。

## 1. 本轮目标与部署边界

两个厂区各自独立完成称重，互联网中断不阻塞本地生产；有网时自动持续同步，中心统一资料并提供跨厂查询汇总。

- 复用当前 Server／Web 项目，按中心与厂区两种角色部署，实例使用独立数据库；职责在服务端校验。
- 各厂 Web、Server、PostgreSQL 和 Agent 部署在该厂工控机上，现场设备链路及页面资源不依赖互联网。现场资源满足情况在部署前验证。
- 厂区端固定本厂业务；中心按用户权限及厂区授权提供跨厂查询。现场 Agent 连接本厂 Server。
- 首期同一目标阶段包含本地独立办理、统一资料和双厂自动同步；按先验证本地、再验证中心与双厂同步的顺序实施。

## 2. 功能分工

| 功能 | 厂区端 | 中心端 |
| --- | --- | --- |
| 称重工作台 | 本厂采集、车牌核对、首磅、回磅、隔日续称与人工确认 | 查询已同步结果，无现场称重入口 |
| 运输任务及异常处置 | 按既有权限办理纠错、终止、人工重量调整、单磅重称、作废及关联重开 | 查看任务、依据、单据版本及处置历史 |
| 单据与打印 | 本地出单、预览、打印、补打和结果核实 | 查看已同步单据及打印记录，不发起现场打印或远程业务处置 |
| 物料与正式往来主体 | 查询、选用已同步资料 | 统一维护、启停用与分发，包含既有物料分类及主体多身份资料 |
| 临时往来主体 | 有权限操作员补录及按状态选用，收到退回后补充再提交 | 人工确认转正式、关联已有主体或退回补充 |
| 账号与授权 | 本地登录鉴权，使用已同步账号与权限 | 统一维护账号、角色、动作权限、厂区授权及密码 |
| 厂区、地磅与 Agent 归属 | 保存已应用配置，现场明确应用；本机设备参数在现场维护 | 统一管理归属与连接身份，停用等待现场满足条件并应用 |
| 查询、统计与导出 | 仅本厂任务、称重、单据、依据、统计及导出 | 按授权跨厂查询、汇总、导出，显示各厂数据更新时间及图片完整性 |

物料与正式资料维护入口归中心，厂区提供选用和临时主体补录入口。工作台显示中心连接、待同步数量和最近同步时间；同步状态与任务、单据状态分别表达。中心未收到现场更新时，显示信息未更新，不据此推断现场停产或 Agent 故障。

## 3. 本地办理与断网规则

1. 入厂卸货通常先毛后皮，出厂装货通常先皮后毛；首次／二次与毛皮重分别表达。同一运输任务两次称重在同厂完成，同厂同车最多一笔未完成任务。
2. 原有人工确认、设备重量、对应抓拍、稳定状态、吨制及 0.001 吨精度、原始／最终双值、双向调整、重称替代链、过夜车和单据版本规则继续适用。
3. 操作员确认并经本地 Server 校验成功后，正式记录与单据在本地成立，不等待中心确认；临时主体的资料确认不构成单据审批。
4. 互联网中断时，本地服务及设备链路正常即可继续登录、称重、出单、打印、查询与已授权的异常处置；不按离线天数自动停止生产。
5. 本地 Server、数据库或 Agent 链路故障仍按对应故障规则处理。提交结果不明时先查询原请求，不能把未确认缓存自动转为正式记录。
6. 恢复联网上传已经确认的记录及后续变化，不自动补办称重、不重新出单、不重放打印。打印未知结果继续人工核实，补打沿用原单号、次数和审计规则。

## 4. 基础资料与任务快照

- 物料由中心预先建档，厂区不补录临时物料。往来主体保留企业／个人、多业务身份及联系人等既有模型。
- 厂区离线使用最近同步资料。收到停用结果后，新任务不得选用；已经开始的任务可沿用原依据完成正常回磅。
- 已首磅任务沿用办理时的业务资料快照。中心修改物料规格、主体名称或供货商／客户／承运商身份，用于新任务，不静默改写原任务或阻断其正常续办。
- 这一规则调整此前集中数据库中“未结束任务所需主体身份不可移除”的前提，改由原任务快照保障续办；旧系统的检查不能被当作新规则已经实现。
- 现场主动纠正本趟资料按既有纠错、作废及更正重开规则办理并留痕，不能借资料同步覆盖原始称重依据或旧单内容。

## 5. 临时往来主体

操作员默认取得单独的临时主体补录权限，不因此获得正式资料维护权限；供货方、收货方及承运方均适用。有网与断网时都可补录。

| 资料阶段 | 新任务选用 | 已开始任务与历史 |
| --- | --- | --- |
| 初次补录、待中心确认 | 可供本厂重复选用，不作为其他厂区可选档案下发 | 正常办理，本地单据无需中心再审批 |
| 厂区收到中心退回补充结果 | 禁止新任务选用 | 继续沿用原依据办理，历史单据保持有效 |
| 现场补充并再次提交 | 等待中心确认后才恢复新任务选用 | 保留原有任务和历史依据 |
| 中心确认转正式或关联已有主体 | 按统一正式资料及启用状态分发、选用 | 保留临时来源、关联关系与原单据快照 |

中心人工确认主体身份，同名仅提示、不自动归并。两厂补录同一主体后，可分别关联同一正式档案，并通过关联统一查询汇总；既有单据名称及原始资料依据不重写。

## 6. 账号、权限与现场配置

- 账号、角色、动作权限、厂区授权、密码修改及重置由中心统一维护。厂区保存独立登录和鉴权所需数据，已同步账号可在断网时重新登录；会话仍正常过期。
- 厂区收到账号停用、撤权或密码更新后生效，适用时撤销旧会话，不撤销此前已提交业务。中心撤权无法在断网厂区即时生效，此取舍已确认。
- 每厂预先同步至少两名实名授权人员账号。一人忘记密码时，由另一人使用本人账号接班；原账号等待中心重置并同步，不另建本地密码版本。
- 中心与厂区职责、动作权限、厂区范围共同约束请求，不能仅靠菜单或按钮隐藏。厂区端不能读取其他厂业务，中心不提供发起现场作废、重开或打印的业务接口。
- 中心管理厂区、地磅及 Agent 归属和连接身份，现场明确应用；各厂连接配置指向本厂 Server，本机串口、摄像头和打印参数仍在现场维护。
- 中心提出厂区停用申请，现场满足无未完成任务、未决打印、在线 Agent 等既有停用条件并明确应用后才停用。未获现场确认时显示待现场处理，不能把停用意图当作已停用。

## 7. 自动同步与中心统计

- 中心下发统一资料、账号授权及已确认范围内的配置；厂区上传任务、称重依据、各版单据、业务审计、打印尝试及对应抓拍，包含后续作废、更正、重开等变化。
- 正常网络、无积压时，业务及资料变更以 1 分钟内在接收端可见为目标。同步可见不等于自动替现场应用配置；仍需现场明确应用的事项保留该边界。
- 业务数据优先，图片随后补齐；分别显示完整性及积压进度。上传等待不阻塞现场业务确认，重复传输不重复生成业务或打印。
- 厂区端仅查询本厂业务，获授权管理人员进入中心跨厂查询。中心展示各厂最近同步时间，不把未收到的数据当成没有业务。
- 完整业务数据已到达且单据有效时，正常计入中心汇总；图片未齐单独标记，不影响单据效力或统计资格。厂区本地的抓拍要求仍然成立，不能把中心暂缺图片解释为现场可以无图确认。
- 汇总仅计当前有效单据，排除作废单，更正重开不重复计数；临时主体归并通过关联统一统计，历史快照不变。汇总与导出表达各厂数据更新时间。

## 8. 编号、首次启用与存量

- 新单号包含稳定厂区码，独立生成不重号，恢复旧备份后也不能复用已用编号。历史单号保留，补打沿用原号、作废不回收、重开使用新号。
- 首期首次安装联网完成中心注册、现场身份配置、账号资料下发，并验证断网运行；初始化后正常生产不依赖中心在线。
- 原开发联调库、图片及配置原样备份封存，新生产任务与单据从空库开始。经确认的基础资料、账号授权及现场身份可迁入，保留 Agent 身份和打印账本；旧浏览器演示库不导入、不删除。
- 联调及测试数据保留原有性质，不能迁移成真实设备采集或正式现场验收依据。

## 本阶段交付清单

1. 基础资料：物料分类、物料、企业／个人往来主体、多身份、多联系人及默认联系人；资料引用保护、停用、历史快照。
2. 工作台：车牌定位、首磅确认同时建任务、回磅确认同时出测试单；两方向毛皮语义、人工核对、隔日续称。
3. 重量与纠错：原始值和最终值分别保存，双向人工调整、业务资料纠错、单磅重称和替代关系、任务终止。
4. 单据：不可改写的版本快照、作废、关联重开、每任务最多一张有效单；旧单证据和打印内容不随新版本改变。
5. 查询：任务、当前原始称重组合、各版单据及历史详情；原始／最终 CSV 明细和汇总。
6. 打印：只读测试预览、发起记录、结果待核实、操作员反馈、补打原因和次数。
7. 服务端保障：真实权限校验、地磅操作会话占用及接管、提交去重、未知结果查询、事务及业务留痕。
8. 前端切换：使用 API 获取业务权威数据；保留局部草稿及未决 requestId，不再将浏览器整库作为业务存储。

## 测试与正式业务的边界

本阶段全部称重链路为测试，采集来源和单据性质由服务端决定，不接收客户端自报的“正式”身份。模拟稳定、重量、抓拍和识别条件可设置，但不能模拟真实账号身份或跳过服务端权限。演示断网与未知结果继续可验证。

真实仪表、摄像头、识别服务、Agent/WSS、物理打印、道闸、库存、结算和 ERP 均不在本阶段实现范围。正式采集有效期、稳定参数、现场图片验收及正式单号前缀留待设备阶段；不能将本阶段测试参数作为现场验收结论。

不新增离线正式确认，不自动把缓存补成正式记录，不将人工最终重量调整记为设备新采集。

## 必须保持的业务规则

- 单车最多一个未结束运输任务；首次和二次不固定等于毛重和皮重。首磅成功前仅有草稿，没有可查询的正式任务行。
- 统一使用吨，精确至 0.001 吨，展示省略末尾零；原始报文及设备原单位属于独立证据。
- 原始毛重必须大于原始皮重，最终毛重必须大于最终皮重，重量为正且不超三位小数；不得用人工调整掩盖原始毛皮异常。
- 最终值可高于或低于原始值；差额＝原始值－最终值。调整备注选填，空白使用“磅精度调整”；其他动作按已有要求记录原因。
- 隔日续称沿用任务与首次依据，不自动终止，不新增审核或最长间隔阻断。
- 重称保留旧记录与替代链，操作员核对装载状态及沿用另一磅的有效性；不得以装卸后的重量冒充之前的重量。
- 出单后先作废，再更正／重称并关联重开；旧单仍作废，即使后续重开失败。终止任务不可恢复。
- 资料改名不回写历史，引用后不能删除，可停用；同名主体和同名不同规格物料允许存在。
- 提交结果未知先查原结果，不能新建请求重复出单；打印未知先核实，不能自动重打。

## 验收结果

| 编号 | 可观察结果 |
| --- | --- |
| BL01 | 管理员维护完整资料；操作员能查询选择，但无资料维护权限时直调 API 也被拒绝 |
| BL02 | 入厂卸货先毛后皮、出厂装货先皮后毛均完成测试闭环；任务、称重、单据可跨浏览器查询 |
| BL03 | 首磅或二磅重复提交、提交超时后查询，不重复建任务、称重和单据 |
| BL04 | 两个终端争用地磅时只有持有有效会话者能采集确认；接管留痕，旧会话不能继续提交 |
| BL05 | 首磅跨日仍可回磅；终止后车牌释放，原任务和依据保留且不能恢复 |
| BL06 | 双向调整正确反映原始／最终／差额；原始异常不能靠调整后出单 |
| BL07 | 单磅重称保留另一磅及替代链；旧单、旧证据及旧打印快照保持不变 |
| BL08 | 作废后失败不恢复有效单；重复重开最多一张有效新单；同车新任务期间旧单可人工更正但不可实际重称 |
| BL09 | 资料改名或停用不改变历史；被引用资料不可删除，未结束任务所需主体身份不可移除 |
| BL10 | 列表日期与原始／最终汇总符合已有口径，作废排除、重开不重复；CSV 导出全部筛选结果 |
| BL11 | 浏览器打印关闭不自动报成功；人工反馈、未知结果、补打及次数可追溯 |
| BL12 | PostgreSQL 和 SQLite 的迁移与关键行为一致；默认无业务种子、无隐式建表 |
| BL13 | 所有页面和导出明确测试性质，客户端不能借参数或切换演示身份产生正式单据 |

验收场景不要求逐条编写浏览器端到端测试；验证方式及分批交付见 [实施计划](backend-business-loop-plan.md)。

# 本厂自治与三服务部署：当前阶段规格

> 数据库依据：[ADR 0024](../adr/0024-postgresql-only.md)。本规格的开发、数据库集成测试与生产均使用 PostgreSQL。

日期：2026-10-22。状态：用户已启动 Issue #6 开发，已实现自治模式、统一维护与部署工具；软件验证及待现场项见[交付记录](standalone-site-delivery.md)，生产切换尚未执行。决策依据：[ADR 0023](../adr/0023-standalone-site-baseline.md)。文档效力见[开发基线索引](../development-baseline.md)。

## 目标与范围

两个厂区分别在自己的工控机运行本地业务服务、设备服务与 PostgreSQL。无需中心即可从首次初始化到日常管理、称重、打印、查询完成本厂闭环。Web 随业务服务发布，设备维护最终使用同一地址及账号体系；CUPS 为系统配套。

本规格定义本阶段改造和验收依据，不重新定义已确认的称重规则。业务规则以 [CONTEXT](../../CONTEXT.md) 和基线索引列出的有效规格为准；现场设备验收与软件验证分别记录。

## 本地管理与初始化

1. 提供明确支持生产的本厂独立运行方式。中心地址、同步密钥、中心首次注册或下发均不是启动和写入前提；不借空角色开发兼容模式绕过初始化或权限校验。具体配置名称在实现时按现有装配确定。
2. 本地完成厂区、地磅、设备身份、实名账号、角色和操作授权初始化，沿用至少两名具备称重权限的实名操作人员准备要求，将来源改为本地配置。管理员在本厂维护账号和权限，密码修改／重置在本厂完成；继续复用 JWT、RBAC、会话过期及安全状态变化后的会话撤销规则。
3. 本地有权限人员维护物料分类、物料、往来主体及联系人。两厂各自维护，不自动共享修改；本地提供完整资料管理能力不等于赋予所有操作员管理权限。
4. 新资料按本地资料权限直接建档，不新增等待中心审批的流程。现有临时主体状态和关联记录保留；升级前逐项明确处理待确认、退回等遗留资料，不静默转正式，不丢弃历史来源与单据快照。
5. 厂区、地磅和设备绑定由本地维护，保留身份不跨厂改绑和厂区停用检查。安装初始化生成本机连接配置，减少日常手动下载导入；重装和升级复用已有身份、密钥及账本，明确应用有影响的配置变化。
6. 部署初始资料可以来自同一份经确认文件；这不构成跨厂持续同步或同名自动关联。保留稳定厂区码、跨厂不冲突的记录身份与编号。

## 本地业务与页面

- 页面资源、本地登录、资料维护、授权、称重确认、单据、异常处置、打印、查询与导出均不依赖互联网或中心运行时服务；本厂仅办理和查询本厂数据。
- 本地管理员修改资料用于后续任务；已首磅任务沿用原资料快照正常回磅，主动更正按既有流程留痕。原始重量、最终重量、人工调整、单磅重称和单据版本约束保持。
- 操作员确认经本地业务服务校验后形成正式记录。互联网断开不阻塞；本地业务服务、数据库或设备链路故障不能退回浏览器缓存确认。提交结果不明先查询原请求；打印结果不明先核实，恢复或重启不自动补称、重出单、重打。
- 当前产品入口隐藏或移除中心状态、同步积压、中心审批及配置下发操作；后台同样解除对中心的依赖并落实本地权限，不能只改菜单。保留可观察的本地服务和设备故障状态。

## 设备维护与部署整合

设备进程继续独占串口、处理设备协议和打印执行；业务服务不另开串口。现有 WSS／本机 WS 契约和设备身份校验继续复用，开发 mock 与真实 Agent 保持每磅互斥。

本地业务服务接管日常设备状态、串口／打印参数、队列及校准操作、服务控制和维护记录入口，复用本地登录与权限。保留配置草稿／已保存／已生效区分、操作结果核实、设备及 CUPS 所需最小授权、敏感配置脱敏与维护审计；不将业务服务整体以 root 运行作为整合方式。只读排障范围按本地账号权限提供，原匿名维护页不自动开放到业务系统。

独立维护服务可在过渡期继续使用。统一入口能在设备进程停止时检查状态、修改有效配置和启动设备，且不依赖旧维护服务后，才退出旧服务与独立密码入口。业务服务自身无法启动时使用 systemd、日志和本机配置恢复。摄像头维护只呈现真实能力，不以未接入的占位页面代替驱动。

最终提供统一版本的安装包及安装、启停、升级说明，管理两个自研进程和本地数据库依赖；不要求更换既有数据库技术、打包框架或设备协议。生产页面使用现有内嵌构建能力，无需单独 Vite／Node 常驻服务。host-collector 为可选监控能力，不作为本期新常驻依赖。

## 实施顺序与验收

每步完成相关验证后直接衔接；本次开发按以下顺序实施。软件验证不替代现场验收。

| 步骤 | 可观察验收条件 |
| --- | --- |
| S1 独立初始化与本地管理 | 不配置、不启动中心，从空业务库完成本厂初始化；本地登录、账号维护／密码重置、权限管理、资料增改停用可用；无权限请求被服务端拒绝；另一厂状态不影响本厂 |
| S2 本地发布与恢复 | 一台工控机运行业务、设备及 PostgreSQL，页面由业务服务提供，旧维护服务可按过渡安排保留至 S4；断互联网后刷新、重登、维护资料及办理测试闭环正常；重启后身份、数据、图片和账本保留，按既有恢复规则处理未决操作 |
| S3 真实生产闭环 | D12 非零及稳定判定、真实对应抓拍、人工核对、两次称重、单据、实物打印和结果核实逐项现场验收；真实能力未验收前不宣称正式闭环完成 |
| S4 维护入口整合 | 同一地址与账号按权限查看设备、配置及执行维护；设备停止仍可排障和启动；旧维护服务停止后上述功能正常，业务服务故障有系统级恢复说明；最终常驻自研进程为两个 |

软件以现有 HTTP API 为主要测试边界，覆盖两厂独立库、同牌各自任务、本厂范围、防重复提交、历史快照和单据版本；真实设备前可用独立 mock 验证业务。增加少量浏览器冒烟验证本地管理与维护入口。维护整合的软件工作可与现场验收独立推进，软件通过不代替 S3 现场结论。

按改动运行根指导要求的后端、前端和数据库检查；统一进行 PostgreSQL 数据库验证，见 [ADR 0024](../adr/0024-postgresql-only.md)。不以删除旧测试、跳过配置检查或关闭 CI 达成自治；受新决策影响的旧断言需明确更新适用模式并保留有效回归行为。

## 数据、迁移和交付边界

代码实施与新增权限 seed migration 见交付记录。后续结构变化继续新增 Goose migration，保留历史迁移；不直接改库身份字段或覆盖既有数据来切换模式。生产前封存联调库、图片和配置，生产交易从空库开始，仅导入确认资料／账号和现场身份，保留 Agent 打印账本。已存在生产记录时必须制定兼容迁移与回退步骤，不能用联调库覆盖。

部署与备份清单同时覆盖数据库、图片、设备身份、有效配置和账本；恢复不自动重放物理打印。单盘故障保护目标保留，具体方案及恢复指标继续暂缓，不因中心暂缓就宣称本地单盘安全。

本期不实现或验收中心汇总、双向同步、统一账号资料、临时主体中心审批、远程控制；不合并业务与设备进程，不切换生产数据库，不新增微服务基础设施。未来中心建设须重新确认范围，优先评估只读汇总，旧方案和代码不自动转为需求。

## 目标与边界

面向操作员办理车辆首磅、回磅，主管处理异常，管理员维护资料。默认进入称重工作台，通过车牌定位当前运输。沿用纯前端模拟、当前浏览器保存、既有登录与权限契约、现有组件及依赖。正式业务 API、业务表、现场设备、实际打印、跨终端协作仍未实现，本次不新增。

## 已确认的页面分工

| 导航 | 页面与职责 |
| --- | --- |
| 称重作业 | 工作台只办理当前车辆的首磅／回磅；运输任务列表仅查询和选记录，独立任务详情展示依据、替代链及历史 |
| 单据查询 | 测试过磅单列表查询、导出；独立单据详情处理单据关系及异常；独立只读打印预览 |
| 基础资料 | 物料、往来主体独立维护；物料分类由管理员维护简单列表；主体多联系人属于该主体资料 |
| 演示设置 | 独立页面管理模拟重量、稳定／超时／网络／证据／未知结果、岗位、占用接管和本模块重置 |
| 既有系统 | 保留系统管理、消息与监控；原系统概览保留；开发示例集中分组且默认折叠，不优先于称重导航 |

侧栏作为主导航；业务页不重复铺满一排模块切换按钮。保留简明的测试性质、演示岗位及设备未接入说明。任务／单据详情采用已有 Detail Pattern；重称、纠错、核实、终止、作废、重开、补打授权通过详情中的短操作弹窗完成。资料长表单可使用独立编辑页，避免联系人编辑与完整资料挤入窄弹窗。

## 操作员路径

1. 输入车牌并查找；有未结束任务直接显示该任务、首次依据和当前阶段，没有则填写本趟信息。等待回磅的其他车辆不占据当前工作台。
2. 首磅：填写方向、物料、供收方及选填的承运方、联系信息、司机和备注；采集重量、人工核对后一次确认，同时建立任务与首次称重。没有另一个“先建任务”按钮。
3. 回磅：通过车牌进入原任务，核对首次依据并采集当前重量、明确确认；必要时先到任务详情办理跨天核实／主管纠错。
4. 成功后清楚展示结果，提供“办理下一辆车”和“查看任务／单据”。未知提交先查询原结果，不自动重试建任务或出单。
5. 查不到资料时保留当前草稿；管理员到独立页面补充后，返回工作台可刷新候选继续。离开工作台、刷新、往返演示设置均保留本模块草稿。资料选择支持名称、简称、编码搜索，供收方按方向过滤，承运方按承运身份过滤。

首次合并操作仍遵守采集条件、人工确认、同车未结束唯一与去重。历史示例／旧缓存的待首次任务可继续办理，不破坏原状态规则。原有净重大于零、方向锁定、重称保留依据、终止不可恢复、作废关联重开、有效单唯一、打印核实与补打规则继续生效。

## 资料模型

### 往来主体

“往来主体”包含企业和个人，是原“往来单位”的扩充；主体性质与业务身份分开。一个主体仅建一份资料，可同时是供货商、客户、承运商。同名个人允许存在，通过编码与电话辨认。

| 字段 | 规则 |
| --- | --- |
| 编码 | 自动生成且唯一，编辑时只读 |
| 名称 | 必填，允许同名，出现同名时提示核对编码／电话 |
| 简称 | 选填，可搜索 |
| 主体性质 | 企业／个人，必填 |
| 业务身份 | 供货商／客户／承运商多选，至少一项 |
| 主体联系电话、常用业务地址、备注 | 选填，不阻塞称重 |
| 统一社会信用代码 | 企业选填 |
| 启停状态 | 停用后不供新选择，已有记录不改写 |
| 联系人 | 多个，姓名、电话、职务／用途、备注；存在联系人时指定一个默认联系人 |

每趟任务有一个必填供货方／收货方；承运方选填，可与供收方相同。司机姓名、电话独立属于本趟运输，不自动创建往来主体。默认联系人可带入本趟联系信息，与司机分开保存。业务记录保留当时主体编码、名称、联系信息和承运方快照，资料修改不回写历史。

### 物料

编码自动生成且唯一；名称必填；分类、规格／等级、启停、备注完整展示；称重单位固定为吨，业务精度为 0.001 吨，显示省略末尾无效零。每种可独立称重、查询和汇总的规格建独立资料，允许同名不同规格。选择时同时显示名称、规格和编码。分类由管理员维护简单列表，已引用分类和资料不能删除，可停用。资料列表支持搜索、状态，以及适用的分类／身份筛选。

已引用物料和主体禁止删除；已引用主体身份调整不能使现存未结束任务失去所需供收／承运身份。停用或资料改名不改变已确认历史。

## 保存与兼容

仅维护称重模块独立浏览器命名空间。已有初版测试任务、单据、称重及历史应保留；旧单选供收方转为对应的身份集合，旧资料补自动编码及空白选填字段，旧业务快照缺失新增字段时留空，不从当前资料反填历史。保留原存储 key 兼容读取并升级模块版本，重置只恢复本模块新示例。

## 改版验收

- 登录后默认工作台；主导航分组明确，工作台没有资料管理、演示配置长表单或任务下拉杂项。
- 通过车牌首磅一次确认、回磅匹配原任务、成功后办理下一辆车；失败或未知结果不重复生成任务／单据。
- 演示设置独立，往返保留草稿；资料补录后返回可继续选择。
- 企业／个人可多身份；供收与承运分开；多联系人有默认项，司机与联系人不混用。
- 物料规格可辨认；编码、分类、联系方式、状态与备注可维护和查询；历史快照、引用保护生效。
- 列表、独立详情、独立预览职责清楚，已有异常处理、两方向净重、打印核实及筛选导出保留。
- 旧浏览器数据可继续读取，重置不影响登录及其他模块；实际检查结果记录后再标注改版完成。

## 工作台进一步减负（本轮确认）

用户再次试用后反馈工作台上下内容仍过多，已确认实施“按状态逐步呈现＋固定操作区”，不把称重主流程拆成可自由切换的 Tab。

- 顶部用紧凑车辆栏，只保留车牌、查找、当前阶段；测试性质与设置入口简明显示，不重复堆叠说明卡片。
- 首磅常驻运输方向、物料、供收方三个必填项；承运方、联系人、司机及备注放入默认收起的“补充运输信息（选填）”，收起仍显示已填摘要，原字段与保存规则不变。
- 重量及当前操作在桌面右侧保持可见；填写阶段明确缺项，资料齐备后采集，采集后核对并确认。保留采集与人工确认，不因稳定而自动提交。
- 回磅只常驻车牌、方向、物料、供收方、首次重量和时间，次要信息收起；纠错及完整证据仍在任务详情。
- 同一位置呈现当前操作：采集、人工确认、异常恢复提示、查询未知结果或办理下一辆。失稳、断网等不和正常确认按钮并列让操作员自行判断，未知结果必须先查询。
- 按包含既有侧栏及64px顶栏的1366×768桌面可用区域验证：普通首磅／回磅折叠状态下重量、关键核对信息和主操作无需整页滚动；展开选填或窄屏允许正常滚动，操作区在桌面保持可见。

本轮不改变称重核心、资料权限或存储模型。验证运行规定 lint、build、现有核心行为测试及一条受影响页面冒烟，不重复无关菜单／侧栏全套。

## 人工核对交互（本轮确认）

工作台原来的总勾选“我已人工核对车牌、业务信息、重量及模拟证据”改为引导式交互：采集后点击“开始核对首磅／回磅”，依次展示车牌、业务信息、重量、模拟证据四项本次实际值。每项明确点选一致后进入下一项，支持上一项或不一致返回修改。四项后展示汇总，最终明确确认才保存称重；中途关闭或返回不提交。

核对会话只在当前页面内存在，绑定本次数据状态。重新采集、修改资料或模拟条件、切车／切岗位等导致本模块状态变化时，旧进度失效；不得沿用旧内容提交。模拟证据只表示演示状态可用，始终提示摄像头未接入、没有真实抓拍。复用现有 Dialog 与按钮，核心称重入口和浏览器业务数据结构不变。

## 模拟摄像头与抓拍图片（本轮确认）

用户明确要求没有真实摄像头也完整展示拍照截屏界面。当前阶段改为配置内置模拟车辆图片，并展示摄像头预览、随称重采集的模拟抓拍、逐项人工核对中的图片与放大查看、称重历史中的对应图片。所有画面标记“模拟图片／摄像头未接入”，不声称真实实时视频或现场抓拍。

演示设置可选择内置车头／车尾示例视角；工作台预览选定画面，采集时形成包含图片来源、视角、时间、重量及关联手填车牌的独立模拟抓拍。确认记录保留当次图片快照；更换模拟图、重新采集、重称不改写旧记录。旧缓存没有图片的历史记录明确提示未保存，不用当前示例反填。抓拍失败仍阻止确认，核对进度随图片／采集状态变化失效。

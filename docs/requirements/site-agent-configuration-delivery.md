# 厂区配置与 Agent 启动配置交付记录

日期：2026-10-21。用户在[需求讨论](site-agent-configuration-discovery.md)逐轮确认 Q1～Q11，简化凭据流程，随后明确启动开发并要求部署 Agent 至 SSH 主机 `fcc-com-01`。本轮代码、规定检查、受控浏览器验证及该主机部署已完成。真实仪表、摄像头驱动及完整称重设备现场验收不属于本轮交付。

## 已交付

- 后台新增“基础资料 → 厂区配置”，地址 `/weighing/site-config`。按既有列表 Pattern 提供厂区、地磅及 Agent 列表、查找和状态筛选；支持新增、编辑、停用、重新启用，本期每厂一磅，不提供物理删除。已有编号及归属保持不变，新增厂区业务授权仍在用户管理中单独分配。
- 新增厂区配置与启动配置导出独立权限，默认仅管理员拥有；获导出权限者可查看列表并下载，修改仍需配置权限。普通业务操作员不自动获得配置权限。
- 后台统一设置现场工控机可访问的 Server 地址。每厂下载一份 JSON，包含 Server 地址、厂区／地磅名称和编号及既有 Agent 连接参数；可重复下载、保存和使用，不引入一次性签发或凭据轮换流程。普通查询、维护日志和审计不回显密钥。
- Agent 绑定持久保存，新连接实时读取后台映射，不需修改 Server 文件或重启 API。升级启动时只导入旧配置中尚未迁入的映射，保留原身份与密钥，已有后台记录不被旧文件覆盖。其余 YAML 运行配置沿用原职责；API 启动不执行建表或结构迁移。
- 真实打印 Agent 的本地维护台新增 JSON 导入：先展示厂区、地磅、Agent 及地址，确认后只保存连接草稿，保留本机 CUPS 队列、校准和账本；应用仍经过既有队列核查、明确重启及失败恢复。厂区名称等信息写入既有 `agent.env`，打印进程统一读取该文件。
- mock 新增 `--config 文件路径`，使用与真实 Agent 相同的厂区连接配置；可独立指定 `--listen`，页面和启动日志展示现场归属。文件模式不混用旧连接参数，不依赖读取 Server 数据库或 JWT 配置。
- 停用时列出未完成任务、未决打印及在线 Agent 阻塞原因；停用后禁止新业务和设备接入，保留原授权下的历史查询、单据、图片及导出，重新启用恢复原授权。新连接准入与停用互斥，业务写入与停用通过厂区行锁协调；不静默改绑在线连接。
- 新增 Goose schema `00015_site_configuration`、seed `00009_site_configuration`，PostgreSQL／SQLite 对齐，保留所有历史 migration。

## 使用入口

1. 管理员打开“基础资料 → 厂区配置”，维护厂区和对应 Agent，确认现场地址。
2. 下载目标厂区的 `SITE01-agent.json` 或对应编号文件。
3. 真实 Agent 打开本地维护台的“配置”，导入文件并预览，确认保存草稿，再明确应用。新工控机仍需选择本机已安装队列并检查打印参数。
4. mock 示例：`task agent:mock -- --config /path/to/SITE02-agent.json --listen 127.0.0.1:8091`。同一地磅的真实 Agent 与 mock 继续互斥。
5. 在用户管理分配厂区查询／操作范围，再从厂区工作台进入指定现场。

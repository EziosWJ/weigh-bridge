## 余额监测

本环境无独立额度工具，读取本地 Codex 会话 `token_count.rate_limits` 中 `window_minutes=300` 的最近记录，只提取时间、剩余百分比和重置时间，不读取或输出凭据。会话记录可能有延迟，检查时须注明最新可见快照；若无法读取，说明无法保证自动阈值停止，不能把 token 上下文余额或运行时长当作 5h 余额。

开发期间在批次切换及长任务间检查；可见剩余低于 5% 时停止新增开发，清理本任务启动的服务、记录未完成内容与检查结果并汇总。

## B03–B06 已完成的行为检查

- schema 00011（PG／SQLite 同版本）增加会话、采样、任务、不可变称重事实、各版单据、幂等结果、业务历史及打印尝试；SQLite 非空回退、重建已通过。SQLite Down 清除循环 FK 指针，迁移布局测试相应识别其为结构回退所需的数据操作。
- SQLite 验证两方向、首磅去重、旧会话接管失效、原结果查询、跨日续称、原始异常不能被最终值掩盖、双向差额、单磅重称及旧单快照。
- 同车新任务进行时，旧单允许基于旧依据人工重开，旧任务实际重称被拒绝；新任务终止不可恢复，释放车牌后可办理原单约定的重称与重开。
- 二磅成功审计注入失败时，新增称重、单据、任务状态和操作结果一并回滚；之后同请求可安全重新执行。业务拒绝单独保留异常尝试，未形成有效二磅。
- 原始列表按当前有效二磅时间，最终列表按各版出单时间；汇总仅计当前有效单。CSV 不受 pageSize 限制，包含全部筛选行。
- 打印发起仅记为待核实，未知补打保留前次 unknown，操作员明确失败后的 retry 不增加 reprintCount。打印不改变任务完成或单据重量。
- `task backend:check`、相关前端 lint/build 与 SQLite 全套集成在批次中持续通过；最终结果以收尾记录为准。
- 扩展 `test:weighing:backend-master`，使用临时 SQLite 和真实登录／浏览器，已验证两方向的工作台、先采重后补资料、作废人工重开与旧单不变。模拟未补资料的首磅样本先绑定车牌和方向，确认时校验当时已核对的资料版本；已具完整资料的样本仍绑定完整快照。

5h 余额首次观察约 63%，最低观察到约 31%；随后额度窗口重置，继续实施，未出现可见余额低于 5% 的停止条件。

## B07 收尾

- 测试模式默认关闭并由真实 API 用例验证；开启后来源固定 simulated，不能伪造成正式采集。
- 会话与采样 TTL 可配置；旧 token、旧代次和过期样本不能确认。读取任务／单据用一致的只读事务；历史分页按时间及 ID 稳定排序。
- 权限从真实角色菜单动作码读取，隐藏动作仍有效；撤销后当前 token 的下一次请求即被拒绝。补打、导出、资料写入及旧系统赋权入口均有服务端检查。
- 非空 SQLite 业务包含各版作废单、自引用替代链、打印记录和业务事件，schema 00011 Down／Up 验证通过。
- 余额持续读取本地最新可见 300 分钟窗口快照；窗口重置后继续，未出现低于 5% 的可见记录。最终余额随最终回复报告。

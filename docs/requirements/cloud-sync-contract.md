# 厂云同步契约：第一版业务边界

本文记录两端共享的已确认目标，包含尚未实现的摘要同步、对账和同步模块，不能作为现有实现、部署或验收完成的证明。两端仓库保留一致副本，调整时同步维护。本厂详细业务、字段和例外以本地有效规格为准。现有接口和版本 3 字段见云端仓库 `docs/requirements/weighbridge-sync-api-design.md` 及本文末尾的现行协议说明；新协议接口和摘要规范须在实施前另行细化。

## 接入与身份

- 本次各厂正式投入使用时即接入云端；目前各厂尚未使用，本次上线没有需要整理或导入的历史资料及单据。系统保留单机自治能力，不开发自动匹配或合并。
- 云端地址及同步开关由维护人员配置；厂端主动访问云端，不配置或使用厂端同步凭据。云端通过请求中的厂区编码检查该编码存在且启用，以编码决定数据归属；编码不是秘密，不提供请求来源认证。
- 云端维护唯一的厂区编码和名称，不登记地磅，不向厂端提供厂区 ID。厂端在本厂身份中维护厂区编码和地磅编码；地磅编码仅用于本地设备和业务，不参与厂云同步校验。
- 首次同步和每次资料同步携带当前厂区编码；云端校验编码后返回完整资料，厂端成功应用后进入云端资料模式。编码不存在或停用时同步失败并保留上一版。
- 厂端和云端允许更正编码。上传的单据和变化按其携带的厂区编码归属；例如两个厂端互换编码后，云端仍按编码归属对应厂区，不根据物理来源重新分配已上传数据。厂端历史单号、厂区编码和名称快照不改写；待上传单据使用其出单时的厂区编码，作废使用原单厂区编码。
- 厂端或云端改码前检查可获得的待同步信息并明确提示；云端无法独立获知厂端积压，须结合厂端信息，管理员仍可继续改码。云端更正厂区编码时保留该厂已接收数据；旧编码不再接受新写入，未成功的旧编码变化由维护人员处理，不自动改写历史或待发载荷。允许按旧出单编码和变化摘要只读查询已接收的历史确认，用于处理回执丢失，不允许借此写入新变化。历史编码保留给原厂，不能分配给其他厂，原厂可以改回该编码。不同厂端使用相同编码时云端无法区分来源，发生相同单号或变化标识冲突时拒绝而不覆盖。
- 重开单可能使用新厂区编码，而原单使用旧编码：变化须同时标识新单编码和原单厂区编码，云端分别按编码定位新单归属与原单；原单须已作废且不能被重复重开。具体字段及冲突、跨厂关联语义需两端契约测试确认。
- 云端是否使用内部主键属于实现细节，不作为跨系统身份或接口字段；按用户要求目标数据模型不依赖厂区 ID，改码保留已接收数据的归属和出单编码；本次无需旧数据库迁移。
- 打开同步开关后，本厂管理员手动发起首次完整同步；成功后才进入云端资料模式，首次成功前不办理正式称重。失败保留原资料、不切换模式，允许手动重试。首次同步成功后断互联网仍可独立办理本厂正常业务。

## 总部资料下发

- 总部维护物料分类、物料、往来主体及联系人，下发所有厂；云端资料模式中资料只通过同步更新，账号与授权仍由本厂管理。总部资料维护权限现阶段不讨论。
- 首次同步成功后，本地 Server 每小时自动拉取一次全部资料，操作员也可主动同步全部资料；主动同步不触发单据上传。完整下载并校验成功后在本地事务中整体生效，失败保留上一版，不产生部分更新；本地继续使用上次成功资料，等待下次每小时同步或手动重试。资料页面显示上次成功时间，资料列表不显示逐条同步状态；管理员可查看和清空自动及主动资料同步日志，日志不包含不必要的敏感信息。
- 已同步总部分类、物料或主体若在后续完整快照中意外消失，整次同步失败并保留上一版；总部通过停用保留这些资料。联系人允许从主体中移除，历史业务快照不改写。首次完整快照允许为空。
- 维护人员关闭同步开关并重启后退回单机模式，可按本地授权维护资料。重新开启并重启后须由管理员手动同步；成功时总部同编码资料覆盖单机期间的修改，厂端新增资料保留供历史查询，不自动匹配或上送且云端资料模式下不可用于新任务；已首磅任务按原快照完成。失败保持单机模式和原资料。
- 关闭同步期间保留此前及单机期间产生的待上传变化，停止单据上传和自动对账；重新开启并完成必要的手动资料同步后，按依赖顺序继续处理，不清空队列。
- 总部物料、主体、分类编码分别使用 `C-M-0001`、`C-P-0001`、`C-C-0001` 形式；同类型流水号持续递增、至少四位且超过 9999 自动扩展。联系人随主体同步，使用云端稳定标识。具体资料字段、约束和停用规则以本地业务规格为准。
- 总部分类停用后新物料不可选择该分类，已有物料和历史单据保留关联；本地收到物料或主体停用后，新任务不得选择该资料，已首磅任务按原快照完成回磅。重新启用沿用原编码。离线期间使用上次成功同步的状态；资料更新不改写业务快照。缺少资料又无法同步时的临时录入不在范围内。

## 过磅单上送与确认

- 本地正式单据是权威依据，云端仅接收已出单数据供总部查询统计；待回磅任务留在本厂，云端不提供修改、作废或重开本厂单据的业务操作。
- 上送纸单信息、原始及最终重量、人工调整前后值和差额、来源、备注、调整人和时间、司机姓名及电话、联系人及联系电话、物料和供收方编码及名称快照；缺失值保留本地事实。重量统一为吨、精确至 0.001 吨，差额为原始值减最终值。具体字段及例外以本地有效业务规格为准。
- 照片、待回磅任务、打印状态、打印尝试、补打次数及原因留在本厂；单据不上送承运方编码及名称、重称及资料纠错过程或被替代称重记录。承运方基础资料仍由总部统一维护和下发。
- 出单新增云端对应单据；作废更新原单状态、原因、操作人和时间，不覆盖其业务和重量快照；重开以新单号新增并关联原单。同一单据的变化按顺序处理，较早状态不得覆盖较晚状态。重开上传等待原单创建及作废均获云端确认，前序失败时后续等待。
- 出单、作废和重开与相应待上传变化在本地同一数据库事务中保存；后台尽快上传，断网不阻塞本地业务。云端完成保存并确认后本地才标记该变化完成；未知结果使用原变化和原摘要重试。某变化已确认不代表其后的作废或重开已确认。
- 厂端为每次变化计算 SHA-256 摘要，摘要同时作为变化标识和对账依据，不另设随机变化标识。摘要覆盖规则版本、出单时厂区编码、单号、变化类型、约定同步的完整单据业务内容及适用的作废信息、原单关联；作废后的摘要代表作废后的单据状态。固定并版本化字段集合、顺序、编码、空值、十进制重量和时间等规范化规则，厂端重试始终使用已保存的原载荷和原摘要。协议演进及不同摘要规则版本不可直接比较时显示待核查，不直接判为内容冲突；具体规范和跨版本处理须在实施前确定。
- 云端在同一事务保存业务结果、该变化摘要及单据最新变化摘要，按厂区、单号、变化类型和摘要识别重复；已处理的变化返回确认，不重复执行业务或让较早状态覆盖较晚状态。云端保存厂端上传的摘要，不重新计算，不另存完整变化载荷用于逐字段去重；因此依赖厂端正确计算，不能发现相同摘要搭配不同内容或云端内容后来被单独修改。摘要不提供来源认证。
- 厂端保留原变化和摘要，云端保留已确认历史变化摘要及最新摘要，第一阶段均不自动清理，以支持迟到重试和历史确认。网络超时、结果未知或云端暂不可用时自动退避重试；管理员可手动立即重试原变化，不跳过前序。前序未完成显示等待前序；厂区编码、协议或数据错误提示管理员处理；单号或变化冲突暂停该单据及依赖它的重开，其他单据继续。云端返回可区分临时故障、前序未完成、配置或数据错误及冲突的类别。

## 单据对账与异常处理

- 厂端按出单时厂区编码和单号发起单张或批量核对，查询云端已接收变化及最新摘要；云端不主动读取厂端数据库，也不要求厂端上报积压或对账结果。摘要相同表示双方记录的最新变化摘要一致，并非云端内容已被独立校验。摘要不同先结合变化历史和上传进度判断：已知云端处于尚待上传的前序状态时显示待同步；确认无法按正常顺序处理的差异为冲突；无法判断、摘要版本不可比较或请求失败时显示待核查或结果未知，不冒充一致。
- 按用户确认，厂端单张对账接口可在可信网络内无厂端凭据读取完整云端业务快照和作废信息，以便厂端管理员查看字段差异；厂端本地详情仍只向有权限的管理员开放。云端无法以厂区编码识别请求来源，能访问接口且知道厂区编码和单号的网络访问者也能读取姓名、电话等字段，部署时应限制该接口的网络访问范围。批量对账只返回摘要和状态。
- 每天在可配置的固定时间自动检查最近 7 天发生过变化的厂端单据及更早未确认的变化；错过执行时厂端启动后补做。管理员可按单号或日期范围手动对账。第一阶段只从厂端现有单据出发，不检查云端有而厂端没有的完整集合；备份恢复后的完整对账另行讨论。展示最近一次对账结果和时间，与变化同步确认状态分开；不将结果解释为永久实时一致。需要人工处理时可重新核查，不要求复杂的并发对账机制。
- 云端确认缺单且厂端保留原出单变化时，按原变化及依赖顺序自动补传；若原变化不存在，或云端记录已确认出单但找不到单据，提示管理员或维护人员处理，不静默补造或覆盖。云端历史确认显示已接收同一摘要变化时，可确认该变化；后续变化未确认时不将整张单据标为已同步。
- 云端比厂端更新或出现内容冲突时保留差异并暂停相关单据，管理员记录核查结论，由维护人员按明确方案处理；第一阶段不提供直接覆盖或删除云端单据的按钮。管理员明确发起重新核查，依赖和差异均满足条件后才恢复；仍有冲突继续暂停。差异详情向有权限的管理员展示厂端和云端相应字段，普通尝试日志不记录完整单据内容。

## 同步模块与日志

- 厂端提供厂云同步模块，分为单据同步、基础资料同步、同步日志三个菜单。单据同步页展示待同步数、需处理数、最近成功时间和最近对账结果，可筛选单据、单张核对、按日期批量对账；详情展示各变化状态、等待原因、重试、关联重开及冲突处理。单据列表保留简要同步状态；同步状态与最近对账结果及时间分开展示。
- 基础资料同步页提供资料同步状态及主动同步；原资料页面的主动同步入口保留，两者均执行同一完整资料同步，不触发单据上传。普通操作员可在有权查询的单据列表查看简要状态；管理员查看同步模块详情、执行对账与处理。菜单显隐不替代服务端授权。
- 同步日志记录自动及主动资料同步、单据上传尝试，可按时间、类型和结果筛选；普通尝试日志暂不自动清理，管理员可手动清空，清空不删除变化或改变同步状态。冲突、核查结论及处理记录单独保留，不随普通日志清空。
- 云端提供厂云同步页面，按厂区展示最近成功接收情况，并按单据查询已成功保存的变化及重开关联。接收时间不表示厂端在线、没有积压或数据完整；云端不展示未知的厂端待同步数量，上传失败原因在厂端查看。总部管理员可查看该页面。

## 云端查询与统计

- 总部人员可查询所有厂，不按厂区限制查询范围；厂区人员在本地查询。云端页面提示数据可能尚未同步。
- 只统计云端已收到且当前有效的单据，作废单不计，重开后只计有效新单；按最终净重汇总，可区分入厂卸货和出厂装货。按单据保留的原资料编码统计，不自动合并不同编码。
- 接受断网补传带来的统计滞后；原单作废获确认到重开单获确认之间可能暂时少计。不得把云端当前结果解释为各厂已实时完整上报。

## 实施前需细化

新协议的摘要版本、规范化字段与测试向量、接口字段、错误类别、分页和对账实现仍需双端细化及验证。当前尚未正式使用，新协议不要求兼容或迁移现有单据协议 v2/v3；在干净环境验证，现有测试环境及数据先保留，备份、清理或重建另行决定。总部资料维护权限现阶段不讨论；旧备份恢复后流水号倒退的正式处理仍暂缓，不在本契约中决定。

## 现行版本 3 单据字段及确认（非新协议目标）

现有厂端实现发送版本 3，现有云端源码兼容版本 2 和 3；实际部署版本及联调状态须另行核实。版本 3 相对版本 2 新增净重调整字段和显式最终净重，接收端须先支持版本 3 才能正确接收和统计。以下仅描述现行协议，不代表上述摘要目标已经实现。

出单、重开变化的 `ticket` 固定包含 `ticketNo`、`previousTicketNo`、`title`、`plate`、`direction`、`materialCode`、`materialName`、`materialSpec`、`partyCode`、`partyName`、`firstConfirmedAt`、`secondConfirmedAt`、`issuedAt`、`issuerName`、`originalGross`、`originalTare`、`finalGross`、`finalTare`、`finalNet`、`netAdjustment`、`netAdjustmentMode`、`netAdjustmentRateBp`、`netAdjustmentCategory`、`netAdjustmentCategoryName`、`previousFinalGross`、`previousFinalTare`、`previousFinalNet`、`previousNetAdjustment`、`grossSource`、`tareSource`、`adjustmentRemark`、`adjustedBy`、`adjustedAt`、`driver`、`driverPhone`、`contactName` 和 `contactPhone`。空文本为 `""`；无原单号、上版重量、比例或调整人时间时对应字段为 `null`。

重量为最多三位小数的十进制吨字符串；`netAdjustment` 为有符号调整量，正数扣减、负数上调；`netAdjustmentMode` 为 `amount` 或 `percent`，`netAdjustmentRateBp` 以 0.01% 为单位且仅比例录入时非空。两次确认时间取单据保存的称重依据，调整人取当版出单时的操作员快照。上版重量和上版净重只在重开时来自原单快照，历史资料不从当前资料反填。接收方以 `finalNet` 为准，并可用 `finalGross − finalTare − netAdjustment` 复核；毛重／皮重更正差额由接收方按原始和最终毛皮重计算。

云端成功响应的 `data` 包含 `changeId` 和 `ticketNo`，厂端必须核对二者后才能确认。云端先校验请求的当前厂区编码，再处理去重：云端改码后即使旧变化曾成功，使用旧编码重试也会返回 401。旧编码的未确认出单或作废不能在该接口下继续处理；重开可用 `previousSiteCode` 查找已经成功作废的旧单，但不能绕过尚未成功的旧单作废。需要云端另定处理方案，不修改本地历史或待发载荷。

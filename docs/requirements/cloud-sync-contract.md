# 厂云同步契约：第一版业务边界

本文记录已确认的厂云行为，是两端规格共享的业务契约；不表示功能已经实现，也不是可直接调用的 HTTP 协议。两端仓库保留一致副本，调整时同步维护。本厂详细业务、字段和例外以本地有效规格为准。具体路径、请求和响应字段、类型、空值、时间格式、分页、版本兼容、错误码、凭据形式及重试参数待实施前设计并在两端保持一致。

## 接入与身份

- 本次各厂正式投入使用时即接入云端；目前各厂尚未使用，本次上线没有需要整理或导入的历史资料及单据。系统仍保留单机自治能力；若将来有单机资料接入，人工分析合并，不开发自动匹配或合并，具体切换和历史单据处理另行确定。
- 首次正式使用前由本厂管理员完成厂区绑定并成功获取完整总部资料；失败不切换到云端资料模式。首次同步成功后，断互联网仍可独立办理本厂正常业务。
- 厂区编码跨厂唯一；地磅编码在本厂唯一、默认 `WB01`，二者用于跨系统识别地磅。本地允许更正编码；云端绑定后如何修改、关联旧单及保持双方契约一致尚待两端共同确定，不能推定云端已支持。云端应检查厂区绑定冲突。厂端使用独立接入凭据，云端核验凭据与厂区的绑定；凭据发放、轮换及具体技术形式待设计。云端内部数据库主键不能替代跨系统业务编码。

## 总部资料下发

- 总部维护物料分类、物料、往来主体及联系人，下发所有厂；本厂接入后资料只通过同步更新，账号与授权仍由本厂管理。总部资料维护权限现阶段不讨论。
- 本地 Server 每小时自动拉取一次全部资料，操作员也可主动同步全部资料；主动同步不触发单据上传。完整下载并校验成功后整体生效，失败保留上一版，不产生部分更新；本地继续使用上次成功资料。资料列表不显示逐条同步状态。
- 总部物料、主体、分类编码分别使用 `C-M-0001`、`C-P-0001`、`C-C-0001` 形式；同类型流水号持续递增、至少四位且超过 9999 自动扩展。联系人随主体同步，稳定标识方式待设计。具体资料字段、约束和停用规则以本地业务规格为准。
- 总部分类停用后新物料不可选择该分类，已有物料和历史单据保留关联；本地收到物料或主体停用后，新任务不得选择该资料，已首磅任务按原快照完成回磅。重新启用沿用原编码。离线期间使用上次成功同步的状态；资料更新不改写业务快照。缺少资料又无法同步时的临时录入不在范围内。

## 过磅单上送与确认

- 本地正式单据是权威依据，云端仅接收已出单数据供总部查询统计；待回磅任务留在本厂，云端不提供修改、作废或重开本厂单据的业务操作。
- 上送纸单信息、原始及最终重量、人工调整前后值和差额、来源、备注、调整人和时间、司机姓名及电话、联系人及联系电话、物料和供收方编码及名称快照；缺失值保留本地事实。重量统一为吨、精确至 0.001 吨，差额为原始值减最终值。具体字段及例外以本地有效业务规格为准。
- 照片、待回磅任务、打印状态、打印尝试、补打次数及原因留在本厂；单据不上送承运方编码及名称、重称及资料纠错过程或被替代称重记录。承运方基础资料仍由总部统一维护和下发。
- 出单新增云端对应单据；作废更新原单状态、原因、操作人和时间，不覆盖其业务和重量快照；重开以新单号新增并关联原单。同一单据的变化按顺序处理，较早状态不得覆盖较晚状态。重开上传等待原单创建及作废均获云端确认，前序失败时后续等待。
- 出单、作废和重开与相应待上传变化在本地同一数据库事务中保存；后台尽快上传，断网或失败保留并自动重试，不阻塞本地业务。变化使用稳定标识；云端保存并确认后本地才标记完成。未知结果使用原变化标识重试，云端识别重复并返回原确认结果，防止重复单据和变化。
- 本地单据列表按最新变化显示待同步、已同步或同步失败；失败仍自动重试，不提供单据手动重试。管理员可在同步日志查看自动及主动资料同步与单据上传尝试，按时间、类型、结果筛选；日志手动清空不删除待上传变化或改变单据状态，不自动清理。

## 云端查询与统计

- 总部人员可查询所有厂，不按厂区限制查询范围；厂区人员在本地查询。云端页面提示数据可能尚未同步。
- 只统计云端已收到且当前有效的单据，作废单不计，重开后只计有效新单；按最终净重汇总，可区分入厂卸货和出厂装货。按单据保留的原资料编码统计，不自动合并不同编码。
- 接受断网补传带来的统计滞后；原单作废获确认到重开单获确认之间可能暂时少计。不得把云端当前结果解释为各厂已实时完整上报。

## 实施前需细化

字段清单及可空规则、完整资料集的一致性与分页、联系人标识、接口版本及错误响应、凭据发放和撤销、重试和重复变化处理等仍需设计。总部资料维护权限现阶段不讨论；旧备份恢复后流水号倒退的正式处理仍暂缓，不在本契约中决定。

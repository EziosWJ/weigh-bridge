## What to build

ADMIN 在原生和 Docker 部署中逐卡查看宿主机 NVIDIA GPU 型号、利用率、显存、温度、功耗及趋势。没有 GPU、驱动缺失、单个字段不支持与采集失败明确区分，其他资源继续工作。

## Acceptance criteria

- [ ] 原生与宿主机采集进程共用 GPU 指标语义，采集依赖在边界隔离，新增库/工具说明真实用途及驱动前提。
- [ ] 支持多卡分别展示型号、利用率、显存、温度与功耗，使用能稳定区分设备的身份关联历史。
- [ ] 支持选择 GPU 查看最近 30 分钟可用指标趋势，缺口与过期遵循公共契约。
- [ ] 区分无设备、非正式支持厂商、驱动/工具缺失、字段不支持、采集失败；不可用字段不填零。
- [ ] 单卡或单字段失败不阻止其他 GPU 和其他资源返回；外部采集限时，不重叠运行。
- [ ] 高 GPU 利用率本身不触发资源异常提示，展示支持的设备状态与错误信息。
- [ ] 通过真实 HTTP 路由的可控采集输入验证多卡、部分字段缺失、驱动失败、超时和过期；Playwright 验证设备切换与降级展示。
- [ ] NVIDIA 真机记录型号、驱动版本、支持字段及真实观察结果，覆盖所声明的多卡与部署能力；模拟验证不替代硬件验证。
- [ ] 没有硬件时如实记录尚未验证的项，不宣称 GPU 验收通过或将整项关闭为已完成。
- [ ] 后端检查、前端 lint/build 通过，API 与 GPU 驱动/采集进程部署说明同步。

# AI 开发执行约定

## 自主推进与范围

用户明确启动开发后，按[当前规格](../requirements/standalone-site-spec.md)、[实际状态](../next.md)及任务依赖连续完成实现、相关验证和必要文档更新。阶段内任务不是审批关卡；普通实现选择、现有组件复用及可逆修改自主执行。

改变业务范围、仓库和已确认结论无法解决的关键业务选择，或未获授权的不可逆操作才请求用户决定；沿用已有授权。提交、推送及远程发布遵守本次授权。历史文档中的启动指令不产生新授权。

## 实现与验证

采用满足当前验收的简单方案，复用现有模块、依赖、权限及错误处理，在实际业务入口验证规则；按具体风险增加防护，避免无需求的通用框架。代码新增必要行为测试，不为可逆低影响展示修改或实现细节单独造测试。

| 改动 | 必要检查 |
| --- | --- |
| 纯文档 | 差异、引用、链接及条款一致性；不运行前后端构建 |
| Go／Web／数据库／工程发布 | 按[根指导](../../CLAUDE.md)运行对应入口及受影响行为测试 |
| 页面集成 | 受影响路径做简短冒烟；菜单、路由等公共入口改变时再加相关专项检查 |
| 设备 | 软件可用独立 mock、虚拟串口及模拟 RTSP；真实设备和纸面效果单独现场验收 |

围绕公开行为覆盖双方向称重、非法状态、重复确认、重称／作废／重开证据及有效单唯一性；按改动选场景，不要求每条 AC 都有独立端到端测试。同一流程可覆盖多个结果，已有等价检查通过后不重复执行，出现新变更或失败再补相关验证。

数据库测试使用隔离临时 PostgreSQL，不连接真实业务库。服务有超时并清理；失败、未运行及现场限制如实记录，不删除测试、跳过配置检查或禁用 CI 来达成通过。历史 Phase 2A 模拟不作为当前正式业务或真实设备验收依据。

# AI 开发执行约定

## 自主推进

用户明确启动开发后，按[当前开发基线](../development-baseline.md)中的有效 Spec 和阶段依赖持续完成任务、相关验证与必要文档更新；阶段内各任务不是新的审批关卡。普通文件编辑、命名、现有组件复用、局部重构和相关测试由 Agent 自主决定。

只有需要改变业务范围、出现无法从仓库或已确认结论解决的关键业务选择，或需要执行尚未授权的不可逆操作时，才请求用户决定。沿用已有授权；提交、推送和远程发布遵守本次任务的授权范围。用户明确要求等待时，先完成已授权的准备工作再等待。

## 简单实现与实际风险

优先采用满足当前验收条件的最小实现，复用现有模块、组件、状态和依赖。校验放在实际业务入口，处理已知输入错误和明确的失败状态；有具体问题再扩展防护，不基于假设攻击或未来规模增加通用安全框架、审批流程和层层兜底。

以下 Phase 2A 说明仅适用于历史模拟功能的维护，不是当前本厂自治开发范围。Phase 2A 是浏览器内的模拟功能：用本地状态表达任务占用、岗位切换、断网和结果不明等场景。保留约定的业务检查与历史记录，不为这些演示实现分布式锁、生产权限引擎、离线补传系统或真实设备容错。现有登录、JWT 与真实权限契约保持原样。

正式称重的人工确认、设备重量和对应抓拍要求继续有效。软件阶段可用独立 mock 验证；真实设备闭环必须单独现场验收，不能用历史前端模拟结果替代。

## 最小必要验证

| 改动 | 验证方式 |
| --- | --- |
| 纯文档 | 差异检查；涉及链接或任务编号时核对对应内容，不运行前后端构建 |
| Phase 2A 前端业务 | 根指导规定的前端 lint、build，加一个轻量的核心行为测试入口；页面集成做简短冒烟检查 |
| 其他代码或基础设施 | 按根指导选择受影响模块的检查；相关失败或新增风险出现后再扩大验证 |

Phase 2A 的自动化优先覆盖两种运输方向的毛皮净重、非法状态转换、重复确认，以及重称／作废／重开保留记录和有效单唯一性。直接通过业务模块的公开行为验证即可，测试可以构造输入状态；不要求所有数据都经浏览器表单逐步创建。

浏览器冒烟用于确认主流程可操作、刷新保留与重置、预览和导出等页面集成。可以交互检查，也可复用现有 Playwright 做少量场景；不要求每条 AC 对应独立端到端测试。同一条演示流程可覆盖多个验收条件，剩余交互按清单简短核对。

复用现有测试工具和启动方式，不新增多层测试框架或另建完整后端模拟平台。菜单、侧栏、路由等既有专项测试只在相关公共行为被改动或出现回归迹象时运行，不因新增普通业务页面默认全跑。

相关检查通过后继续推进，不在每个任务结束时重复全量检查；后续变更影响已验证内容时再补跑相应项。不为测试数字、覆盖率或形式完整性重复测试同一规则，不为可逆低影响的展示修改单独造测试。

必要的业务行为测试与项目规定检查仍须完成；不得通过删除已有测试、禁用 CI、跳过配置检查或隐瞒失败规避问题。确实无法运行的检查如实记录原因与实际验证结果，继续完成不受影响的工作，不将未验证项标为通过。开发服务和浏览器用后清理。

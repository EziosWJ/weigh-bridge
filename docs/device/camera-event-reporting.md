# 摄像头主动上报接入与现场验证

本厂 Server 的 `POST /api/v1/event/pull` 供设备使用，不要求用户 JWT；必须通过防火墙或网关仅允许本厂可信设备网段访问，禁止直接暴露公网。可选环境变量 `WEIGHBRIDGE_CAMERA_EVENT_ALLOWED_IPS` 以逗号分隔允许的直接连接 IP，配置后只接受这些来源，不信任转发头；部署在反向代理后应结合代理自身的网络限制。未配置时由网络规则限制。设备身份按管理员在摄像头管理页绑定的序列号匹配；序列号本身不是认证凭据。管理与诊断接口仍需摄像头权限。HTTPS 由现场已有 TLS 终止或 Server 部署方式提供，设备配置的地址、端口、路径须与实际入口一致。

升级前备份数据库；显式执行 schema 迁移 `00032_camera_events.sql`，该迁移不支持直接回退，需恢复升级前备份。然后在摄像头管理中打开“上报”，填写设备实际序列号、勾选启用，按设备心跳周期设置离线阈值（建议三倍）。保留原 RTSP 配置；不修改 Agent。服务重启后持久状态保留，状态根据 Server 接收时间计算；未收到心跳显示未知，超过阈值显示离线。设备自报时间和 IP 仅用于诊断。

请求上限 15 MiB，并发上限 8；处理限时 30 秒，HTTP 读取超时沿用 Server 配置。现场观察到请求 15,216 至 263,743 字节；限额是软件侧保守值，现场仍须持续核对真实报文大小、带宽和内存。超限返回 413，不作成功 ACK。上报的图像字段不解析、不保存，也不写日志或数据库；是否带图不影响车牌接收。

`CarLicenseSnapshot` 在绑定摄像头与完整请求 SHA-256 上去重；记录请求事件号（原 JSON 标量）、设备时间、Server 接收时间、车牌原值及规范值和指定识别属性。设备识别不到号码时保留空车牌记录并标示“未识别车牌”，避免重传堵塞后续事件。数据库事务成功后返回 `CarLicenseSnapshot-Ack`，响应字段为 `info.eventID`；失败不返回成功 ACK，相同报文重传可恢复。对未处理过的事件，按 Server 接收时间减 `info.time` 判断：超过配置的有效期的旧事件不保存车牌记录，在验证设备已启用且绑定后仍返回同一成功 ACK，避免堵塞设备补传；有效期在配置管理维护，默认 5 分钟，范围 1–10080 分钟，保存后立即生效；恰好等于有效期不丢弃。缺失或无效配置回退 5 分钟，数据库读取失败不成功应答。已保存的历史记录不删除，重复已保存事件仍应答。无效时间不成功应答；该判断依赖设备时钟与 Server 同步，时间在未来不会被视为过期，现场须核对两端时钟。车牌记录不受诊断 100 条限制，管理页以摄像头管理权限展示最近 50 条；本期没有自动到期，管理员应监控数据库容量。schema 的图片长度列为先前现场迁移保留字段，新记录均为 0，不表示保存了图片。

未知事件仍只记录去值结构和摘要，最多 100 条并返回 503；心跳行为不变。脱敏合成示例见 [fixture](fixtures/car-license-snapshot.synthetic.json)，其中车牌和图片占位均为合成数据，不是现场抓包。

升级前按[部署说明](local-deployment.md)核对并备份数据库、图片和配置，先在备份副本验证迁移，再显式执行 schema `00033_camera_license_snapshots.sql`、`00034_plate_confirmations.sql` 与 seed `00023_camera_event_max_age.sql`；不得直接回退删除业务记录。保留原 RTSP 配置及心跳策略。部署后查看 `/health` 和 `/ready`，通过摄像头管理的“上报”核对绑定及最近记录。现场触发识别，记录请求字节数、处理耗时、HTTP 状态及同摘要的重复投递时间；确认 HTTP 200、`eventID` 与原事件号一致、车牌记录已保存，持续观察同事件每秒重传停止或显著收敛。不要记录完整车牌或 Base64。确认后按现场安排恢复接单；失败保留脱敏摘要、大小及错误类别并核查设备协议和网络。模拟成功不能代替真机验收。

## 心跳策略现场测试（2026-10-29）

根据厂家心跳响应表，设置环境变量 `WEIGHBRIDGE_CAMERA_HEARTBEAT_STRATEGY=1` 后，在心跳应答 `info.strategy` 下发完整字段：心跳 30 秒、车牌抓拍开启、其他事件开关关闭；客流统计间隔按厂家示例设为 2 小时。默认未设置时不下发策略。关闭开关并重启 Server 可恢复不带策略的应答，但设备是否恢复原周期须实测，不能假定省略策略会撤销已应用配置。

现场 14:14:20、14:14:50、14:15:20 连续收到 HTTP 200 心跳，观察到周期约 30 秒；14:19:44 实际车辆识别后，Server 接收 `CarLicenseSnapshot`，事件 ID 66；诊断记录含车牌属性及抓拍图、背景图字段结构，值均脱敏。Server 按当前未确认 ACK 的设计返回 503，设备以约一秒间隔重复上报，同一事件的请求摘要相同。未保存车牌和图片；字段含义、完整载荷及厂家非心跳 ACK 仍待核实。

## 车牌事件现场联调（2026-10-29）

现场已部署 schema 33 和本次 Server，备份及副本验证见[当前状态](../next.md)。先前观察到 15,216 字节的重传报文，车牌图 10,753 字节、160×64，背景图宽高和图片长度均为 0；初版要求双图，因背景为空返回 HTTP 400、持续重传。用户随后明确只需要车牌号，软件调整为忽略图片并独立保存车牌。仅车牌号版本部署后设备收到 HTTP 200，抓到的 ACK 使用 `eventID=90`；原重传摘要成功后至少 60 秒未再次出现。未识别车牌事件也入库并应答，观察 84 秒未再次收到该摘要，设备随后补送其他历史事件，之后约每 10 秒产生不同摘要的新事件；车牌号码与实车是否一致及长期稳定性待核对。

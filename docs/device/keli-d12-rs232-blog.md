# 从“收不到一个字节”到读取稳定状态：柯力 D12 的 RS232 联调记录

日期：2026-10-22。

本文是面向技术博客的实验整理稿。主机别名、账号均使用示例；不包含现场地址、设备出厂编号或密码。实验范围是串口链路、报文读取及一次小轿车带载采集。本文写作时尚未接入业务 Agent；2026-10-22 后续已完成驱动集成、软件测试及零值／故障恢复现场验证，但不改变本文的实验结论与未覆盖范围，见[交付记录](../requirements/d12-agent-integration-delivery.md)。

## 1. 目标与最终结果

现场设备是宁波柯力 D12 电子称重仪表，接收端是运行 Linux 的 HP ProDesk 400 G2 Mini。我们希望得到实时重量，并知道仪表是否已经判定重量稳定。

最终采用以下连接：

```text
D12 的 9 针 PC 接口
        │
        │ DB9 母对母直通线
        │ 2↔2、3↔3、5↔5
        ▼
Linux 工控机内置串口 /dev/ttyS0
```

更换直通线后，先读通 `tF=00` 的毛重报文，再切换到 `tF=05`，读到了重量、皮重和状态字。初次用零值验证格式；随后录制了一次小轿车上磅过程，共 868 帧，并由现场人员确认主要稳定重量为 1.55 吨和 1.48 吨。

这次带载数据支持了本机的 CKS 累加规则，也暴露出单位标志与文档不一致的问题：数值实际以吨表达，不能按文档字面当成 kg 再除以 1000。跨固件适用性、负值、非零皮重及完整故障恢复仍未验证。

## 2. 先确认哪个设备节点是真串口

一开始，机器上有 `/dev/ttyS0` 到 `/dev/ttyS31` 一长串节点，没有 `ttyUSB*`、`ttyACM*` 或 `/dev/serial/by-id/` 链接。节点数量并不等于物理串口数量。

```bash
ls -l /dev/ttyS* /dev/ttyUSB* /dev/ttyACM* 2>/dev/null
ls -l /dev/serial/by-id/ /dev/serial/by-path/ 2>/dev/null

for p in /sys/class/tty/ttyS*; do
  uart_type=$(cat "$p/type" 2>/dev/null)
  if [ -n "$uart_type" ] && [ "$uart_type" != 0 ]; then
    echo "$p type=$uart_type"
    readlink -f "$p/device"
  fi
done

journalctl -k -b --no-pager -g 'ttyS|ttyUSB|ttyACM|8250'
```

这台机器只有 `ttyS0` 的 UART 类型非零；内核日志进一步确认：

```text
ttyS0 at I/O 0x3f8 (irq = 4, base_baud = 115200) is a 16550A
```

其中 `base_baud` 是驱动信息，不是当前需要配置的通信波特率。实际收数使用 9600。

## 3. 权限通过以后，还要切到原始模式

串口节点属于 `root:dialout`，权限为 `660`。SSH 用户不在 `dialout` 组，第一次打开设备直接得到 `Permission denied`。

临时调试可以由管理员给实际操作账号增加 ACL。下面的 `operator` 是示例账号，需要替换：

```bash
getfacl -p /dev/ttyS0
sudo setfacl -m u:operator:rw /dev/ttyS0
```

本次重启后临时 ACL 曾失效，需要重新授权。长期运行应为实际服务账号配置串口访问权限，并核对服务进程的有效组；这项持久化配置不属于本次已完成实验。

原有串口还开启了规范输入模式和回显。读取设备报文时，应使用 raw 模式，关闭软件及硬件流控，否则程序可能等待换行，或把接收的数据回显到仪表。调试程序还应独占串口、设定超时，并在退出时恢复原配置。

本次后续读取均不向仪表发送数据。只有核对默认指令模式时，短暂尝试过地址 1 的只读毛重请求，未发送置零、去皮或参数修改命令。

## 4. 参数一致，却仍然收到 0 字节

初期尝试了多档波特率，以及无校验、奇校验和偶校验，结果始终是零字节。随后通过仪表面板确认实际参数：

| 参数 | 当时的值 |
| --- | --- |
| `Adr` | 1 |
| `bt` | 9600 |
| `tF` | 00 |
| `Jn` | none |
| `bit` | 8 |
| `CyC` | 200 ms |

对应电脑配置为 **9600、8N1、无流控**。`tF=00` 是连续输出毛重模式，无需电脑轮询；`Adr` 不参与这种连续报文。设置完成后，仪表需要回到正常重量显示画面。

参数确认后，连续监听 25 秒仍得到：

```text
total_bytes=0
UART rx 增量=0
UART frame/parity 错误增量=0
```

这时连 UART 接收计数都没有增长，应优先检查物理链路和实际端口，而不是继续修改解析代码。零错误计数在没有收到字节时，也不能证明链路正常。

面板还有一个容易混淆的地方：现场出现的是 `S-CodE` 操作密码提示，而通信说明的设置示例是 `C-CodE` 标定密码提示。应按实际屏幕识别入口，密码由现场人员管理，不能把两种提示混为一谈。接线照片也要确认拍摄时点，旧照片不能证明当前连接状态。

## 5. “TX 接 RX”与“直通、交叉”是两层概念

关键线索来自线缆：最初工控机与仪表之间使用的是**母对母交叉线**。

柯力官方针脚图中，D12 的 PC 接口定义为：

| 针脚 | D12 的信号方向 |
| --- | --- |
| 2 | TXD，仪表发送 |
| 3 | RXD，仪表接收 |
| 5 | GND |

标准电脑串口是 2 脚接收、3 脚发送。因此电脑与 D12 使用 **2↔2、3↔3 的直通线**，已经实现了 TX 接 RX。加上交叉线，反而会把发送端接到发送端。

USB 转 RS232 又引入了另一种情况。现场那根转换线是母头，随附说明书把母头定义为 **2=TX、3=RX、5=GND**。按这份定义，它与 D12 直接对插时也是 TX 对 TX，需要交换 2、3 脚。这个结论限定于该转换器的信号定义，不能推广为“所有母头都如此”。

| 本次涉及的组合 | 对应接法 |
| --- | --- |
| 电脑标准内置串口 → D12 | 母对母直通线 |
| 该 USB 转 RS232 母头 → 电脑标准串口 | 直接连接 |
| 该 USB 转 RS232 母头 → D12 | 交换 2、3 脚，5 脚相连；该组合尚未实测 |

判断接法要同时看针脚编号、设备自身信号方向和整条线的连通关系。公母外形只决定能否插合，不能单独决定串口角色。数针脚时也要以连接器标号为准，公母正视图及焊接面可能镜像。

## 6. 用两台电脑先证明串口可以双向通信

在拿到直通线之前，我们先让一台电脑的 USB 转 RS232 母头直接连接工控机内置串口，两端均设为 9600、8N1、无流控。

发送端发出：

```text
TEST123
```

工控机读到完全一致的 7 个字节：

```text
54 45 53 54 31 32 33
```

随后反向从工控机发送三次 `FCC_TEST123\r\n`，每次间隔 1 秒。硬件发送计数增加 39 字节，另一台电脑也确认收到。

这一步证明该转换线与工控机串口能够双向收发，也说明当时选择的 `/dev/ttyS0` 和 9600、8N1 配置有效。它尚不能证明 D12 的输出电路和带载称重结果正常。

## 7. 更换直通线，先读通 tF=00

断电更换接线，重新开机，并确认仪表回到重量显示画面后，连续读到 15 帧：

```text
02 2b 30 30 30 30 30 30 33 31 38 03
```

按字段拆开：

```text
02 | + | 000000 | 3 | 18 | 03
起始  符号  六位数值  小数位  校验  结束
```

小数位为 3，得到 `+0.000`。`18` 是两个 ASCII 十六进制字符，对应符号、六位数字和小数位字符逐字节异或得到的 `0x18`。

这次收到 180 字节，15 帧异或校验全部通过，平均帧间隔约 **200.1 ms**，没有新增 UART 帧错误、奇偶校验错误或溢出。

不过，`tF=00` **没有稳定状态字段，也没有单位字段**。连续多帧数值一样，不能代替仪表自己的稳定判定；校验通过也只表明报文符合该校验规则。

## 8. 切到 tF=05，读到仪表状态字

为了取得稳定状态，现场把仪表通信方式改为 `tF=05`，其余参数保持不变，再回到正常重量画面。

这次收到的是 18 字节报文，连续采到 15 帧：

```text
02 2d 30 20 30 30 30 30 30 30 30 30 30 30 30 30 0d bf
```

| 字段 | 样本内容 | 解释 |
| --- | --- | --- |
| 起始符 | `02` | STX |
| 状态字 A | `2d` | 小数位置编码为 5，对应三位小数 |
| 状态字 B | `30` | 毛重、正值、动态位为 0、kg 单位标志为 1 |
| 状态字 C | `20` | 打印命令位与扩展显示位未置位 |
| 显示重量 | `30` × 6 | ASCII `000000` |
| 皮重 | `30` × 6 | ASCII `000000` |
| 回车 | `0d` | CR |
| 校验字段 | `bf` | 本批次观测到的 CKS |

状态字 B 的 bit 3 表示动态：1 为动态，0 为非动态。当时按文档字面把零值解释为 **重量 0.000 kg、皮重 0.000 kg、仪表判定稳定**；超载／低于零异常位未置位。零值无法证明单位解释正确，后续带载对照确认本机实际使用吨，见下一节。

这里还发现一个需要继续验证的细节：`0xbf` 恰好等于从 STX 到皮重末字节的累加低 8 位，即：

```python
candidate_cks = sum(frame[:16]) & 0xff  # 不包含 CR 和 CKS
```

在只有这 15 帧时，它只能算**候选规则**，因为内容完全相同，不能据此排除其他算法。柯力这份说明只标明 CKS，没有写出计算公式；梅特勒官方连续输出资料则描述了包含 STX、CR 的累加补码规则。不能仅因“兼容托利多”就假设算法完全相同，更不能把当前样本宣布为该标准算法校验通过。

为继续辨识算法和单位，我们随后录制了真实上磅过程。超载等异常路径仍可先用构造报文测试解析器，无需人为制造危险工况。

## 9. 小轿车上磅：868 帧验证与单位修正

15:30:08～15:33:02（UTC+08:00）录制约 174 秒，保存了原始二进制、每次接收片段及时间、逐帧记录和停止摘要。采集进程只接收，不向仪表发送任何字节，结束后恢复配置并释放串口。

| 统计项 | 结果 |
| --- | --- |
| 字节／帧数 | 15,624 字节／868 帧，每帧 18 字节 |
| 不同数值／不同整帧 | 52／61 |
| 稳定／动态帧 | 787／81 |
| 非零帧 | 409，其中稳定帧 332 |
| 动态位切换 | 12 次，包含动态→稳定和稳定→动态 |
| 帧间隔 | 平均 200.108 ms，范围约 199.451～200.618 ms |
| 丢弃字节、UART 帧错误／校验错误／溢出增量 | 均为 0 |
| CKS 匹配 | `sum(frame[:16]) & 0xff` 匹配 868／868 |

原始接收片段拼接、解析整帧拼接，两者分别与原始二进制完全一致。此次覆盖零值、不同正值毛重及两种动态状态；包含 CR 的累加和、包含 CR 的 7／8 位补码规则均为 0／868 匹配。上述不含 CR 的累加规则因此可作为**本机本次已验证的解析基线**，不扩展声称适用于其他固件、负值、非零皮重或净重。

同一数值 1.560 的两条实测报文：

```text
稳定：02 2d 30 20 30 30 31 35 36 30 30 30 30 30 30 30 0d cb
动态：02 2d 38 20 30 30 31 35 36 30 30 30 30 30 30 30 0d d3
```

B 从 `0x30` 变为 `0x38`，动态位相差 8，CKS 也由 `0xcb` 增加为 `0xd3`。稳定台阶主要为 1.550 和 1.480，现场人员确认它们实际表示 **1.55 吨、1.48 吨**，测试车辆是小轿车，峰值解码数值为 1.560 吨。

但这批报文的 B bit 4 全部为 1，文档却把它定义成 kg 标志。现场对照说明：**本机实际单位应采用确认过的吨，不能机械按该标志把 1.550 当成 kg，再换算为 0.00155 吨。** 接入配置需要显式记录现场确认单位，同时保留原始状态位及差异说明，不按“数值看起来像汽车重量”自动猜单位。其他仪表仍需单独对照。

12 次状态位切换已捕获；尚未与面板稳定灯逐时核对。此次也没有覆盖断线恢复或长期运行，不能据此宣布完整设备验收。

## 10. 一个可复用的短时接收方式

下面只展示传输层接收与清理，不包含业务解析或 CKS 通过判定。它使用 Python 标准库，不安装串口依赖，在工控机上执行即可。接收前确认实际服务没有占用同一串口。

```python
import fcntl
import os
import select
import signal
import termios
import time
import tty

def stop(signum, frame):
    raise SystemExit("stopped")

signal.signal(signal.SIGTERM, stop)
signal.signal(signal.SIGINT, stop)

fd = os.open("/dev/ttyS0", os.O_RDWR | os.O_NOCTTY | os.O_NONBLOCK)
original = termios.tcgetattr(fd)
try:
    fcntl.ioctl(fd, termios.TIOCEXCL)
    tty.setraw(fd, termios.TCSANOW)
    attrs = termios.tcgetattr(fd)
    attrs[2] |= termios.CLOCAL | termios.CREAD
    attrs[2] &= ~(termios.PARENB | termios.PARODD
                  | termios.CSTOPB | termios.CRTSCTS)
    attrs[4] = attrs[5] = termios.B9600
    termios.tcsetattr(fd, termios.TCSANOW, attrs)

    deadline = time.monotonic() + 10
    while time.monotonic() < deadline:
        remaining = max(0, deadline - time.monotonic())
        if select.select([fd], [], [], remaining)[0]:
            data = os.read(fd, 4096)
            if not data:  # EOF：结束，避免断线后空转
                break
            print(data.hex(" "), repr(data), flush=True)
finally:
    try:
        termios.tcsetattr(fd, termios.TCSANOW, original)
    finally:
        os.close(fd)
```

一次 `read()` 不等于一帧。本次同一条 18 字节报文曾被拆成 8、8、2 字节到达，接收程序必须累计字节后按协议重组；也应处理多帧粘在一次读取里的情况。

## 11. 实验结论与接入边界

本次已验证设备节点、USB 与工控机的双向串口通信、D12 通过直通线向工控机连续发送，以及两种报文的字段读取。`tF=00` 的异或校验已通过；`tF=05` 经一次带载录制，验证本机 868 帧的累加校验并捕获动态状态变化，现场确认非零读数按吨解释。

串口读通只是设备接入的第一步。单位配置、状态与面板逐时对照、断线恢复、校验失败处理，以及接入 Agent 后的新鲜度和人工确认流程，仍需要分别实现与验收。不能把一次带载抓包当成已完成正式称重，也不能用打印成功或 WebSocket 在线替代设备状态。

配图可选：仪表前面板、标有 PC 接口的后面板、直通与交叉接线图、双向字符测试和十六进制抓包。发布实物照片前遮挡现场地址、设备编号及其他可识别信息。

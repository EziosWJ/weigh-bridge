# 每厂独立自治，中心暂缓，统一本地产品与维护入口

> **效力：历史决策，已被 [ADR 0028](../../adr/0028-single-local-runtime-identity.md) 替代。** 本文关于双运行模式、旧初始化和旧数据转换的内容不再适用于当前架构；旧事实保留。业务、设备和维护原则仅按开发基线索引确认仍有效的条款复用。

2026-10-22，用户接受架构收缩并授权收敛当前开发基线。两个厂区各一台地磅，业务服务与设备 Agent 已确定同机部署；当前优先形成现场可用的生产闭环。此前中心统一账号、资料和配置的方案使本地启用仍依赖中心，并增加同步与维护入口。现决定每厂独立初始化、管理和运行，中心退出本期交付范围。

## 决策

- 每厂工控机部署三个核心服务：本地业务服务（内嵌构建后的 Web）、设备服务（现有 Agent）、PostgreSQL。两个自研进程与一个数据库服务组成一套产品；不运行生产 Vite 服务，不另建中心实例。CUPS 属于打印系统配套，migration、备份和开发 mock 不计为常驻业务服务；host-collector 不作为三服务部署的必需项。
- 本厂业务服务是账号授权、密码、物料、往来主体、厂区／地磅配置、称重、单据和业务审计的权威。维护权限继续由现有 RBAC 控制，普通操作员不会自动获得完整资料或账号管理权限。本厂初始化、换班、密码重置和后续管理都不依赖中心下发。
- Agent 保留独立进程，负责串口、摄像头及打印等设备执行；不承担正式业务确认。沿用已有设备协议、身份校验、每磅单连接互斥和打印账本，不为减少进程数重写已验证的设备链路。
- 统一访问入口、账号、版本和安装升级流程。设备维护逐步纳入本地业务服务，复用本地权限；独立维护服务仅作过渡，整合验收完成后退出常驻部署。业务服务自身故障通过 systemd、日志等系统工具处理；新入口不得依赖已退出的维护进程。
- 两厂分别维护资料与账号，可导入同一份经确认的初始资料，但后续不自动共享。同名主体不等于同一主体。中心统一资料、临时主体中心审批、账号下发、配置提案及双向同步全部暂缓。
- 本地服务、数据库和设备链路正常时，互联网中断不阻止人工确认后的正式称重。设备重量、稳定状态、对应抓拍、人工核对和服务端业务校验仍为必要条件。设备故障和本地服务故障继续按原规则处理。

## 替代关系

本 ADR 部分替代 ADR 0021：保留本地业务权威、独立数据、互联网断开可运行、编号及快照原则；替代中心管理权和首次下发依赖，暂缓同步与跨厂汇总的当前验收要求。部分替代 ADR 0018 的共享资料、集中部署和跨厂统一入口前提，保留厂区归属、同厂两次称重及权限隔离。

本 ADR 部分替代 ADR 0016／0017 的长期独立维护服务、维护账号和页面方案，以及 ADR 0020 的中心归属管理和同机常规手动下载导入流程；保留配置来源清晰、明确应用、现场参数及账本保护、停用条件和操作结果核实。原维护 HTTP 取舍仅适用于过渡维护服务，不自动扩大为业务系统的网络安全规则。

ADR 0013／0014 的证据与更正规则、ADR 0015 的设备模拟归属、ADR 0019 的设备互斥、ADR 0022 的 D12 驱动决策继续有效。旧文档中远程 Server 断网暂停的条件按本 ADR 区分互联网与本地链路。

## 取舍与未来条件

选择两个自研进程，保留设备独立重启和现有协议测试的价值，接受少量本机通信配置；不采用将业务与设备全部并入一个进程的重构。统一维护后，业务服务不可用时失去网页排障入口，接受系统级工具作为恢复入口。

暂缓中心减少首期运维和资料同步成本，但暂时需要人工导出汇总，未来跨厂汇总需处理资料映射。现在保留稳定厂区标识、跨厂不冲突的记录编号、历史快照和修改留痕。出现实际集中查询需求后另行决策，优先评估只读汇总；统一账号、资料与远程控制分别评估。已有同步代码不自动恢复为未来需求。

Server 开发、数据库集成测试与生产统一采用 PostgreSQL，见后续数据库范围决策 [ADR 0024](../../adr/0024-postgresql-only.md)。数据库、业务图片、现场身份、设备配置与打印账本按原要求保护；单盘故障保护目标保留，具体方案继续暂缓讨论。

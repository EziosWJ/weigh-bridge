# 业务一期正式称重必须具备设备重量和对应抓拍

> 2026-10-23 调整：[ADR 0027](../../adr/0027-optional-weighing-capture.md) 将抓拍改为默认强制、本厂管理员可关闭；关闭期间允许无图正式称重，保存实际状态和策略。本文无条件强制抓拍及“缺图一律阻止”的条款按此调整，其余规则保留。

> **2026-10-22 效力：业务规则继续有效，部署及阶段描述按当前基线。** 人工确认、证据及后续重量修订继续适用；旧“断网暂停”指远程依赖背景，现区分互联网与本地链路，本地正常时断互联网可办理。文中未实现描述为当时状态。当前依据见 [ADR 0023](0023-standalone-site-baseline.md)及[基线索引](../../development-baseline.md)；下文历史正文保留。

业务一期以称重准确、记录可追溯为首要目标。正式称重只接受设备采集的重量，并要求具备与本次现场称重对应的抓拍，由操作员确认且经 Server 校验后形成正式记录；已确认重量不可手改，纠正须通过符合条件的重称并保留原记录与替代关系。

这项决策选择保留完整证据，而不采用故障时由授权人员手输重量或缺图确认的备选方式。因此，采重故障或抓拍失败会阻止系统内的正式称重，现场需承担等待设备恢复的影响。设备、抓拍和业务功能均为计划，尚未实现；本决策不代表完整需求或实施方案已获批准。

来源：[业务一期需求讨论](../requirements/business-v1-discovery.md)，用户接受 Q6=A、Q7=A、Q10 和 Q12 推荐。

用户在 Q30 调整交付顺序：目前没有摄像头，先做界面功能，车牌先手填；随后在 Q32 选择 A，明确当前只进行界面与流程验证，使用模拟重量、测试单据与打印预览，不生成正式业务记录。本决策的正式称重条件继续保留，真实设备接入与正式业务验收放在后续。

后续人工扣减需求另见 [ADR 0014](../../adr/0014-manual-weight-adjustment.md)：保留本次设备测量原值，独立记录用于单据的扣减和最终重量，不将人工调整视作重称或覆盖设备证据；该调整已在前端模拟中实现并验证，正式业务仍未实现。

2026-10-18 补充（已确认、待实现）：[ADR 0014](../../adr/0014-manual-weight-adjustment.md) 扩展为最终重量双向调整及操作员直接处置。已保留设备依据的单据可由操作员更正最终值，保留人工来源及备注；客户确认调整原因选填，默认“磅精度调整”。实际重称仍需新采集及对应抓拍，且只替代指定磅并保留旧记录。人工更正不能充当新的正式称重采集，也不允许断网办理正式确认。隔日回磅、作废及重开无需审核，原始值、时间、图片及各版单据始终可追溯，不能以补充规则认定真实设备或正式业务已实现。

# Issue #4：本地业务权威与同步实现

> **2026-10-24 效力：历史多模式设计。** `node.role=central|site`、空角色兼容、`wb_node_identity` 和数据库保留转换约束已被 ADR 0028 替代；正文仅作历史方案记录。


> **2026-10-22 效力：部分被替代，中心能力暂缓。** 本地业务权威、断互联网可运行、编号与快照继续有效；中心管理账号资料／归属及首次下发依赖被替代，双向同步、中心审批与跨厂汇总退出本期。当前依据见 [ADR 0023](../adr/0023-standalone-site-baseline.md)及[基线索引](../../development-baseline.md)；下文历史正文保留。

日期：2026-10-22。依据：[确认规格](../requirements/local-first-deployment-spec.md)。软件验证与现场边界以[交付记录](../requirements/local-first-deployment-delivery.md)为准。

## 角色及身份

同一 Server/Web 代码通过 `node.role=central|site` 装配；空角色保留原开发联调拓扑。`wb_node_identity` 在显式 Goose 迁移后绑定数据库角色和厂区，已有身份不可通过修改配置重新解释。首次绑定厂区库拒绝已有运输交易；不清空联调数据。中心与各厂使用独立数据库、JWT 密钥、文件目录及图片目录。

角色边界先于具体 API 执行，仍叠加原认证、RBAC、厂区范围。中心拒绝现场业务写入、设备连接及现场设备状态读取。厂区拒绝正式资料、系统管理及密码写入，称重查询和操作范围固定为本厂。临时主体与明确应用配置有各自权限入口。初次资料下发后，至少两名启用、具备称重确认动作权限及本厂操作授权的实名人员才能启用生产写入。正常离线不另设有效天数。

## 数据身份和单号

保留现有数字 API 主键。中心生成低位 ID；厂区主键分配在 `site_id × 2^45` 的互斥区间内，厂区 ID 限 1～255，最大值不超 JavaScript 安全整数。数据库中的单调计数器与自 2026-01-01 起的毫秒时间下界共同分配；事务内分配避免同节点并发碰撞。时钟要求在支持的纪元内，正常运行中回拨由计数器继续推进。恢复旧库前仍需校准现场时钟；本轮没有实现单盘故障恢复方案。

新任务号、单号及临时主体编码包含稳定厂区码和随机 128 位标识，不依赖恢复后的日序列。旧单号不修改，补打沿用原号，更正重开生成新号。中心内部幂等操作键增加厂区前缀，并单独保存原请求编号；中心按 `siteId` 查询原请求，避免两厂同一账号使用相同请求编号时相互冲突。PostgreSQL 新迁移扩展相关字符串长度。两厂互不等待中心分配编号。

## 同步过程

厂区每 10 秒主动向中心发起一次同步，仅需要厂区可访问中心，无需中心连接厂区端口。每厂使用独立同步凭据，由中心固定映射厂区；不使用人员 JWT 传输节点数据。首次注册配置由部署人员提供，实例身份、同步状态和待发送包持久化在本地库。协议采用既有 JSON 响应封装，网络错误或接收错误持续重试。

1. 在一致事务中读取本厂业务，比较已确认的逐行摘要。按最多 50 个变化任务组织完整关联图，另含临时主体、非任务事件及配置应用回执；封装单调版本，先保存待发送包。
2. 中心以节点身份验证主键区间、厂区、地磅及业务关联，按传输版本及任务业务版本拒绝旧数据回滚；相同业务版本内容冲突、作废单重新变有效或已核实打印退回未知均拒绝，保留已收到的事实，需按恢复流程核对。任务、采样、记录、单据版本、业务事件、幂等操作及打印尝试在同一接收事务更新。循环外键通过事务内暂时清空当前记录指针后恢复处理。
3. 中心返回本厂可见的统一资料、账号、角色、动作权限、厂区授权、临时主体处理结果和待应用配置。厂区在事务中更新；登录元数据不回传覆盖。授权或密码等安全状态变化时撤销本地旧会话，未变化的同步不使会话失效。
4. 接收完成后才确认本地包、更新逐行摘要。确认丢失会重送原包，接收去重不重建业务。同步只写数据，完全不调用采集、确认、出单或打印命令。
5. 业务提交后单独请求缺失图片，单轮最多补 8 张。中心仅接收已同步称重记录引用的图片，校验格式、大小和原始 SHA-256，再原子保存。图片积压不影响单据有效性或汇总；单据详情/列表与厂区状态分别表达完整性。

业务上行按变化任务增量追平；统一资料下行采用本厂可见快照。当前适用两个厂区的资料规模，尚无大型资料集压测结论。单包限制 64 MiB，图片限制 10 MiB；资料增长或任务证据超过当前单包上限时需扩展分页契约，错误会保留待发送包，不静默丢弃。

## 资料、临时主体及现场配置

已首磅任务正常回磅沿用任务资料快照，不重新取中心名称、规格或主体身份。主动更正仍走原纠错、作废、重开流程。正式资料停用约束新选用，删除在厂区保留必要历史引用；联系人及授权关系按当前中心快照同步。

临时主体的资料和来源状态在同一事务保存。初次 pending 仅本厂可选；returned 与 resubmitted 均禁止新选用，既有任务继续。中心按提交版本人工退回、转正式或关联既有正式主体；同名不触发自动归并。转正式生成中心正式档案，来源主体及快照保留，后续选用正式档案。汇总和筛选通过正式关联统一主体维度，不回写历史单据。

中心修改已有厂区配置形成带版本的提案，原已应用启停状态不变。提案包含本厂连接地址及 Agent 连接身份；厂区维护权限人员明确应用，复用未完成任务、未决打印和在线 Agent 的停用检查。应用回执上传后中心才更新已应用状态。同步和本地应用均不操作 Agent 的串口、摄像头、CUPS 设置或打印账本。

## 查询与运行边界

中心汇总延用有效单唯一性和作废排除规则，额外返回授权厂区更新时间，CSV 附带各行厂区最近同步时间。未更新只说明中心信息陈旧，不表示现场停产或设备故障。本地工作台和后台显示中心连接、待同步数据、图片积压及最近同步时间。

本地 Web 由工控机上的同源 Server 或本地静态服务提供；不能在生产使用远程 Vite 开发服务器。发布构建已有 `embedweb`，可将 Web 资源嵌入同一 Server 二进制。Agent 始终连接本厂 Server。真实设备驱动、现场资源核验与生产切换验收仍按原范围另行执行。

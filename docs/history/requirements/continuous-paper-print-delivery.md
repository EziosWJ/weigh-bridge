# 五联三等分连续纸打印适配交付记录

范围来自 [Issue #5](https://github.com/EziosWJ/weigh-bridge/issues/5) 及已确认方案。软件实现已完成，按用户授权合入本地 `main`；未部署到现场，纸面待验收。

## 实现范围

- 打印 Agent 和维护台支持小数毫米表长、整体缩放，并复用同一份本地配置映射用于校准样张与业务打印。
- 文字和表格统一缩放，偏移与表长保持实际毫米含义；实际宽高、分带走纸和量化表长在维护台显示，超出纸宽或表长时拒绝保存／渲染。
- 校准样张加入外框、中心定位标记和不随缩放改变物理间距的毫米标尺，包含当前参数和队列，不改变业务打印／补打计数。
- 缺少缩放的旧配置按 1 倍兼容，默认 A4 点阵与 ESC/P 输出保持既有快照；整数表长仍可读写，现有配置恢复流程保留。
- 保持一份任务、既有业务字段与打印尝试处理；继续设置表长并在末尾发送 FF，没有添加未经现场验证的设备撕纸命令。

## 验证

2026-10-22 软件验证：

- `task backend:check`：全部后端测试及 `go vet` 通过，包含小数表长保存／应用／重启读取／恢复、旧配置兼容及非法尺寸拒绝。
- `python3 -m unittest discover -s server/internal/agentprinter -p '*_test.py'`：11 项通过，覆盖默认点阵与 ESC/P 快照不变、小数表长编码精度、整幅缩放后平移、分带边界、非有限数值拒绝及标尺物理间距。
- `task agent:maintenance:smoke`：通过；使用真实 Chromium、维护服务和打印 Agent，以及隔离的 CUPS／systemd 模拟命令。浏览器保存并应用 170 mm 基准宽、1.02 倍缩放、4／1 mm 偏移和 93.13 mm 表长，校准样张生成后实际解码核对表长、图形宽度和分带数量；真实打印进程反馈与维护台有效配置一致，厂区配置导入保留本机校准参数。
- 上述 smoke 任务同时构建维护服务及 Linux amd64 打印 Agent；JavaScript 语法与差异空白检查通过。
- 人工查看生成的校准样张图像，标题、参数、测试标记、外框和毫米标尺完整。预览不代表物理尺寸已获设备验证。

测试均在独立 worktree 执行。受限环境禁止本地监听，后端及浏览器检查在获准允许监听的执行环境完成；未连接现场 CUPS／设备。SQLite 依赖编译产生既有 C 警告，检查成功。

现场走纸、撕纸位置、实际纸张尺寸和第五联效果未验证。当前状态：**软件完成、纸面待验收**。

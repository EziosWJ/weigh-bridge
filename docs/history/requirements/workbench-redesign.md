# 称重台操作与视觉改版

2026-10-18 用户确认流程并要求使用 frontend-design 改善页面。本轮扩展现有前端模拟，不包含真实视频、设备通信或正式单据。

## 已确认流程

输入车牌并匹配首磅／回磅 → 采集重量及对应模拟抓拍 → 补齐业务资料 → 一次集中核对 → 明确确认保存。首磅确认才建立任务，回磅确认同时出测试单。

- 采集前必须定位车牌；物料、供收方等资料允许采集后补齐。
- 同车补资料保留本次采集，但修改车牌、改变现场模拟条件、切换车辆仍使采集失效。核对窗口绑定当前资料，资料变化须重新打开核对；失稳、超时、断网等仍按原规则阻止确认。
- 摄像头画面支持小窗、标准、大窗及独立放大。尺寸变化不改变采集结果，图片完整呈现、不裁掉车辆。
- 集中核对同时展示车辆、业务、重量和本次图片；回磅同窗录入最终毛皮重，保留原始值、独立扣减计算、原始异常校验及固定底栏。
- 当前画面始终明确标记静态模拟，未来实时能力未实现。

## 设计方案与自检

继续使用 Form / Detail 业务变体及现有公共组件，局部设计不修改全站主题。

色彩：操作蓝 #1677FF、正文石墨 #1F2937、背景蓝灰 #F5F7FA、面板白 #FFFFFF、分隔灰 #E5E7EB、稳定绿 #16A34A，均复用现有 token。警告与错误沿用已有语义色。

字体：中文沿用 PingFang SC / Microsoft YaHei / Noto Sans SC；重量数字优先 Bahnschrift / DIN Alternate，回退 Arial，启用等宽数字。标题 24px，分区 16px，正文及操作 14px，功能性仪表数字 48px，辅助信息 12px；不引入远程字体。

布局：现场画面在左，重量及本趟资料在右，所有业务内容左对齐，重量数字右对齐。主操作固定在重量区，补资料时仍可见；窄屏按车辆栏、现场画面、重量操作、业务资料顺序自然堆叠。

```text
称重工作台                                  测试环境 / 设置
车牌 [输入] [查找当前运输]                   首磅 / 回磅
┌─ 现场画面 ─────────────┬─ 当前重量 ─────────────┐
│ 小窗 / 标准 / 大窗 / 放大 │ 稳定状态       32 吨  │
│                         │ [采集 / 核对 / 下一辆]│
│ 完整车辆画面             ├─ 本趟业务资料 ─────────┤
│                         │ 方向 / 物料 / 供收方  │
├─ 本次抓拍与采集时间 ──────┤ 补充运输信息（折叠）   │
└─────────────────────────┴──────────────────────┘
```

设计自检：舍弃最初的三个等宽卡片方案，改为围绕现场观察和称重操作的两个工作区域；重量大小服务于远距离辨认，图片尺寸服务于车辆位置核对，不增加统计卡片、装饰渐变、进场动画或自由切换流程 Tab。视觉重点仅给仪表数字和当前动作。

## 验证记录

前端模拟改版已完成，沿用原业务存储和单据规则，未新增依赖。

- `task frontend:lint`、`task frontend:build` 通过。
- `npm run test:weighing`：26 项通过，新增两方向先采集后补资料、同车保留采集、换车／失稳使采集失效的行为验证。
- `npm run test:weighing:smoke` 通过：验证资料未齐备仍可采集、缺项定位、摄像头三档尺寸／放大／焦点恢复、集中核对取消及数据变化失效、首磅与回磅出单，并保留已有预览、CSV、更正重开和缓存场景。
- `npm run test:weighing:invalid-original` 通过：原始异常不可通过最终重量绕过，扣减仍各自计算；恢复后正常出单；桌面左右布局、390px 窄屏堆叠与固定操作区通过。

- 测试服务和浏览器均由测试入口清理。截图保存在 `/tmp/weighing-workbench-compact.png`、`/tmp/weighing-adjustment-review.png`、`/tmp/weighing-workbench-mobile.png` 等本地临时路径。

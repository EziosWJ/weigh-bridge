# 多厂区与 Agent 互斥实施记录

日期：2026-10-21。用户在完成 [Q1～Q18 需求确认](multi-site-discovery.md)后明确要求“开始实施”。本文记录本次实现和实际验证，不代表真实仪表、摄像头或工控机现场升级完成。

## 实现

- 新增厂区及用户厂区授权，分别表达查询和操作范围；两厂共享基础资料，任务、单据、设备和操作按厂区归属。受影响 HTTP 入口统一解析数据库归属并校验授权，查询、汇总及导出按授权过滤；保留原请求幂等重试语义。
- Goose schema 00014、seed 00008 同步覆盖 PostgreSQL／SQLite。现有业务默认归原厂区，新增厂区配置第二台地磅；已有用户保留原厂区范围，管理员初始获得两个厂区，新用户需要显式分配。原单内容及打印账本不改写。
- 同车未完成任务约束改为厂区内唯一；采样禁止关联其他厂区任务，新单保存厂区身份及名称，精简打印抬头显示厂区；旧单从新增归属读取展示名称，不改写旧存储内容。列表新增厂区列和筛选，汇总明细及 CSV 带厂区身份。
- Server 可配置多个 Agent 映射，各地磅分别持有连接、锁、设备版本和未决请求；同磅新连接获得冲突错误，不替换原连接。
- 后台厂区面板提供受独立动作权限及厂区操作授权保护的踢出操作，携带目标连接 ID，避免误踢后来建立的连接。服务端先记录踢出请求审计，再发 kick；未确认采样失效，未决打印继续人工核实。不能确认客户端退出时明确反馈。
- 真实打印 Agent 在独立接收协程处理 kick，可中断等待中的打印／维护暂停并正常退出；mock 同时停止连接运行和 HTTP 控制服务。普通网络故障仍重连，kick 不自动重连；现有 systemd `Restart=on-failure` 不拉起正常退出进程。
- 新增“厂区工作台”菜单，仅显示授权厂区；卡片进入固定地磅的独立窗口，不同地磅使用不同窗口名称，原任务定位和表单导航保留地磅参数。用户管理增加厂区授权表单，现有工作台、任务详情及打印动作使用对应厂区授权。

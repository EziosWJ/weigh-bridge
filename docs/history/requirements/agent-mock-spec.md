# Agent 接口与独立 mock 方案

> **2026-10-22 效力：设备协议与模拟职责继续有效。** 设备服务连接本厂业务服务，真实与 mock 互斥；远程 Server 部署和断互联网暂停前提被替代。软件测试不代表真实设备验收，数据库按 ADR 0024。当前依据见 [ADR 0023](../adr/0023-standalone-site-baseline.md)及[基线索引](../../development-baseline.md)；下文历史正文保留。

> 数据库范围更新（2026-10-22）：[ADR 0024](../../adr/0024-postgresql-only.md) 已取代本文的 SQLite 支持、双库迁移与兼容测试条款；当前开发和验收统一使用 PostgreSQL。其余条款按当前开发基线适用。

状态：2026-10-19 用户已通过 to-spec 授权发布后实施；[Issue #3](https://github.com/EziosWJ/weigh-bridge/issues/3) 已发布，实现及协议／SQLite／浏览器验证完成，PostgreSQL 受 Docker 环境限制。正式 Spec 见 [Issue 正文](agent-mock-issue-spec.md)，准确报文见 [协议 v1](../../../protocol/v1.md)。

## 范围与职责

- Server 统一接收 Agent 数据，负责鉴权、地磅操作会话、采集依据、人工确认、业务校验、单据及打印记录，不区分模拟／正式处理流程。
- Web 工作台显示实时重量、Agent 给出的稳定状态、设备在线／故障、车牌候选和最近图片；保留人工车牌核对、采集、确认及业务操作。
- agent-mock 是独立程序，提供独立 Web 页面并以 Agent 身份连接 Server。配置 Agent 编号、地磅编号、连接密钥和 Server 地址；本轮配置单 Agent 对应单地磅。
- mock 页面控制目标重量、车牌候选／识别失败、前后视角图片、设备故障、上磅／下磅、连接与打印回执。模拟逻辑只存在于 mock。
- 本轮不实现仪表驱动、真实识别、实时视频和物理打印。真实设备接入验收另行进行。

系统移除称重设备模拟入口及人为制造网络异常、提交结果未知的演示开关；真实连接异常和结果未知仍需正常处理。保留原系统无关模块，避免扩大重构。

## 操作流程

1. mock 页面设置目标重量、车牌和图片，点击模拟上磅。
2. mock 每 500ms 上报重量及状态，先波动 3～5 秒且 `stable=false`，随后持续上报目标重量和 `stable=true`。系统展示每次更新，不自行推断稳定。
3. 系统用户核对车牌，点击采集。Server 校验用户权限与地磅会话后，向 Agent 发出采集命令。
4. Agent 返回同一采集请求对应的当次重量、稳定／故障状态、采集时间和前后视角抓拍引用。Server 保存采集依据，沿用已有样本与任务、阶段、操作者及会话的绑定。
5. 操作员核对后确认。再次失稳、设备故障、连接中断、样本过期或业务绑定变化，使尚未确认的依据失效；稳定状态本身不会生成称重记录。稳定期间重复上报相同重量不使依据失效；重量改变则使其失效。
6. mock 点击模拟下磅后上报零重量，不稳定／不可采集。零重量仅用于现场状态，不可作为有效称重依据。

## 最小通信契约

### 连接与身份

计划入口为 `GET /api/agent/ws`。Agent 主动连接，配置密钥通过 Authorization 请求头提供，Server 校验其 Agent 与地磅映射；不借用操作员 JWT，不改动既有用户鉴权。生产使用 WSS，本地开发允许 WS。实际凭据不写入示例文件。

同一 Agent 只保留一个有效连接，替换连接时使旧连接及未确认依据失效。在线时每 5 秒心跳，连续 15 秒没有收到任何有效消息则离线；Agent 自动重连后上报当前状态，不重放离线重量或自动确认旧采集。命令只向当前连接发送。

### 消息封装

统一 JSON：`version`（首版为 1）、`type`、`messageId`、`occurredAt`、`payload`；命令与回复额外使用同一个 `requestId` 关联。消息时间使用 RFC3339；Server 另存接收时间，不能仅凭 Agent 时间判定新鲜度。重量以吨表达，精确至 0.001 吨，保留设备原值／原单位时作为附加证据。

| 方向 | type | 内容 |
| --- | --- | --- |
| Agent → Server | `device.state` | `weight`、`unit=t`、`stable`、`deviceOk`、可选故障说明；持续上报 |
| Agent → Server | `plate.observed` | 候选车牌或识别失败、发生时间；只作候选，不替代人工确认 |
| Agent → Server | `camera.updated` | 前后视角最新图片引用；只在图片更新时发送 |
| 双向 | `heartbeat` | 连接保活 |
| Server → Agent | `capture.request` | 采集请求编号；Agent 执行采集，不负责判断毛重／皮重或绑定业务任务 |
| Agent → Server | `capture.result` | 成功／失败、当次重量及稳定／故障状态、图片引用及采集时间；关联原请求 |
| Server → Agent | `print.request` | 打印尝试编号、单号及该版单据不可变内容，含现有打印所需字段 |
| Agent → Server | `print.result` | 对应打印尝试的成功／失败及说明；没有回执不代表失败或成功 |
| 双向 | `error` | 关联请求的错误码和可读说明 |

重量示例：

```json
{
  "version": 1,
  "type": "device.state",
  "messageId": "state-001",
  "occurredAt": "2026-10-19T10:00:00+08:00",
  "payload": {"weight": "32.518", "unit": "t", "stable": false, "deviceOk": true}
}
```

采集失败不得生成可确认样本；回复必须匹配当前未结束的请求，旧连接回复、重复回复和超时回复不能产生新的有效依据。初始采集超时沿用现有样本超时量级，具体配置在实现时统一，避免增加多套时限。

### 图片

图片通过同一 Agent 身份认证的 HTTP 上传入口 `/api/agent/images` 上传，返回 Server 图片编号，WSS 只传编号。Server 保存文件及采集关联，校验图片归属和必需视角，不接受任意外部 URL 作为抓拍依据。图片随既有称重依据保留，不能由普通临时文件清理误删；复用现有文件处理能力中适用的格式和大小限制。

mock 提供内置示例图和上传替换；最新预览图与确认采集的抓拍分别表达，采集结果明确绑定当次图片，不能用随后更新的预览替换历史依据。

### 打印

Server 先保存打印尝试再发送命令；mock 页面展示任务和内容，由人选择回报成功、失败或暂不回报。相同尝试编号不能重复创建任务或重复计数。

断连、超时且没有明确结果时保留结果未知，不自动重发打印；沿用现有人工核实、明确失败重试和补打规则。Agent 成功回执表达其执行结果，不将“已接收任务”当作“已打印”。

## 系统接入与清理

- 新数据不再受 `testMode`、`source=simulated` 或 `Task.Mode=test` 门控；调整测试采集路由、模拟条件版本及测试专属权限入口，用 Agent 采集替代浏览器提供重量／图片。
- 用户确认和业务操作继续沿用 JWT、RBAC、地磅会话、幂等、审计及历史版本规则；Agent 连接权限不能代替用户业务权限。
- 新单据统一走正常单据流程与编号；历史测试单号、标识、图片、原始依据和快照保留，不修改旧记录来伪装真实设备采集。
- 移除工作台设备模拟面板、浏览器生成的识别候选、演示网络开关及旧浏览器称重模拟数据路径；不删除业务规则、单据预览或历史依据展示。
- Web 通过现有业务 HTTP 入口读取 Server 保存的最新设备状态；本轮优先轻量轮询，不再增加一套浏览器长连接协议。离线、数据过期应清楚显示并禁止采集确认。
- 数据库变化新增 Goose migration，开发、测试与生产统一使用 PostgreSQL。
- 不建设设备管理后台、离线补传队列、自动离线确认或真实 Agent 的 SQLite 存储。

## 验收与实施顺序

1. 先落地 protocol 契约、Server Agent 接入和最小连接测试，再接入实时状态、图片及采集。
2. 实现独立 mock 程序与页面，验证上磅波动、稳定、失稳、下磅、故障、断连及识别候选。
3. 工作台切换到 Agent 数据，完成两磅确认、对应抓拍、重称及历史查看，移除系统内模拟生成逻辑。
4. 接入 Agent 打印命令和可控回执，验证成功、失败、结果未知及重复回执。
5. 完成受影响模块的行为测试、规定检查和简短端到端验证，更新启动说明及实际交付记录；真实设备功能不得标记为已完成。

核心验收：系统可看到 3～5 秒重量变化；不稳定无法采集；稳定后可采集并人工确认；失稳和断连使未确认依据失效；前后抓拍与本次采集绑定；重连不补办旧称重或自动重打；重复消息不产生重复依据／打印记录；系统不提供设备模拟控制；旧测试历史仍可查询。

实际实现、验证与限制见 [交付记录](agent-mock-delivery.md)。

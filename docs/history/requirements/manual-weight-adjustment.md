## 问题与交付边界

客户在实际过磅时会因地磅读数偏多，人工扣减毛重或皮重后开单。系统需要保留可查询的原始测量依据，同时准确表达最终开单重量；两种重量分别提供独立列表，避免混用。

本轮扩展现有 Phase 2A 前端模拟，验证入厂卸货与出厂装货的操作、查询、导出和打印预览。继续使用浏览器测试数据、模拟采集和测试单据，不新增业务 API、业务表、真实设备、物理打印或 WSS；正式称重的设备、抓拍、人工确认及 Server 校验条件保留。

本需求覆盖既有 Phase 2A 文档关于单一毛皮净重、单一单据列表和更正重开不得调整单据重量的相应描述；原始设备重量仍不得改写，其他已确认规则继续适用。历史交付记录保留，新增模拟能力以本轮交付记录为准。扣水、扣杂、采购销售结算及按比例调整不在本轮范围。

## 重量定义与计算

| 项目 | 规则 |
| --- | --- |
| 原始毛重、原始皮重 | 取本趟运输最新有效的对应确认称重值，保留采集依据；人工扣减不改写原记录 |
| 原始净重 | 原始毛重 − 原始皮重 |
| 毛重扣减量、皮重扣减量 | 系统只读计算：对应原始重量 − 人工录入的最终重量；未扣减显示为 0 吨；原因选填 |
| 最终毛重 | 人工录入扣减后的毛重，默认等于原始毛重 |
| 最终皮重 | 人工录入扣减后的皮重，默认等于原始皮重 |
| 最终净重 | 最终毛重 − 最终皮重，不允许独立编辑 |

毛重、皮重按业务含义确定，不以首次／二次顺序固定，也不按大小自动交换。全部业务输入、保存、计算、查询、汇总、CSV 和打印统一以吨为单位，精确至 0.001 吨。重量显示最多三位小数并省略末尾无效零，例如 5.000 吨显示为 5 吨，5.250 吨显示为 5.25 吨。最终重量最多允许三位小数，超出时提示修正，不静默截断；空白不等于零。

业务计算以 0.001 吨为最小单位，使用整数刻度或等价十进制定点方式，先确定三位小数的业务毛皮重，再计算净重和扣减；汇总累加业务净重，避免浮点尾差。设备原始报文及精度独立留存；采集或历史数据换算规则见 [调整计划](weight-entry-tonne-plan.md)，不得用显示格式覆盖测量证据。

人工录入的最终毛重、最终皮重须为有限正数，且各自不大于对应原始重量；扣减量自动反算，须为非负数；最终毛重须大于最终皮重，最终皮重与最终净重须大于零。原始重量仍须通过既有采集与业务校验，不以扣减绕过失稳、异常重量或证据要求。扣减皮重可能使最终净重增加，这是本轮已明确接受的结果。

## 办理与追溯

1. 首次称重沿用现有流程，保存原始值及称重依据。
2. 二次重量采集完成后，在同一确认界面展示只读原始毛皮净重、可编辑最终毛皮重、只读扣减量及最终净重，供操作员核对。
3. 操作员观察原始值，直接输入扣减后的最终毛重和最终皮重；系统实时反算两项扣减量和最终净重。最终毛皮重默认带入原值，不调整时无需重填；原因选填，不增加主管审批。
4. 点击“确认称重并出单”，校验通过后完成二次确认、保存扣减及最终值、生成一个测试单并完成任务。不增加“待出单”状态。
5. 保存操作人、时间、原始值、扣减量、最终值及选填原因，并与运输任务和单据关联。前端模拟必须明确操作身份，不把模拟岗位等同于已实现的正式授权。

现有失效采集、断网、提交结果不明、重试及重复确认规则继续适用；不得用核对界面停留前的失效数据出单，确认失败不得显示完成，重试不得形成重复单据或重复扣减。

出单后不可直接修改扣减或覆盖原单。主管沿用既有作废、更正重开流程，核验原称重依据仍有效后，可在新单中重新录入最终毛皮重并由系统重新计算扣减量；新单使用新单号，关联原单及原任务。原单重量、扣减、操作记录及原始称重依据保留，同一任务最多一张有效单。调整原因选填不改变既有作废、重开动作的原因要求。

重称仍是重新采集并确认重量，遵守原装载状态等既有条件；最新有效记录参与计算，被替代记录及替代关系保留在详情中。人工扣减不冒充重称，也不改写抓拍关联的测量重量。

## 两份独立列表

| 规则 | 原始称重 | 最终单据 |
| --- | --- | --- |
| 每行对象 | 一个已完成两次称重的运输任务 | 一张单据，保留有效、作废及重开版本 |
| 重量列 | 原始毛重、原始皮重、原始净重 | 最终毛重、最终皮重、最终净重 |
| 关联 | 通过任务查看关联单据与调整记录 | 通过任务查看原始称重，通过单号追溯原单和重开单 |
| 重开处理 | 不新增原始行，不改变原始重量和称重日期 | 新增新单号，原单保留作废状态 |
| 日期筛选 | 北京时间二次称重确认日期 | 北京时间出单日期 |
| CSV | 原始重量明细及原始净重汇总 | 最终重量明细及最终净重汇总 |

未扣减的业务也在两份列表中展示，原始与最终重量相同。未完成称重的任务仍在运输任务页查询。原始列表可追溯历次重称；详情保留扣减的操作人、时间、前后值及原因，不要求在两份列表中混放两组重量。

筛选沿用现有车牌、任务号、方向、物料、往来主体等业务条件；最终列表保留单号和单据状态筛选。日期区间包含起止当日，日期字段明确命名。跨天重开时，两份列表的日期筛选结果可能不同，不能把原始称重日期改成重开日期。

CSV 导出遵循各自当前筛选条件，导出全部筛选结果而非当前分页，保留任务关联、状态、单位与测试标记。岗位权限沿用现有约定，主管可导出；作废历史可查、可导出明细，不计汇总。

两份列表各自汇总对应净重，均只统计关联当前有效单据的运输业务。原始列表每任务最多计一次原始净重；最终列表仅计当前有效单的最终净重。无有效单据的任务不计汇总，作废排除，重开不重复计重。汇总仍为当前有效业务的模拟查询结果，不新增历史结账或财务报表能力。

## 打印与已有数据

打印预览只展示最终毛重、最终皮重、最终净重，不列出原始重量或扣减明细；保留测试标记、单号及原有业务字段。首次打印、失败、结果未知、补打次数及补打授权沿用现有规则，始终打印对应单据版本的最终值。

既有未扣减的模拟数据按零扣减理解，原始值沿用既有称重依据，最终值与原值一致；保留现有浏览器历史，不通过清库规避兼容。缺少历史操作人或时间时不得伪造曾发生的调整记录。刷新保留已确认的原始值、扣减、最终值及追溯关系，重置沿用当前模块范围。

| MA10 | 打印预览仅显示最终毛皮净重及原有测试标记、补打信息；刷新保留全部已确认数据，既有零扣减数据可继续查询 |

## 交付范围

- 中心/厂区独立角色与数据库身份；厂区固定本厂，中心拒绝现场称重、业务处置、打印及 Agent 接入。保留空角色开发联调兼容方式。
- 厂区独立认证、账号/角色/权限/厂区授权下发；首次下发至少两名实名且具备称重动作授权的人员后启用生产写入。安全状态变化撤销本地旧会话，普通同步不使会话失效。
- 持久化待发送包、逐行摘要、接收版本去重，厂区自动连接/重试、变化任务分批追平。上行覆盖任务、采样、记录、各版单据、业务事件、幂等操作及打印尝试；接收不执行称重、出单或打印命令。
- 业务先到、图片后补；原始 SHA-256 校验、图片积压及单据完整性展示。完整有效业务计入汇总，不等待图片；汇总与 CSV 显示厂区更新时间。
- 临时主体独立补录权限、本厂待确认选用、中心退回/转正式/关联、补充后仍待确认；保留原快照和来源，关联用于统一查询汇总。
- 中心资料改名、规格/身份更新与停用不重写已首磅任务依据；现场正常回磅沿用快照。新任务继续校验最近已同步的资料状态。
- 中心厂区配置提案、现场明确应用及回执，停用复用未完成任务、未决打印及在线 Agent 检查；每厂连接地址独立，本机设备配置和打印账本不参与资料下发。
- 厂区命名空间主键和含稳定厂区码的新编号；旧单号不修改，旧备份恢复后重新生成编号。新增 schema 00016 与 seed 00010，同时提供 PostgreSQL/SQLite 迁移。
- 本地工作台/后台同步状态、中心入口限制、临时主体登记与处理页、厂区配置应用入口。

技术取舍见[同步设计](../architecture/local-first-sync-design.md)，首次启用、数据封存和生产切换步骤见[部署说明](../device/local-first-deployment.md)。

## 软件验证

主要新增边界为现有 HTTP API 的中心＋两厂实例及 Agent mock。测试分别使用独立 SQLite 文件和临时 PostgreSQL；互联网故障仅作用于厂区到中心的连接，不中断本地浏览器/API/Agent。

`server/integration/local_first_integration_test.go` 观察了：

- 两厂断网重新登录、同牌独立任务、相同原请求编号的跨厂幂等隔离、入厂先毛后皮与出厂先皮后毛、本地出单、厂区隔离及中心写入拒绝。
- 资料修改/停用/移除业务身份下发后，在途任务正常回磅，仍保留办理时名称与规格。
- 接收成功后丢失确认，发送端保留包重试；重复同步不重复生成单据或打印尝试，后台自动重连和统一资料更新在一分钟内可见。
- 图片通道暂时阻断时，中心单据标记图片未齐但有效汇总照常；恢复后图片补齐。
- 临时主体仅本厂可见、退回及补充提交、人工转正式后跨厂分发、同名不自动合并和显式关联。
- 后续打印尝试与作废同步，作废单退出汇总；停用提案在现场明确应用前不改变中心的已应用状态，在线 Agent 阻止停用，核实打印/停止 Agent 后应用及回执正确。
- 账号停用下发后，本地旧会话不可继续使用；无安全变化的普通同步不撤销旧会话。
- SQLite 一致备份恢复到独立临时实例后重新完成两次称重，新数据身份及单号没有复用原单；将旧业务快照装入新的同步包，也不能复活中心已经作废的单据。

`web/tests/local-first-smoke.mjs` 在上述真实临时 API 上使用 Chromium，验证断中心链路下的本地页面刷新、登录、同步状态、临时主体补录和中心操作入口限制。使用构建后的本地静态资源，不连接现有开发/生产数据库。

全量检查最终结果见本记录末尾；曾发现新迁移对应的菜单数量/种子版本固定断言需要更新，已随新权限增量调整，没有删除或跳过旧行为测试。

## 尚未执行的现场工作及限制

本轮没有升级 `fcc-com-01`、第二厂工控机或中心生产服务，没有迁移/删除既有联调资料，没有发起实物打印。首次生产联网启用、磁盘/CPU/内存资源、本机 PostgreSQL 共存、系统服务开机恢复、现场 TLS、真实仪表/摄像头/识别以及五联连续纸仍需实际环境验收。软件 mock 通过不代表这些项目已完成。

部署前须按说明原样封存旧库、图片与配置，再使用空生产交易库；这些步骤已提供操作依据，尚未替用户在真实现场执行。单盘故障保护及恢复演练继续按用户要求暂缓。

当前下行采用本厂可见的统一资料快照，业务上行按变化任务分批；没有大型资料量和现场带宽压力测试结果。单包 64 MiB、图片 10 MiB，超过会保留积压并报错，需要按实际规模扩展分页。恢复旧库前校准时钟并核对中心差异，不能据单号不复用测试宣称所有故障恢复场景已获验收。

## 已确认结论

1. 本次讨论的“第一阶段”指首个供酒厂实际使用的业务交付版本，统一称为“业务一期”，与已经完成的工程初始化 Phase 1 区分。业务一期在后续业务阶段推进，尚未确定与工程阶段的一一对应关系。
2. 首要目标是称重准确、记录可追溯，重点减少重量抄录错误、车辆与称重记录错配，以及事后缺少核查依据的问题。通行效率和业务核算的具体范围仍待确认。
3. 一期覆盖入厂卸货与出厂装货两类运输场景。通常分别为先毛后皮、先皮后毛；具体物料、特殊运输场景与例外流程待确认。
4. 追溯证据包含车牌、两次重量、采集时间、确认人员、修改／作废记录，以及每次确认称重时关联的现场抓拍。连续视频调阅不列入本轮已确认范围。
5. 一辆车的一次装货或卸货业务及对应的两次称重，统一称为“运输任务”，每个任务具有独立编号。同一车牌同时最多存在一个未结束任务；二次称重显示该任务，由操作员核对确认，上一趟结束后才能创建新任务。不得仅凭车牌拼接不同趟次的重量。
6. 一期正式称重只接受设备采集的重量，不提供手工输入正式重量的方式；设备采集故障时暂停系统内的正式称重。
7. 称重抓拍成功是本次称重确认的必要条件。抓拍失败需重试，重量和图片须对应同一次现场称重，不能使用车辆离开后的画面补齐；如何判定对应关系、采集有效期和故障恢复细节待确认。
8. 操作员确认二次称重且 Server 业务校验通过后，自动计算净重、生成正式电子过磅单，并将任务标为已完成。正式单据生成失败时不得将任务显示为完成；重试不能生成重复单据。失败后的具体恢复流程待确认。
9. 未结束任务跨天保留，不自动清零或结束。操作员核实仍属同一次运输后才能继续称重，保留原始采集时间；车辆离场后换货不应直接视为原运输。未结束任务须先处理，同车才能创建新任务。
10. 首次确认后发现车牌录错，由具有纠错权限的人员核对原抓拍后更正，记录原值、新值、原因与操作人，并校验目标车牌是否已有未结束任务。已确认重量禁止手改，只能通过符合条件的重称纠正，保留原记录及替代关系；车辆装货或卸货后，不得将当前重量冒充之前的重量。
11. 净重必须大于零；重量不符合业务方向或净重为零时阻止出单，保留异常尝试及原因供核查。不得自动交换毛皮重或取差值绝对值；原任务保留，核查后再决定重称或终止。异常尝试不等同于已通过业务校验的正式二次称重。
12. 未出正式单据，且核实车辆仍处于被替代称重对应的装载状态时，才允许重称。由有权限的人员填写原因，重新采重、抓拍并确认，保留历次记录，仅最新有效结果参与计算。装货或卸货已改变装载状态时，不得以当前重量替代先前装载状态的重量。
13. 一期每个运输任务只对应一种物料、一个往来单位；入厂卸货对应供方，出厂装货对应收方。混装重量分摊、多货主拆单留待后续。
14. 未完成运输取消时，由有权限的人员填写原因终止任务，保留已有重量、图片及操作记录，释放该车牌的未结束任务占用。终止任务不能恢复使用，新业务另开任务。
15. 正式电子过磅单禁止直接修改或删除。由有权限的人员填写原因作废，保留原单号、内容和证据及作废标记；作废不自动让任务退回待称重状态。更正重开须关联原单，核验原始称重依据仍然有效，不得通过重开手改重量。
16. 首次称重前必填车牌、运输方向、物料和往来单位；物料与往来单位从维护好的资料中选择。采集时间与确认人员由系统记录；司机信息与备注选填。
17. 允许确认重量的必要条件为设备正常、重量稳定且大于零、未超量程，并由操作员确认车辆已完全上磅。任一条件不满足不得确认；重量稳定不能代替车辆完全上磅的人工核对。
18. 每次确认使用本次新采集的重量及对应抓拍。核对期间发生重量失稳、明显变化、车辆驶离或数据超时，须重新采集，不能使用屏幕残留值。稳定时长、允许波动及采集有效期须形成现场验收参数，尚未确定数值。
19. 重量统一按千克计算和保存，保留仪表实际精度，界面与单据明确标注单位。显示吨时从千克换算；净重按原始精度计算后再按展示规则显示，不先舍入毛皮重。仪表实际单位、分度值、量程与最终展示位数待设备资料和现场联调确认。
20. 一期交付正式电子过磅单的纸质打印，由操作员在出单后发起。打印失败可重试，补打须标明次数并留痕；打印始终使用原单号，不重复生成单据，也不改变任务已完成的结果。纸张、联数和版式待现场确认。
21. 云端断网时暂停正式称重确认，不办理离线正式出单，不自动将历史缓存补成正式记录。恢复连接后先查询上次提交结果；已成功则使用原记录，未成功则重新核对现场条件，符合条件才重新采集。车辆已离开时，不得拿旧数据直接补确认。
22. 一期划分操作员、主管、管理员三类岗位：操作员负责日常首次与二次称重确认及记录查询；主管负责重称、纠错、终止、作废和更正重开，填写原因并留痕，由主管直接办理；管理员维护账号、岗位授权、物料、往来单位和设备配置。任何岗位均不得绕过重量与抓拍条件。业务动作须有服务端授权校验；打印和导出权限另见下述细化规则。
23. 更正重开时，主管核验证据后可更正车牌、物料、往来单位及司机等业务信息；运输方向、原始重量、采集时间和抓拍不得改写。重开使用新单号，关联原单及原任务，同一任务最多一张有效正式单；证据不足以支持更正时不能重开。
24. 历史记录保留当时使用的业务资料名称，不随基础资料改名而变化。已引用的物料、往来单位不得删除，可以停用。首次确认后的业务信息仅允许主管纠错并留痕，运输方向锁定，不允许直接在入厂卸货与出厂装货之间切换。
25. 抓拍须能核对车牌及车辆与磅台的位置关系；视角不足须调整或增加摄像机，由操作员核对车辆是否完全上磅。车牌自动识别失败时允许人工填写车牌并对照图片确认；图片本身无法满足核对要求时，不能确认称重。具体摄像机数量、安装位置和昼夜成像能力须现场确认。
26. 一期不自动清理已确认称重的图片、单据及称重业务审计记录，统一纳入备份。上线前估算存储容量，并验证恢复后仍能查到单据、图片及关联关系。以后需要清理时，另行确认保留期限与争议资料保全规则。
27. 打印机未回报且无法判断是否出纸时，标记“打印结果待核实”，不得自动重打，由操作员检查实际出纸情况。明确失败且未出纸可以重试；已经打印或无法排除已出纸时，由主管授权补打并填写原因。所有打印尝试留痕，补打注明次数。
28. 一期支持按日期、车牌、任务号／单号、运输方向、物料、往来单位和状态查询，并查看称重图片及操作历史。操作员负责查询，主管可导出明细与基础净重汇总。汇总仅计当前有效正式单，排除作废单，更正重开不得重复计算；日期口径和导出格式待细化。
29. 一期部署范围为一个厂区、一台地磅；同一时刻仅一个操作会话办理当前车辆的采集与确认，其他终端可查询，主管接管须留痕。占用仅针对本次现场称重，车辆装卸及等待二次称重期间允许其他车辆过磅。本阶段可展示占用与接管状态，服务端并发机制属于后续实现。
30. 一期业务目标为称重、毛皮净重计算和单据闭环；车辆放行沿用现场人工流程。道闸控制、库存记账、采购销售结算、ERP 对接、无人值守、扣水扣杂等结算重量调整留待后续。当前先做界面，车牌手填，摄像头尚无实物；当前不接真实设备、不办理正式称重，打印采用预览。
31. 跨天续称时，操作员对照首次称重、原抓拍、物料、往来单位及现场情况，确认仍属原任务并填写核实说明。有换车、转运或货物归属疑点时交主管核查，核查前不继续出单，无法确认则终止任务。此项为后续具备真实称重证据后的业务规则，当前只验证对应界面流程。
32. 当前阶段为界面与流程验证，采用模拟重量、测试单据与打印预览，摄像头显示未接入，测试数据须有明确标记；真实设备与正式业务接入放在后续。正式称重的设备重量和抓拍必要条件不因此取消。
33. 新增称重功能采用前端模拟，测试数据保存在当前浏览器，刷新后保留并支持重置，不同浏览器不共享数据。不新增称重业务 API 或业务表，现有登录保持原样。
34. 提供明确标记的演示面板，用于设置模拟重量、切换稳定／失稳、超时、断网、模拟抓拍成败及打印结果未知等状态，并演示不同岗位的操作差异。模拟重量从演示面板设置，业务表单仍禁止手改已确认重量；演示身份切换不修改真实账号权限，摄像头始终明确标注未真实接入。
35. 用户确认整体界面清单，包括页面组织、北京时间日期口径与 CSV 导出。随后用户要求暂停编码，先完成 Matt 技能配置，再依次定稿 Spec 与 Phase 2A 任务计划，等待下一步启动确认。需求确认与编码启动分开记录。

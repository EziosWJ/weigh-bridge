## Problem Statement

> 数据库范围更新（2026-10-22）：[ADR 0024](../../adr/0024-postgresql-only.md) 已取代本文的 SQLite 支持、双库迁移与兼容测试条款；当前开发和验收统一使用 PostgreSQL。其余条款按当前开发基线适用。

两个厂区各有一台地磅和独立工控机，现场互联网不稳定。现有集中 Server 与数据库的架构把正式业务确认依赖放在远程服务上；外网中断会阻塞现场称重、出单和生产。仅把页面或设备 Agent 放在现场，不能消除这种依赖。

现场需要在外网中断时独立登录、完成运输任务、人工确认称重、形成有效单据、打印并处理异常。管理人员需要统一维护物料、往来主体和账号授权，并在有网时自动取得两厂最新业务；暂时未同步的数据和图片必须能够辨认，不能被误读为没有业务或现场停产。

当前已有业务闭环、多厂区隔离、Agent 通信和打印相关能力；中心／厂区部署角色、跨节点同步和临时主体确认归并尚未实现。真实仪表、摄像头及现场称重验收仍需后续交付。

## Solution

复用当前 Server／Web 项目，按中心与厂区两种角色独立部署和存储。每个厂区的 Web、Server、PostgreSQL 及 Agent 部署在该厂工控机上，本地 Server 是所属厂区业务权威；中心统一管理资料、账号及现场归属，接收业务结果并按授权提供跨厂查询汇总。

外网中断而本地服务与设备链路正常时，现场继续生产。本地确认成功的单据即具有既定业务效力，不等待中心审批。有网时自动持续同步，恢复后补齐积压；正常网络、无积压时，业务和资料变更以 1 分钟内在接收端可见为目标。图片单独标记完整性，上传等待不阻塞称重。

正式资料由中心维护。操作员可在本厂补录临时往来主体并办理业务，中心随后人工确认转正式或关联已有主体；原任务、单据及依据始终保留历史快照。

## User Stories

1. 作为现场操作员，我希望在本厂工控机打开完整业务界面，以便办理称重时无需等待互联网。
2. 作为现场操作员，我希望断外网后刷新页面仍可使用本地系统，以便页面重载不会使生产中断。
3. 作为现场操作员，我希望已同步账号能在断网时重新登录，以便换班或会话过期后继续工作。
4. 作为现场操作员，我希望断外网后正常建立运输任务和确认首次称重，以便车辆能继续入厂办理业务。
5. 作为现场操作员，我希望断网期间正常办理二次称重并在本地出单，以便完成车辆进出厂流程。
6. 作为现场操作员，我希望入厂卸货和出厂装货分别使用正确的毛皮重语义，以便首次称重不被固定当作毛重。
7. 作为现场操作员，我希望称重仍需本人核对并确认设备重量和对应抓拍，以便离线运行保留可信依据。
8. 作为现场操作员，我希望过夜车辆沿用原任务和首次称重，以便跨日回磅不需重新建立运输任务。
9. 作为现场操作员，我希望原始重量、最终重量和调整差额继续按吨制准确表达，以便单据与汇总保持一致。
10. 作为有权限的现场操作员，我希望在本厂办理双向重量调整并保留原始值，以便纠正单据重量时保留来源。
11. 作为有权限的现场操作员，我希望单磅重称保留另一磅依据和历次替代关系，以便纠正测量结果时仍可追溯。
12. 作为有权限的现场操作员，我希望本地办理纠错、终止、作废及关联重开，以便异常处置不依赖中心在线。
13. 作为现场操作员，我希望本地已确认单据无需中心再审批，以便出单和交付不受同步进度影响。
14. 作为现场操作员，我希望在本厂打印和补打已有单据，以便断网时仍能交付纸单。
15. 作为现场操作员，我希望打印结果未知时继续按原流程核实，以便重连后不会自动重复出纸。
16. 作为现场操作员，我希望业务提交结果不明时先查询原请求，以便避免重复建任务或出单。
17. 作为现场操作员，我希望看到中心连接、待同步数量和最近同步时间，以便了解数据上传情况。
18. 作为现场操作员，我希望同步等待不改变已完成任务或有效单据状态，以便准确判断业务是否办结。
19. 作为现场操作员，我希望厂区端固定显示本厂工作台、任务、单据和统计，以便避免跨厂误操作。
20. 作为获授权的管理人员，我希望在中心查询两厂业务，以便统一掌握各厂生产情况。
21. 作为获授权的管理人员，我希望中心查询及导出遵守本人厂区范围，以便只访问获准的数据。
22. 作为获授权的管理人员，我希望跨厂报表显示各厂数据更新时间，以便识别暂未同步的业务。
23. 作为获授权的管理人员，我希望中心完整收到的有效单据在图片未齐时仍计入汇总，以便统计不等待大文件上传。
24. 作为获授权的管理人员，我希望图片未齐有独立状态，以便查看业务时知道证据同步是否完整。
25. 作为获授权的管理人员，我希望作废单被排除、更正重开不重复计数，以便汇总准确反映当前有效业务。
26. 作为获授权的管理人员，我希望中心未收到更新时显示信息未更新，以便不把互联网断开误认为现场停产或 Agent 故障。
27. 作为资料管理员，我希望在中心统一维护物料和分类，以便各厂使用一致的物料档案。
28. 作为资料管理员，我希望在中心维护企业／个人往来主体、多业务身份及联系人，以便两厂共享完整正式资料。
29. 作为现场操作员，我希望断网时选用最近同步的正式资料，以便常规业务持续办理。
30. 作为资料管理员，我希望厂区收到资料停用更新后禁止新任务选用，以便停用规则用于后续业务。
31. 作为现场操作员，我希望已首磅任务在资料停用后仍能沿用原依据回磅，以便车辆不会因资料维护卡在厂内。
32. 作为现场操作员，我希望已开始任务沿用办理时的资料快照，以便中心改名、改规格或调整主体身份不改变本趟依据。
33. 作为有权限的现场操作员，我希望主动纠正本趟资料时沿用既有纠错流程并留痕，以便保留更正前后关系。
34. 作为现场操作员，我希望有网或断网时都能补录临时往来主体，以便新供货方、收货方或承运方不阻塞现场业务。
35. 作为现场操作员，我希望取得独立的临时主体补录权限，以便补录业务所需档案而无需完整资料管理权限。
36. 作为现场操作员，我希望初次待中心确认的临时主体可在本厂重复选用，以便同一主体再次来厂时正常办理。
37. 作为资料管理员，我希望未确认临时主体不作为其他厂区可选档案下发，以便统一资料经过确认后再共享。
38. 作为资料管理员，我希望人工确认临时主体转正式或关联已有主体，以便处理两厂重复补录。
39. 作为资料管理员，我希望同名只作为提示，以便不会把不同的人或企业自动归并。
40. 作为获授权的管理人员，我希望主体归并后可按统一关联查询汇总，同时保留原单据内容，以便统一统计和历史追溯都可用。
41. 作为资料管理员，我希望退回信息不足的临时主体要求补充，以便完善正式档案。
42. 作为现场操作员，我希望收到退回结果后明确看到新任务不可选用，但既有任务仍可续办，以便正确处理现场车辆。
43. 作为现场操作员，我希望补充并再次提交的主体在中心确认后恢复新选用，以便不会通过重新提交绕过退回限制。
44. 作为系统管理员，我希望统一维护账号、角色、动作权限和厂区授权，以便各厂使用同一套管理规则。
45. 作为系统管理员，我希望密码修改和重置在中心统一办理，以便不会产生冲突的本地密码版本。
46. 作为现场操作员，我希望离线期间使用最近同步的权限、会话正常过期且不按断网天数停用，以便长期断网仍能按既有授权生产。
47. 作为系统管理员，我希望厂区收到账号停用、撤权或密码更新后按规则生效，以便管理变更在恢复通信后落实。
48. 作为业务管理人员，我希望账号更新不撤销此前已提交业务，以便历史记录及责任归属保持稳定。
49. 作为现场负责人，我希望每厂预先准备至少两名实名授权人员，以便一人忘记密码时由另一人用本人账号接班。
50. 作为现场维护人员，我希望中心管理厂区、地磅及 Agent 归属和连接身份，以便统一表达现场身份。
51. 作为现场维护人员，我希望 Agent 配置连接本厂 Server，并在现场明确应用，以便配置更新不静默切换运行环境。
52. 作为现场维护人员，我希望本机串口、摄像头、打印队列、校准参数和打印账本在现场保留，以便中心资料下发不破坏设备配置。
53. 作为系统管理员，我希望中心停用申请在现场满足既有条件并明确应用后才显示已停用，以便中心状态符合现场实际。
54. 作为现场负责人，我希望本厂断网不影响另一厂办理，以便两厂独立生产。
55. 作为获授权的管理人员，我希望有网时业务及资料自动持续同步、断网恢复后自动补齐，以便无需手工导出汇总。
56. 作为获授权的管理人员，我希望作废、更正、重开、称重依据和打印记录的后续变化也同步，以便中心长期保持正确业务结果。
57. 作为现场操作员，我希望重复传输、重连或服务重启不会重复生成业务或打印，以便网络恢复过程保持业务唯一性。
58. 作为业务管理人员，我希望新单号包含稳定厂区码，独立出单和旧备份恢复后均不重号，以便单据在全系统唯一。
59. 作为业务管理人员，我希望历史单号保留、作废不回收、补打沿用原号、重开使用新号，以便历史关系持续可追溯。
60. 作为部署维护人员，我希望首次联网完成注册、身份配置、账号和资料下发后验证断网运行，以便正式启用前确认现场可独立生产。
61. 作为业务管理人员，我希望原联调库、图片和配置原样备份封存，新生产任务与单据从空库开始，以便测试历史不混入生产交易。
62. 作为部署维护人员，我希望仅迁入确认的基础资料、账号授权和现场身份，并保留 Agent 打印账本，以便切换部署时不丢失既有防重依据。

## Implementation Decisions

- **代码与角色**：沿用当前后端、前端及现场 Agent，不另建中心后端项目。应用装配支持中心与厂区角色，每个实例使用独立数据库；厂区实例固定本厂归属。页面入口与服务端接口共同落实职责限制。
- **部署目标**：各厂 Web、Server、PostgreSQL 及 Agent 部署在该厂工控机，不以独立 Server 主机作为默认替代。V1.0 部署数据库保持 PostgreSQL，开发与数据库测试同样使用 PostgreSQL。现场资源满足情况在部署前核验，不宣称已验证。
- **复用模块**：扩展既有应用装配、认证与会话、RBAC、用户管理、物料与主体、厂区配置、称重业务、单据、打印、查询导出及前端 API／页面能力；新增中心与厂区同步、临时主体确认及关联能力。沿用既有分层，不做无关重构。
- **业务权威**：任务、称重确认、正式单据、异常处置、打印及其审计由所属厂区负责。中心同步业务结果，不审批单据，不发起现场作废、更正、重开或打印。
- **正式依据**：人工确认、设备重量、对应抓拍、稳定条件、原始记录、毛皮重语义、吨制精度及历史版本继续适用。外网中断不等于本地业务或设备链路断开；后者仍可阻止新的正式确认。
- **资料权威**：中心统一维护物料分类、物料及正式往来主体；厂区选用最近同步资料，不新增临时物料。初次待确认临时主体限本厂选用，中心可查看处理。
- **临时主体权限**：操作员默认取得独立补录权限，不授予完整正式资料维护权限；供货方、收货方和承运方均覆盖。中心人工确认、关联或退回，不按同名自动归并。
- **临时主体状态**：初次待确认可供本厂重复选用；收到退回后禁止新任务选用；补充再次提交后须中心确认才恢复新选用。既有任务继续，历史单据不因退回失效。
- **资料快照与关联**：中心资料修改及临时主体归并不改写任务、单据和原始依据。已首磅任务沿用原快照正常续办；中心修改用于新任务。主体归并通过保留来源的关联实现统一查询汇总。主动纠正本趟资料按既有流程留痕。
- **停用规则**：厂区收到基础资料停用更新后禁止新选用，既有任务仍可沿用原依据正常回磅，不允许任意换用其他停用资料。原单库下对未结束任务所需主体身份的维护限制，需要按快照续办规则适配。
- **账号与会话**：账号、岗位权限、厂区授权、密码修改和重置中心统一维护；厂区独立登录鉴权。离线使用最近同步账号权限，可重新登录，会话正常过期，不因离线天数停产。接收更新后按规则生效，适用时撤销旧会话；不撤销已提交业务，不另建本地密码版本。
- **接班规则**：每厂首次启用前同步至少两名实名授权人员。一人忘记密码时由另一人使用本人账号接班，原账号由中心重置并等待同步。
- **现场配置**：中心管理厂区、地磅及 Agent 归属和连接身份，Agent 连接本厂 Server；现场明确应用，保留本机设备参数与账本。各厂现场连接地址与中心管理入口分别表达。
- **厂区停用**：中心提出停用申请，现场满足无未完成任务、未决打印、在线 Agent 等既有条件并明确应用后才生效。未确认显示待现场处理，不能把中心意图当作已停用。
- **同步范围**：中心下发统一资料、账号授权及已确认范围内的配置；厂区上传任务、称重记录、各版单据、业务审计、打印尝试及对应抓拍，包含后续作废、更正和重开。业务数据优先、图片随后补齐，分别表达完整性和积压进度。
- **同步契约**：为中心与厂区建立独立同步契约，复用现有鉴权、响应、错误和审计约定。需要持久化待同步状态、接收去重及版本依据；不预先指定消息中间件、数据库表名或具体 URL。现有 Agent 通信链路继续负责现场设备。
- **同步结果**：正常网络、无积压时，业务和资料变更 1 分钟内在接收端可见。同步等待不阻塞本地确认；重复传输、重连或重启不重复建业务、不重新打印。提交结果未知仍先查原请求，不把未确认缓存自动转正式。
- **中心查询**：按动作权限及厂区授权跨厂查询，厂区端仅查询本厂。中心展示各厂最近同步时间；信息未更新不等于现场停产或 Agent 故障。
- **中心汇总**：完整业务数据已到达且单据有效时计入，图片未齐另标，不影响单据效力或统计资格。继续排除作废单、更正重开不重复计数；报表与导出表达各厂更新时间。
- **数据身份与编号**：独立节点不能直接合并本库自增 ID。设计跨节点身份、关联及编号规则，新单号包含稳定厂区码；独立出单及旧备份恢复后不复用已用编号。历史单号保留，补打沿用原号、作废不回收、重开新号；内部主键及具体编号实现由技术设计确定。
- **持久化变更**：部署角色、本厂身份、同步状态、临时主体来源／确认结果／关联、必要的编号及授权同步状态需要持久表达。结构变化新增 Goose migration，验证 PostgreSQL 迁移及业务行为，不改写已发布历史，不在 API 启动时自动建表。
- **首次启用与切换**：首次联网完成注册、现场配置、账号及资料下发，并验证断网运行。联调库、图片及配置原样备份封存，新生产交易空库开始；仅迁入确认资料、账号授权和现场身份，保留 Agent 身份及打印账本。旧浏览器演示库不导入、不删除。

## Testing Decisions

- **用户已确认测试边界**：以现有 HTTP API 为主要边界，启动中心＋两厂实例及 Agent mock，验证断网办理、恢复同步、权限隔离与单据去重；少量浏览器测试覆盖操作入口和状态展示。
- **测试质量**：断言对外可观察的业务结果，包括请求结果、任务与单据状态、可查询历史、统计导出、可见图片及打印次数。不围绕私有函数、表字段布局或实现步骤编写镜像测试，不要求每个用户故事对应一个浏览器端到端测试。
- **既有先例**：复用已有称重闭环、多厂区隔离、现场配置的 HTTP 集成测试装配、临时数据库及 Agent mock；浏览器部分复用真实 API 与 Agent mock 驱动的称重业务冒烟模式，不新增另一套前端整库模拟。
- **最少新增测试设施**：在现有 API 测试装配上支持中心与两厂独立实例、独立持久存储，并控制中心与厂区连接的断开、恢复和重复传输；本地浏览器到厂区、厂区到 Agent 的链路保持可用。新增的是拓扑和网络控制设施，主要业务测试边界仍为 HTTP API。
- **本地闭环与边界**：覆盖两种运输方向、人工确认与抓拍、过夜车、双向调整、重称、作废重开、打印未知核实，以及本地服务或设备链路故障不能被当成可继续确认。
- **跨节点行为**：覆盖断外网后刷新与重新登录、两厂互不等待、恢复同步及正常无积压 1 分钟目标、重复接收／重连／重启、后续版本变化、图片延迟，以及重复传输不触发打印。通过外部查询核对本地与中心业务结果，不只断言发送次数。
- **资料与权限**：覆盖临时主体初次待确认、转正式、关联、同名不自动归并、退回与补充后待确认、跨厂选用限制；覆盖资料修改／停用后的既有任务快照续办、正式资料维护限制、中心与厂区角色约束、账号与权限接收后生效。
- **查询及配置**：覆盖中心各厂更新时间、未更新状态、图片未齐的统计资格、作废排除及重开去重、授权导出、厂区停用申请与现场应用，确认配置下发不覆盖本机设备参数。
- **数据与启用**：覆盖两厂独立编号、旧号保留、必要的恢复后编号不复用验证、首次初始化与脱网办理，以及联调交易不混入新生产库。单盘故障保护方案及其演练不纳入本轮测试承诺。
- **数据库与常规检查**：对受影响迁移和关键行为运行 PostgreSQL 集成，保持既有后端检查、前端 lint／build 等项目检查。长驻测试设置超时并清理进程和临时数据；依实际改动选必要检查，不跳过失败或删除原行为测试。
- **验收性质**：以上是后续测试决定，当前未实施或执行。Agent mock 软件验收不等于真实仪表、摄像头、识别或实物纸张验收。

## Out of Scope

- 单盘故障保护的具体方案、硬件采购、恢复时限及故障演练。用户保留已确认数据保护目标，但明确要求本阶段先收敛业务修改，不继续展开该方案。
- 新建独立中心后端项目、无关大规模重构、数据库或前端技术栈升级。
- 中心发起远程称重确认、作废、更正、重开、打印，或积压远程业务指令待恢复后自动执行。
- 自动补办历史称重、将未确认缓存直接转正式、同步时重新出单或自动重打。
- 临时物料、厂区直接修改中心正式资料、同名主体自动归并。
- 首次完全离线安装、U 盘增量交换。
- 以本 Issue 宣称真实仪表、摄像头、识别、五联或连续纸验收完成；相关设备能力按既有阶段分别交付。
- 库存、结算、ERP、跨厂拼接两次称重等新增业务。

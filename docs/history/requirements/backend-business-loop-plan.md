## 实施顺序

| 编号 | 交付内容 | 依赖 | 完成证据 |
| --- | --- | --- | --- |
| B01 | 迁移基础：资料、地磅、编号；真实业务权限查询／校验与菜单／角色 seed；既有赋权和账号管理写入口的必要授权；测试模式配置 | 设计评审、明确启动 | PostgreSQL 显式迁移通过；已有系统契约保持；空业务库；无权限直调拒绝且不能经旧入口自授权限 |
| B02 | 资料 service/repository/API，分类、物料、主体身份及联系人；前端资料页面接入 | B01 | 自动编码、同名资料、默认联系人、引用保护、身份约束及版本冲突生效 |
| B03 | 任务／采样／记录／单据／操作结果／事件等迁移，会话占用接管，测试采集和首磅原子确认 | B01、B02 | 两终端争用、接管失效、重复首磅、同车唯一、跨浏览器查任务 |
| B04 | 二磅原子出测试单、双向最终值、过夜回磅、未知提交查询；工作台接入 | B03 | 入厂／出厂闭环；原始异常阻断；丢响应后找回原结果，不重复出单 |
| B05 | 纠错、终止、单磅重称、作废、关联重开及各版快照；详情接入 | B04 | 旧单不变、同车新趟冲突规则、替代链、失败不恢复作废单、有效单唯一 |

以上为连续开发批次，不构成逐批审批关卡。用户明确启动编码后，按依赖自主推进；普通命名、文件拆分和可逆实现选择不重复确认。实现中只有新增关键业务分歧才回到用户。

每批迁移与代码同时交付，不先创建未使用的全部未来设备表。资料引用检查在 B02 搭接口，任务和历史表进入 B03 后补齐真实引用／并发保护，不能在最终交付保留“只查当前任务”的简化。

## 验证重点

复用既有 Go 单元／集成测试、前端核心行为与浏览器工具，测试公共行为，不为每个字段编写重复实现测试。

| 范围 | 最小必要验证 |
| --- | --- |
| 迁移 | PostgreSQL 从现有版本升级；schema／seed 分流；非空测试库回退及重建；业务表默认无测试交易，API 不自动建表 |
| 权限 | 真实角色和隐藏动作码生效；撤销后拒绝；mock 切岗位不能越权；直接访问动作／导出也校验；旧角色／菜单／账号写入口不能自授权限或重置管理员密码，本人改密／头像不受管理权限限制 |
| 资料 | 多身份／默认联系人、自动编码、引用后删除拒绝、停用可沿用历史、未结束任务身份删除拒绝、并发更新冲突 |
| 原子性与去重 | 首磅／二磅／重开成功但回包丢失，同 key 返回原对象；同 key 不同 payload 拒绝；单据或审计写失败业务整体回滚 |
| 并发 | 同车首磅竞争只建一个任务；同任务两次二磅／重开只出一个有效单；过期／接管会话拒绝旧采样 |
| 重量与日期 | 两方向、吨制字符串精度、正数、原始与最终净重、双向差额；跨日／替换单磅日期正确 |
| 历史 | 资料纠错／改名、人工调整、实际重称、作废重开后，旧单业务／重量／图片快照不变，业务历史不随系统日志清空 |
| 跨趟 | 新任务进行时旧单人工重开允许、旧任务实际重称拒绝；旧任务不恢复普通待回磅占用 |
| 打印 | 预览不算打印，重复发起去重；未决尝试不自动重发；明确失败 retry 与 reprint 计数分离，人工反馈有来源 |
| 页面 | 真实登录后完成一条入厂与一条出厂流程，刷新／第二浏览器可查询；失网未知结果先查；默认 1366×768 工作台主操作可见 |

### 命令与检查时机

- Go 改动运行 `task backend:check`；数据库改动增加 `task db:check`，PostgreSQL 集成需 Docker。
- Web 改动运行 `task frontend:lint`、`task frontend:build`；按实际接口切换补核心行为与少量页面冒烟。
- 修改 API 注解后使用 `task backend:swagger` 更新 Swagger；不把设计文档里的未实现接口发布为可用 API。
- 若涉及工程配置迁移，再按实际影响运行 `task check`、`task build:check`；等价检查通过不重复底层命令。
- 长驻服务设超时并清理，`/health` 检查存活，`/ready` 检查数据库就绪；无法运行的检查说明原因，不标通过。

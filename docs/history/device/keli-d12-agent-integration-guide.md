## 3. 已验证的现场基线

内部 SSH 别名为 `fcc-com-01`，实验操作账号为 `hp`，实际串口为 `/dev/ttyS0`。USB 转换线此前用于电脑间对测，最终仪表链路使用 FCC 内置串口；不能因曾使用 USB 就把驱动默认写为 `/dev/ttyUSB0`。

| 项目 | 基线 |
| --- | --- |
| 接线 | D12 的 PC 接口 → 工控机内置串口，DB9 母对母直通，2↔2、3↔3、5↔5 |
| 串口 | 9600、8 数据位、无校验、1 停止位，无软／硬件流控 |
| 仪表 | `Adr=1`、`bt=9600`、`tF=05`、`Jn=none`、`bit=8`、`CyC=200 ms` |
| 接收方式 | 连续接收，raw 模式；无需轮询，不写入置零、去皮或改参指令 |
| 现场权限 | 曾由管理员临时授予 `hp` 串口 ACL；重启后失效过，持久服务权限尚待核实 |
| 验证范围 | 电脑间双向字符通信；`tF=00` 零值 15 帧校验通过；`tF=05` 带载 868 帧，含 52 种数值、12 次动态位切换，CKS 累加规则全匹配 |
| 现场单位 | 用户确认小轿车的主要稳定读数 1.55 和 1.48 实际为吨；本机以吨解释，B bit4 的文档 kg 含义与现场不符 |
| 尚未验证 | 与稳定灯逐时对照、负值／净重／非零皮重、其他固件的 CKS 与单位、长期运行及设备故障恢复 |

现有 S-CodE／C-CodE 设置入口可能不同，以实际屏幕和现场人员为准；文档不保存现场密码。调整接线按设备要求断电进行。实验脚本已退出、串口已释放；真实部署前仍需重新核查是否有其他进程占用。

## 4. tF=05 解析参考

### 4.1 按字节流拆帧

本机观测到每帧 18 字节，以下下标从 0 开始：

| 偏移 | 长度 | 内容 |
| --- | --- | --- |
| 0 | 1 | STX，`0x02` |
| 1、2、3 | 各 1 | 状态字 A、B、C |
| 4～9 | 6 | 显示重量，ASCII 数字，不含符号和小数点 |
| 10～15 | 6 | 皮重，ASCII 数字 |
| 16 | 1 | CR，`0x0d` |
| 17 | 1 | CKS，单个二进制字节 |

实现累计缓冲区：查找 STX，等待完整长度，再检验结构和 CKS。错误候选移过一个字节后重新找帧；限制垃圾缓存大小。完整帧消费成功后继续解析余下内容。CKS 可能等于控制字符，因此不能仅用换行或分隔符切整帧。

本次实际发生过 8＋8＋2 字节分段到达；一次读取也可能包含多个完整帧。接收层不依赖单次 `Read` 的大小。

### 4.2 状态及数值

按柯力官方状态表：

| 字段 | 含义与映射 |
| --- | --- |
| `A & 0x07` | 小数位置编码 `d`；原始六位整数乘 `10^(2-d)`，不是直接把 `d` 当小数位数 |
| A bit 3～4 | 分度值因子；是元数据，不应再重复乘到已传送的显示重量 |
| B bit 0 | 0=毛重、1=净重，单独保留类型 |
| B bit 1 | 0=正、1=负，应用于显示重量；皮重字段无独立符号位 |
| B bit 2 | 超载或低于零异常位；置位时不得作为正常可采集状态 |
| B bit 3 | 1=动态、0=非动态；正常新鲜帧的 `stable` 来自该位 |
| B bit 4 | 文档规定置位表示 kg；本机带载实测置位却按吨表达，原始标志与确认过的现场单位分别保留，禁止仅凭该位自动换算 |
| C bit 3、4 | 打印命令标志、扩展显示标志；作为诊断信息保留，不据此新建打印任务 |

确定性原始样本：

```text
02 2d 30 20 30 30 30 30 30 30 30 30 30 30 30 30 0d bf
```

解析结果：A=`0x2d`，`d=5`，三位小数；B=`0x30`，毛重、非负、非动态、文档 kg 标志置位、异常位未置位；C=`0x20`。零值本身无法辨识单位；后续带载与现场确认表明本机显示重量、皮重按吨解释，不能继续使用初步按文档得出的 kg 推断。

### 4.3 CKS 的本机带载验证

初期 15 帧相同零值样本的尾字节都是 `0xbf`，随后带载采集的 868 帧覆盖 52 种数值、61 种整帧及动态／非动态状态，全部符合：

```text
CKS = sum(frame[0:16]) & 0xff  // 包含 STX，不含 CR 与 CKS
```

本机非零稳定样本与同值动态样本分别为：

```text
02 2d 30 20 30 30 31 35 36 30 30 30 30 30 30 30 0d cb
02 2d 38 20 30 30 31 35 36 30 30 30 30 30 30 30 0d d3
```

这两帧均为数值 1.560，现场确认按吨解释；动态位及 CKS 同时相差 8。包含 CR 的累加、包含 CR 的 7／8 位补码算法均为 0／868 匹配。可以据此实现本机的严格 CKS 校验与篡改测试。

柯力本次引用的文档没有给出 CKS 公式；本规则应命名为本机验证过的 D12 累加校验，不称为“标准托利多校验”。证据仅覆盖零值、正值毛重及两种动态状态；负值、净重、非零皮重及其他固件仍待核实。用该算法生成的测试验证实现，真实原始帧验证与设备一致性，两者分别保留。

解析结果区分结构有效、CKS 通过和校验失败；不支持的协议版本明确提示未核验。坏帧不更新最后有效时间，不采用“总是忽略 CKS”的降级。原始录制 JSONL 中的校验状态保留采集时的 `unconfirmed_algorithm`，后续分析单独记录 868／868 匹配，不改写原始文件。

### 4.4 单位、精度与业务含义

协议内部保留原始整数、倍率、符号、原始单位和完整帧，用整数／十进制精确换算，避免浮点误差。

业务协议只允许吨制字符串，精确至 `0.001 t`，即 1 kg。`agentproto.Weight(1)` 表示 `0.001 t`，不是 1 吨；从整数 kg 换算到该类型时数值相同，仍要通过语义明确的转换函数，防止额外乘除 1000。

本机的关键差异是：B bit4 按文档像是 kg，但现场确认数值 1.550、1.480 实际为 **吨**，对应小轿车重量。首期为本机显式配置现场确认单位 `t`，将解码值直接作为吨制字符串，例如 `"1.55"`；对应 `agentproto.Weight(1550)`。**不能因文档单位位而再次除以 1000，也不能对所有 D12 一律强制吨。** 原始状态位、配置单位与确认依据都应保留。

其他现场按明确配置转换，未知单位保持不可采集。若配置为 kg 且遇到无法无损映射到业务精度的值，先明确返回精度不兼容并保留原值；业务量化策略在实际数据暴露问题时确认，不能悄悄截断、四舍五入。

负值在驱动诊断中保留，现有消息反序列化不能承接正常负重量，故通过故障状态表达，不擅自扩展协议。零值可以上报，现有 Server 会拒绝正式采集确认。

仪表的“毛重／净重”与业务首磅／回磅不同：空车回磅时仪表毛重可以是车辆皮重。首期以仪表毛重模式提供测量值；若切为净重，应显式标明状态不适用并提示现场检查，而不是默默把净重当作业务毛重。仪表皮重字段也不自动写入运输任务的业务皮重。

## 5. 串口模块与运行状态（已实现）

纯解析器与 Linux 串口读取位于 `server/internal/agentscale`；状态文件写入与维护页读取也在该轮实现。沿用现有 Go module，Linux termios 可复用已存在的 `golang.org/x/sys/unix`，不因读取串口升级依赖或引入通用驱动框架。

对外提供配置、启停和最新快照即可。快照至少区分原始读数、单位／重量类型、仪表稳定位、最后有效接收时间、故障原因及校验状态；上层无需理解拆帧细节。

运行要求：

- 打开时独占串口，raw、8N1、无流控；处理权限不足、设备不存在和忙，关闭时释放独占及文件描述符。读超时服务于轮询取消和状态保鲜，不让串口读取永久阻塞退出。
- 每次有效帧刷新本机单调时钟计时；建议以 1 秒无有效帧作为首期现场可调整阈值，最终值在实现中注明。这是建议值，尚未实测验收，并须早于 Server 的 3 秒陈旧门限。
- 失联、校验异常或不支持的单位／精度，及时上报 `deviceOk:false`、`stable:false` 及原因。最后读数可用于维护页诊断，但同时显示过期，不能继续刷新成“当前稳定重量”。
- 串口故障后有界退避重开，恢复后由新完整有效帧决定状态；网络重连同样只上报当前新鲜状态。心跳、成功打开串口及重复读取缓存均不刷新测量时间。
- 故障转换／恢复即时上报，正常状态可按 v1 建议的约 500 ms 节奏上报。每次上报都核查原始测量新鲜度；不以 v1 的心跳来假造新采样。
- 配置关闭或进程收到 kick 时，关闭读取与重连循环；打印忙或暂停维护时，串口读取及 kick 接收仍可运行，不让一个阻塞操作卡住全部设备能力。

串口占用与 WebSocket 身份互斥是两层约束，均需遵守。现场终端工具、独立诊断脚本与驱动不能同时打开设备。

## 6. 接入 WSS、配置和维护页（已实现）

### 单一 Agent 连接

在原 Agent 的连接和并发发送控制内接入仪表状态，保留身份、配置摘要、打印账本、未决打印处理和 kick 退出语义。串口采集生命周期可独立于 WSS 重连，但网络恢复时只读取新鲜快照；不要在每次重连泄漏读取协程。

`device.state` 继续使用 `agentproto.DeviceState`，重量为吨制十进制字符串，`stable` 取自仪表动态位，`deviceOk` 明确表达当前可用状态。接入后的故障定义需与当前 Server 配合，仪表正常不代表摄像头已接入。

当前 Agent 会忽略 `capture.request`。仪表首期接入时应补充明确失败回复：摄像头或其他采集前提未完成时，用相同 `requestId` 回复 `capture.result`、`success:false` 和具体原因。既有采集要求前后抓拍，不以只有重量就回复成功，不伪造图片或绕过 Server 校验。正式称重闭环仍列为未完成。

### 共享本地配置

共享配置模型只保留 Agent 主机的串口路径与波特率；旧 `agent.env` 中的启用开关、协议、源单位和超时字段不再读取，未配置串口时保持维护连接并按仅打印运行：

```dotenv
WEIGHBRIDGE_SERIAL_PORT=/dev/ttyS0
WEIGHBRIDGE_SERIAL_BAUD=9600
```

D12 `tF=05`、8N1、无流控、吨制解析及 1 秒无有效帧阈值固定；不根据 B bit4 静默切换单位。配置与实际仪表设置不一致时显示故障，不在串口上自动改仪表参数。服务器地址与打印队列沿用当前值；Agent 身份由 Server 在接入握手时分配。

扩展配置时同步处理读取、校验、摘要和维护服务的单次保存并应用／核实／回退；核查其环境文件重写逻辑，防止丢失串口或原打印字段。本机串口参数属于现场维护，不夹带到中心分发的身份配置。维护界面不回显连接密钥。

### 本地预览与服务权限

驱动输出有限的本地状态快照，供维护服务只读展示：是否启用、实际端口、协议、最后有效帧时间、原单位读数、业务换算值、稳定、异常与校验状态。可沿用既有状态文件的原子写入方式；格式与路径在实施时确定，不新建第二个串口读取进程。

维护服务独立于 Agent；Agent 停止或快照过期时，页面显示停止／过期，不能仅因磁盘文件仍写着 `stable:true` 就显示当前可用。页面保留摄像头未接入提示，具体编辑页面遵循其所在目录指导。

现场检查实际服务账号的串口组／ACL 与有效进程组。实验 ACL 为临时授权，持久化方案需按现场 systemd 用户服务方式落实并验证重启；不将整个 Agent 或维护服务改为 root，也不通过开放所有用户写权限解决问题。

| 数值与状态 | 所有小数位置编码、正负号、毛净、动态、异常、单位不明；真实支持与构造测试明确区分 |
| 校验 | 已核实规则的通过／失败；单字节篡改被拒；算法未确认状态保持不可采集 |
| 生命周期 | 通过可控 reader／伪终端验证无新帧、断线、恢复、取消、独占和有界缓存，不依赖固定长等待 |
| 精度 | kg→t 的精确转换、协议精度不兼容、负值不伪造正常值、零值不开放正式确认 |
| 集成 | 同一 Agent 提供打印与重量；网络恢复不复活旧重量；打印忙时 kick 仍退出；缺摄像头明确回复采集失败 |
| 配置维护 | 旧配置兼容、新字段保存应用及回退保留身份／密钥／打印；维护预览标明过期与未核验 |

Go 改动运行 `task backend:check`。涉及 Web 工程再运行 `task frontend:lint`、`task frontend:build`；维护页面沿用其已有必要测试入口。只有真正改动数据库时才按根指导追加迁移与数据库检查，本项正常不需业务表变化。

现场验收按下面的证据清单逐项补齐：

- 记录有效服务账号、端口、直通线、仪表参数，确认服务权限重启后仍有效。
- 复用本次非零样本，核对配置单位为现场确认的吨及其换算；增加当前未覆盖的模式／固件时另行抓包验证，不能把本机结论泛化。
- 正常称重过程覆盖动态→稳定，比较面板稳定灯与解析位，不用多帧同值代替仪表判稳。
- 受控验证串口无数据／设备不可用和恢复；按厂家要求断电插拔，软件侧可用伪终端先验证故障，避免通电拔线试验。
- 验证单一 Agent 的真实重量预览、Server 状态保鲜、原打印功能及踢出；只有摄像头等证据链真正完成后，另行验收正式采集和确认。

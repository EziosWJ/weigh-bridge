# 通知与公告完善设计

> 数据库范围更新（2026-10-22）：当前 Server 开发、测试、生产仅支持 PostgreSQL；本文旧 SQLite 兼容要求已由 [ADR 0024](../../adr/0024-postgresql-only.md) 取代。历史验收事实保留。

状态：已实现并通过 HTTP 集成契约、浏览器行为及容量验证。规格见 [GitHub Issue #73](https://github.com/EziosWJ/base-project-golang/issues/73)，使用入口、业务接入和验证结果见[实现说明](notification-implementation.md)。

本轮在[首版站内通知](notification-plan.md)基础上完善公告、业务通知接入和实时体验。首版文档中的轮询方案描述历史实现，本轮将替换该方案。

## 已确认决策

- 公开公告：未登录也能查看，内容必须适合公开，在有效期内持续可见。
- 站内公告：登录后可查看，在有效期内持续可见，发布后新建用户也能看到。
- 站内通知：发送给指定用户或发布时的全体用户，每个接收人有独立已读状态；支持管理员手动发送和业务自动触发。全体用户沿用发布时已有且启用账号的快照语义。
- 本轮复用范围为公告发布管理、个人通知中心、业务发送入口与实时更新；角色变更作为业务接入示例。不纳入邮件、短信、微信等外部渠道或审批待办的业务状态。
- 首版实时能力承诺单 Go API 实例，使用 PostgreSQL 部署，不要求 Redis 或 MQ。多 API 实例的跨实例投递不在本轮承诺内。
- 不使用定时轮询更新消息，采用 SSE 推送变化；允许连接心跳与断线重试，不在连接失败时降级轮询。

### 公告生命周期与阅读

- 公告支持草稿、立即发布、可选到期时间和主动撤下；不提供预约发布或发布审批。
- 草稿可编辑；发布后内容固定，更正采用撤下旧公告并发布新公告。内容为标题与纯文本正文，不提供富文本。
- 公开公告在登录页和登录后的公共布局均有公告栏；站内公告在登录后的公告栏和公告列表展示。
- 公告不建立逐人已读记录，不要求确认收到；关闭公告栏只影响当前标签页本次访问，公告仍可从列表查看，新公告仍会提示。
- 个人通知沿用铃铛、未读数和“我的通知”；打开详情才已读，支持全部已读。在线收到新通知时给予一次轻提示。
- 默认不自动弹窗、不播放声音、不发送浏览器桌面通知。

### 实时体验与恢复

- 正常网络下，发布成功后 2 秒内更新在线页面。
- 消息先持久化再推送变化；实时连接失败不影响已成功保存的消息。
- 首次打开、断线重连及服务重启后重新查询完整状态；离线期间的消息不逐条补弹。
- 公告发布、撤下和到期后的页面更新须遵守上述实时体验与可见性规则。

### 容量验证基线

- 单 API 实例，100 条并发 SSE 连接，最多 1,000 个启用账号的全体用户通知。
- 连接数包含匿名访问、多标签页和多设备；同时建立的公开流与登录流分别计数。
- 该基线是测试规模，不是产品硬上限，也不承诺任意规模下均达到 2 秒更新目标。
- 在该规模的正常网络测试中，记录发布成功至在线客户端完成页面状态更新的延迟；使用 PostgreSQL 验证，记录机器配置、数据库类型、测试负载和实测延迟。
- 更大规模与多实例部署由实际项目另行验证。

### 管理权限与历史

- ADMIN 管理公开公告、站内公告与手动通知，服务端独立校验管理权限。
- 普通用户只能查询当前有效的可见公告及自己的通知；不提供任意发送接口，不增加角色或部门受众条件。
- 公告到期、撤下后不再向普通用户提供列表或正文；已经打开的详情也提示失效并停止展示正文。
- 草稿、到期和撤下的公告只供管理员查询，历史记录不自动清理。
- 沿用现有通知规则：指定接收人必须为启用账号，任一指定接收人失效则发送整体失败；通知发布后不可编辑或撤回，接收记录持续保留。

### 业务发送与多页面体验

- 提供后端业务发送入口，接受接收用户、标题、纯文本正文和可选站内跳转路径，无需业务模块调用通知 HTTP 接口。
- 通知、业务操作和审计在同一事务提交；持久化通知失败则业务回滚，提交后实时推送失败不回滚。
- 角色变更作为接入示例；不提供模板管理、异步补发和独立的发送去重平台，业务操作自身判断是否应产生新消息。
- 所有已登录页面同步通知列表与未读数，包括详情已读和全部已读的变化。
- 只有获得焦点且可见的页面给予新通知轻提示，其他页面静默更新；不做跨设备提示去重。
- 退出登录、会话失效或账号禁用后停止个人实时连接，清除页面个人消息；公开公告仍可访问。

## 实施约束

- 沿用现有 Authorization Bearer 认证。前端用 fetch 读取 SSE 流并处理重连；不把登录 token 放入 URL，不更改现有认证契约。原生 EventSource 的构造参数仅包含 URL 与凭据选项，不能直接沿用现有 Authorization 请求头；参见 [WHATWG SSE 规范](https://html.spec.whatwg.org/multipage/server-sent-events.html)。
- 匿名公开流只传递公开公告变化；登录流只传递该用户可见的变化。登录流身份失效时不得继续发送个人事件，不影响匿名公告能力。
- JWT 到期应关闭连接；连接建立时鉴权之外，发送个人事件前须确认会话仍有效，并借助心跳检查撤销状态。心跳与认证检查不查询消息，不构成消息轮询。登录态变更立即中止前端旧连接。
- 事务拥有方只能在提交成功后广播；角色变更的 RecordRoleChange 在用户事务内部执行，不能在该方法内直接广播。业务发送接口不得暴露 GORM 或 Gin 类型给业务 Service；事务内持久化留在 Repository 边界。
- SSE 传递变化提示，REST 返回持久化状态。初次同步和重连时先建立订阅，再获取快照，并处理同步期间的变化，避免查询后才订阅造成漏更新；读取失败允许有界重试和用户手动刷新，不启动定时消息查询。
- 慢连接、重复事件及短时间连续变更不能导致无限队列或重复提示；丢失实时提示后通过重连快照恢复。
- 公告到期不能依赖浏览器轮询：服务端安排到期变化通知，页面按到期时间停止展示，查询接口始终检查有效性。重启后重新加载有效公告与到期安排。
- 站内跳转只接受本系统路径，拒绝外部地址与脚本协议；目标业务页沿用自身鉴权。没有路径时打开通知详情，列表预览与跳转入口不能绕过通知已读规则。
- 管理写操作沿用事务内审计；公开接口永远不返回草稿、撤下公告、站内公告、个人消息或接收信息。
- 单实例内共享事件分发设施，匿名与登录页面分别管理连接；开发与部署文档说明反向代理流式响应、缓冲和连接超时设置。

## 验收场景

1. 未登录访问可读取有效公开公告，不能读取站内公告、个人通知或管理信息；登录后公开公告与站内公告均按规则显示。
2. 发布后新建账号可以看到有效站内公告，不能补收历史全体用户通知；指定通知只能由接收人读取。
3. 草稿可编辑，发布后正文不可修改；发布、撤下和到期更新在线页面，失效公告列表与详情不再对普通用户展示，管理员历史保留。
4. 关闭公告栏不产生已读或签收记录，仅影响当前标签页本次访问；公告列表仍可查看，新公告重新提示。
5. 在线发布与通知到达、已读状态变化在正常网络下 2 秒内反映到相关页面；预览不算已读，详情与全部已读同步到同用户其他页面。
6. 断网、服务重启、慢连接导致重连后，列表与未读数恢复为数据库状态，不重复补弹离线消息；无定时查询消息或轮询降级。
7. 非 ADMIN 管理操作被拒绝；禁用、登出或过期会话停止个人连接且不再接收个人事件，公开公告保持可访问。
8. 业务事务或审计失败时既无持久化通知也无实时事件；事务成功但广播失败时业务保持成功，后续查询和重连可见通知。
9. 角色集合实际变化才发送通知，重复保存相同角色不发送；示例经统一业务入口实现且保持事务原子性。
10. 恶意站外跳转路径被拒绝，合法站内跳转遵守业务授权；公开流与个人流没有数据串流。

## 验证计划

- 先补充以上关键行为的后端测试，再实现；数据库 migration、权限隔离与事务契约覆盖 PostgreSQL。
- 使用隔离数据库执行迁移验证及集成测试；日常检查使用 task backend:check，PostgreSQL 集成测试使用 task backend:integration。
- 前端执行 task frontend:lint 与 task frontend:build，并验证未登录访问、双标签页、断网重连、账号退出及到期撤下流程。
- 使用可控超时验证流式更新，运行期间检查 /health 与 /ready，结束后关闭测试连接与进程。
- 在上述容量基线下验证群发和在线更新，报告实测延迟及未达目标的情况；设计基线不代替实际测试结论。

## 实施顺序

1. 公告模型、migration、生命周期与匿名/登录查询接口；验证权限隔离、有效性和管理员历史。
2. 统一业务发送入口与提交后事件分发，迁移角色变更示例；验证通知、审计与业务原子性。
3. 匿名及登录 SSE、会话处理与同步恢复；验证提交后广播、断线重连和无消息轮询。
4. 公告管理与展示、通知中心与多页面同步；验证未登录访问、已读、提示与站内跳转。
5. PostgreSQL 契约、容量基线、前后端检查与部署文档；记录验证证据。

新增或变更接口同步 Swagger / 契约文档；实现依然在 web/ 和 server/ 中进行。

## 已核查现状

- 当前没有独立公告模型；通知接口均要求登录，不能供匿名访问。
- 全体用户通知在发布事务内建立接收记录，新建用户不补收历史通知。
- 顶部铃铛在挂载时加载，页面可见时每 30 秒查询未读数与最近五条；没有 SSE / WebSocket。
- 打开详情标记已读，列表与预览不算已读；支持全部已读。
- 通知发布后不可编辑或撤回，历史持续保留。管理员可以查看接收人数和汇总已读人数。
- 角色变更已有事务内通知接入，但尚无通用业务发送入口。[ADR-0007](../../adr/0007-atomic-site-notifications.md)规定角色变更、通知和审计原子提交，本轮尚未改变该决策。

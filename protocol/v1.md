# Agent—Server 协议（v1 历史事实与 v2 契约）

> 2026-10-24 状态：用户已确认 [ADR 0030](../docs/adr/0030-local-device-responsibilities-and-configuration.md)、[需求规格](../docs/requirements/local-device-maintenance-spec.md) 和[实施拆分](../docs/history/requirements/local-device-maintenance-plan.md)。本文同时记录两件事，不能混用：
>
> - **v1 历史契约**：现有二进制、旧部署及已有现场事实；从[v1 身份与连接](#v1-身份与连接)起至文末原文保留。
> - **v2 契约**：本轮 Server 数据与协议契约工作包冻结的接入、测量窗口、摄像头、图片、设备配置与参数备份约定。v2 实施尚未完成现场验收。
>
> 不兼容变化与升级顺序见下文。任何新实现不得以 v1 的 key／配对、前后两图或 Agent 相机上传作为正式采集门槛；旧二进制也不会因本文加注而自动获得 v2 能力。

实现基线对应 [Issue #3](https://github.com/EziosWJ/weigh-bridge/issues/3)。agent-mock 与真实 Agent 使用同一契约，系统不按模拟／正式来源分流。当前目标是连接本厂业务服务，见[当前总规格](../docs/requirements/standalone-site-spec.md)；D12／打印已有部分现场交付，完整设备闭环仍待验收。

## v2 不兼容变化与升级顺序

### 不兼容变化

1. **接入身份**：v2 不再发送 `Authorization`、`X-Agent-ID`、`X-Scale-ID`。Agent 只配置 Server 地址；Server 按本厂唯一地磅建立运行关联。旧 key、配对文件、人工 Agent 编号不再是接入门槛。
2. **正式采集依据**：v2 用测量窗口（`measurement.*`）取代 Server 下发 `capture.request` 由 Agent 同时取图上报的模式。正式采集要求客户端声明并实现 `measurement.window.v2`；不支持时明确返回 `agent_capability_missing`，不得静默回退到仅比较前后读数或 500 ms 状态。
3. **摄像头归属**：摄像头增删改、RTSP 取帧、图片保存、识别和 MediaMTX 同步归 Server。Agent 不再接收相机配置，不再上传正式称重图片。v1 的 `camera.updated`、`capture.request`／`capture.result`、`camera.test.request`／`camera.test.result` 仅为旧客户端兼容保留。
4. **图片对象**：新图片由 Server 生成稳定对象，带摄像头快照、来源、取得状态和时间；旧 `front`／`rear` 图片编号与读取地址继续可读，历史证据不改写。
5. **设备配置**：Agent 只持有串口、波特率和打印／校准参数。保存并应用是一次操作；Server 自动保存最近成功生效参数及摘要，恢复必须显式发起，不能随连接自动套用。

### 升级顺序

1. 先升级 Server 并执行新增 Goose migration。迁移只新增表、列和索引，在旧绑定行上写 `retired_at`，不删除业务数据、图片、打印尝试或历史身份。Server 启动后仍能读取 v1 消息，同时接受 v2 无密钥连接。
2. 再升级真实 Agent 和 agent-mock：删除 key／人工编号启动要求，连接后先发送 `agent.hello`。旧 Agent 仍可上报重量和打印，但正式采集会因缺少 `measurement.window.v2` 被拒绝。现场不得把该拒绝改判为成功。
3. 在网页配置摄像头、视频服务与抓拍策略；确认 Server 能直接访问摄像头 RTSP 和 MediaMTX 管理接口。
4. 旧 key／配对文件不再作为运行凭据。保持旧身份行仅用于历史排查，不做重新绑定；换机也不需要换编号或密钥。
5. 回滚只按数据库备份恢复；不得用 schema 回滚删除新表而保留一半新流程，也不得清空现有业务库。

## v2 身份与连接

### 连接与握手

Agent 主动连接 `GET /api/agent/ws`，线上使用 WSS，本机可使用 WS。连接不携带认证头。Server 从本厂身份（`wb_local_identity`）和该厂唯一启用地磅（`wb_scale`）解析运行关联；设备通道不能创建厂区、地磅或用户会话。

连接建立后 Agent 应立即发送：

```json
{
  "version": 2,
  "type": "agent.hello",
  "messageId": "unique-id",
  "occurredAt": "2026-10-24T10:00:00+08:00",
  "payload": {
    "protocolVersion": 2,
    "agentVersion": "0.2.0",
    "hostname": "weigh-agent-01",
    "capabilities": ["measurement.window.v2", "maintenance.effective-config.v2", "maintenance.cups-queues.v1", "maintenance.parameter-backup.v1"]
  }
}
```

Server 回复 `agent.hello.ack`，沿用请求的 `requestId`：

```json
{
  "version": 2,
  "type": "agent.hello.ack",
  "messageId": "unique-id",
  "requestId": "hello-request-id",
  "occurredAt": "2026-10-24T10:00:00+08:00",
  "payload": {
    "protocolVersion": 2,
    "siteId": 1,
    "scaleId": 1,
    "agentId": "agent-01",
    "capabilities": ["measurement.window.v2"],
    "serverTime": "2026-10-24T02:00:00Z"
  }
}
```

`agentId` 是内部排障标识，不是密钥、不是人工编号，也不要求 Agent 写入连接配置文件。主机名、连接 IP、版本和能力只用于排障和命令前检查。

### 错误语义

拒绝连接或拒绝命令时，Server 发送 `error`，payload 为 `{code,message}`；能关联命令时原样带 `requestId`。接入相关错误码：

| code | 含义 | Agent 行为 |
| --- | --- | --- |
| `site_not_initialized` | 本厂尚未完成初始化 | 显示“请先完成本厂配置”，正常重试；不得自建厂区／地磅 |
| `scale_not_initialized` | 本厂身份存在但唯一地磅缺失或停用 | 显示配置原因并重试 |
| `server_unavailable` | 本厂身份暂时无法读取（非未初始化） | 记录原因并按正常重连策略重试 |
| `agent_conflict` | 同磅已有连接 | 不抢占；等待原连接断开或管理员踢出 |
| `agent_protocol_unsupported` | 协议版本高于 Server 支持 | 停止重试并提示升级顺序 |
| `agent_capability_missing` | 当前连接缺少命令所需能力 | 不得降级执行；提示升级 Agent |
| `invalid_message` / `invalid_payload` | 封装或字段无效 | 修正消息；持续无效应停止重发 |

同磅先连接者保持，后连接者收到 `agent_conflict`，Server 不改变已在线连接的状态或设备依据。正常断连可重连；后台踢出沿用既有权限、审计、`connectionId` 匹配和退出确认规则。

### 请求关联与连接代次

每个命令和回复带 `requestId`；回复必须原样沿用。Server 只接受当前连接、当前未结束请求的第一条回复。连接变化、超时、重复或迟到回复不得形成有效样本。重量仍使用吨制十进制字符串，最多三位小数；`stable` 和 `deviceOk` 必须显式给出。

## v2 测量窗口

正式采集的顺序固定为：Server 开始并确认测量 → Server 取得并保存本次图片 → Agent 结束并核实 → Server 保存样本 → 操作员确认时再次核实同一依据。任何一个阶段失败都不得形成有效样本。

### 消息

| type | 方向 | payload |
| --- | --- | --- |
| `measurement.begin.request` | Server → Agent | `captureId`、可选 `capturePolicyRevision`、`cameraConfigVersion` |
| `measurement.begin.result` | Agent → Server | `accepted`、`generation`、`state`、可选 `code`／`message` |
| `measurement.end.request` | Server → Agent | `generation` |
| `measurement.end.result` | Agent → Server | `verified`、`generation`、`state`、`endedAt`、可选 `code`／`message` |
| `measurement.cancel.request` | Server → Agent | `generation`、可选 `reason` |
| `measurement.cancel.result` | Agent → Server | `cancelled`、`generation`、可选 `code`／`message` |
| `measurement.verify.request` | Server → Agent | `generation`（操作员确认前） |
| `measurement.verify.result` | Agent → Server | `valid`、`generation`、`state`、`checkedAt`、可选 `code`／`message` |
| `measurement.invalidated` | Agent → Server | `generation`、`reason`、`state`、`at` |

`state` 为 `{weight,unit:"t",stable,deviceOk,error?,at}`，是 Agent 本地原子取得的读数，不是 Server 缓存的 500 ms 状态。

### 代次与有效性

- `generation` 由 Agent 在 begin 时生成，同一测量窗口内稳定不变，跨整个取图窗口持续有效，并保存到 `wb_sample.measurement_generation`，用于操作员确认前的 `measurement.verify.request`。
- Agent 必须在每个已解析帧、稳定变化、故障变化、串口错误／过期、设备重载、断连和进程重启处锁存失效。即使之后恢复原重量、原稳定状态，本代次也不得恢复有效。
- 相同有效稳定帧重复到达不增加失效代次，也不引入“必须再稳定若干秒”的门槛。现有 500 ms 上报和 20 ms 快照轮询不能作为唯一依据。
- Server 只接受与当前连接、当前 `captureId`／`generation` 关联的回复；超时、断连、迟到、重复回复无效。Server 不得长时间持有阻止设备状态更新的锁跨越网络取图。
- 操作员确认不新增固定时限；条件变化沿用失效和重新采集规则。确认时必须向 Agent 核实同一代次仍为当前有效依据。

测量拒绝／失效错误码：`device_unavailable`、`device_unstable`、`device_fault`、`device_stale`、`weight_changed`、`generation_invalid`、`generation_superseded`、`cancelled`、`connection_changed`。结果中的 `code` 与 `error` 使用同一语义；不得只给布尔值而不说明原因。

## v2 摄像头与视频服务（Server 模块）

摄像头和 MediaMTX 配置存 Server PostgreSQL，不通过 Agent 通道下发。Agent 的 `camera.updated`、`camera.test.*` 仅为旧客户端保留。

### 摄像头对象

管理路径：`/api/weighing/cameras`（列表、新增）、`/api/weighing/cameras/:id`（读取、修改、删除）、`/api/weighing/cameras/settings`（抓拍超时与识别源）、`/api/weighing/cameras/video`（MediaMTX 设置）、`/api/weighing/cameras/sync`（显式同步）、`/api/weighing/cameras/:id/test`（测试抓拍）、`/api/weighing/cameras/:id/preview`（实时预览）. 最终路由前缀由 DC-03 按现有路由风格落地，但字段名和语义冻结如下。

安全读模型：`id`、`publicId`、`name`、`sourceUrl`、`username`、`hasPassword`、`captureEnabled`、`enabled`、`version`、`stream`、`createTime`、`updateTime`。秘密不回显到普通响应、图片元数据、日志或预览地址。

写入模型：`name`、`sourceUrl`、`username?`、`password?`、`passwordAction?`、`captureEnabled?`、`enabled?`、`version?`。

- `passwordAction` 取值 `keep`（省略或空密码时的默认）、`set`、`clear`。空密码默认保持；只有 `clear` 才清除已有秘密。
- `captureEnabled=true` 表示参与正式称重抓拍；其余摄像头只用于预览。数量允许 0..N，不以 `front`／`rear` 决定含义。
- `version` 是行版本。修改必须匹配当前版本，否则返回冲突；并发保存不能混用新旧配置。新增忽略客户端版本。
- 站点级 `configVersion` 在任何影响抓拍内容的变更（增删、名称、源、凭据、抓拍用途、抓拍超时）时递增；`wb_sample.camera_config_version` 冻结采集时的值。
- 删除为软删除：历史图片和视频路径清理信息继续可用。删除或取消识别用途时，若该摄像头是识别源，同时清除识别源并提示识别停用；不得静默改选其他摄像头。

### 视频服务与托管路径

`VideoSettings` 字段：`apiUrl`、`apiUsername`、`hasApiPassword`、`whepBaseUrl`、`version`、`syncState`、`syncError`、`syncedVersion`、`updateTime`。`apiUrl` 是 Server 可达的 MediaMTX 管理接口；`whepBaseUrl` 是浏览器可达的公开 WHEP 入口。管理凭据不下发浏览器。

每个摄像头在 `wb_camera_stream` 有一行受管路径：`mediaPath`、`desiredVersion`、`syncedVersion`、`state`（`pending`／`synced`／`error`／`removing`／`removed`）、`lastError`。Server 只操作系统持久标识和摄像头 ID 对应的路径，不扫描、不覆盖、不删除其他流。同步结果绑定版本：只有与当前期望版本一致的回复才能标记已同步；旧请求迟到不得覆盖新状态。离线删除保留清理信息直到远端确认移除。

## v2 图片对象与历史兼容

新图片对象字段：

```json
{
  "id": "srv_<system-generated>",
  "url": "/api/weighing/images/<id>",
  "sha256": "内容摘要",
  "source": "server",
  "cameraId": 3,
  "cameraPublicId": "cam_xxx",
  "cameraName": "西门抓拍",
  "status": "captured",
  "capturedAt": "2026-10-24T10:00:05+08:00",
  "width": 1920,
  "height": 1080,
  "bytes": 245000
}
```

- `status` 为 `captured`／`failed`／`missing`。失败对象保留摄像头快照、错误和时间，但不带 URL 和伪造摘要。
- 历史 Agent 图片继续使用 `id`、`view:"front"|"rear"`、`url`、`sha256`；旧编号格式和 `/api/weighing/agent-images/:imageId` 读取保持不变。新图片不受前后两图限制，校验以摄像头集合和逐台状态为准。
- 图片元数据保存当时摄像头 ID、名称、源地址（不含凭据）、时间、内容摘要和实际取得状态；改名、删除或调整用途不改写历史证据。
- 车牌候选来源单独保存为 `plateEvidence.source`：`manual`（人工录入）、`agent`（Agent 现场观察）或 `server`（Server 调用的外部识别）。Server 直连图片不等于 Server 识别；识别未配置或失败而沿用 Agent 观察时，来源必须是 `agent`。

## v2 设备配置、CUPS 与参数备份

Agent 只持有串口、波特率和打印／校准参数。Server URL、主机信息、连接／暂停状态、测量窗口和执行请求不进入备份，也不随恢复覆盖。

| type | 方向 | payload |
| --- | --- | --- |
| `agent.config.state` | Agent → Server | `configVersion`、`digest`、`serial`、`print`、`appliedAt`、`running`、`deviceState`、可选 `serialState`／`printerState` |
| `agent.config.apply.request` | Server → Agent | `baseVersion?`、`settings`（仅 serial/print） |
| `agent.config.apply.result` | Agent → Server | `status`、可选 `code`／`message`、`configVersion`、`digest`、可选 `appliedAt`／`effective` |
| `agent.config.restore.request` | Server → Agent | `backupId`、`baseVersion?`、`backup`（完整 `settings`、版本、摘要、时间） |
| `agent.config.restore.result` | Agent → Server | 同 apply result |
| `agent.config.backup` | Agent → Server | `configVersion`、`digest`、`settings`、`appliedAt`、可选 `restoreOf` |
| `printer.queues.request` | Server → Agent | `{}` |
| `printer.queues.result` | Agent → Server | `queues:[{name,state,description,isDefault}]`、`at`、可选 `code`／`error` |

`status`：`applied`（成功）、`rejected`（校验失败且有效配置不变）、`unknown`（结果未知，先读取实际状态，不自动重试写操作）、`rolled_back`（应用失败但已恢复上一成功配置）、`rollback_failed`（恢复失败，设备不可用，保留维护连接）。错误码：`config_invalid`、`config_conflict`、`device_busy`、`apply_unknown`、`rollback_failed`、`queues_unavailable`。

Server 保存最近一次 Agent 实际成功生效的配置到 `wb_agent_config_backup`（时间、摘要、仅设备设置），界面显示备份时间与摘要。备份滞后或失败不倒置已生效事实；恢复必须由管理员显式发起，Agent 核对实际端口、队列和校准后再应用。只读备份不接受普通配置编辑。

## v1 历史契约（2026-10-23 及以前）

### v1 身份与连接

Agent 主动连接 `GET /api/agent/ws`，线上使用 WSS，本机可使用 WS。每个请求携带：

- `Authorization: Bearer <连接密钥>`
- `X-Agent-ID: <配置的 Agent 编号>`
- `X-Scale-ID: <配置的地磅数字 ID>`

Server 从本厂配置（数据库绑定）读取 `{id, scale_id, key}` 映射；业务 API 配置文件不再接受 `weighing.agents`、`weighing.agent_id`、`scale_id`、`agent_key`，出现非空绑定即拒绝启动。未完成本厂配置或密钥为空时禁止接入。每磅同一时间只允许一个 Agent，真实 Agent 与 mock 互斥；同磅重复连接返回 `error`，`code=agent_conflict`，保留已在线连接与原设备依据。不同地磅各自管理连接和状态。此身份只能处理设备数据与设备命令，不能执行用户业务确认。重连必须重新上报状态，旧采样不能复活。

所有重量消息使用吨制**十进制字符串**，最多三位小数，例如 `"32.56"`；不用 JSON 浮点数传重量。`stable` 与 `deviceOk` 必须由 Agent 显式给出，缺省不能视为正常。零重量允许上报，但不允许确认称重。

### 封装

```json
{
  "version": 1,
  "type": "device.state",
  "messageId": "唯一消息编号",
  "occurredAt": "2026-10-19T10:00:00+08:00",
  "payload": {"weight": "32.518", "unit": "t", "stable": false, "deviceOk": true}
}
```

命令及回复另带 `requestId`，回复必须原样沿用命令的值。消息编号最长 128 字符；消息最大 128KiB，图片不进入 WSS。时间使用 RFC3339，Server 另记接收时间；Agent 时间不作为新鲜度的唯一依据。

### Agent 上报

| type | payload |
| --- | --- |
| `device.state` | `weight`、`unit:"t"`、`stable`、`deviceOk`，可选 `error` 故障说明 |
| `plate.observed` | `candidate` 候选车牌、`failed` 是否识别失败、`at` 识别时间；失败时传空候选 |
| `camera.updated` | `images` 数组，包含上传后取得的前、后视角图片编号 |
| `heartbeat` | 空对象；Server 回复 heartbeat |

推荐每 500ms 发送当前重量；无重量更新时每 5 秒心跳。15 秒无有效消息断开连接，重量最后更新时间超过 3 秒则不可采集和确认，即使心跳正常也不会将旧重量视为新数据。mock 每次上磅发送 4 秒波动重量与 `stable:false`，再持续发送目标重量与 `stable:true`。

实时状态由已登录 Web 查询 `GET /api/weighing/scales/:id/device`，需业务查询权限及目标厂区查询授权。返回 `connectionId`（当前连接编号，离线清空）、Agent 状态、最近识别与图片及 `revision`；revision 是**字符串**，避免浏览器丢失整数精度。每次重量／稳定／故障／车牌变化、失效后恢复、踢出或重新连接都会使旧依据失效；相同稳定值重复上报不使其失效。

### 后台踢出

`POST /api/weighing/scales/:id/agent/kick` 需要 `weighing:agent:kick` 动作权限及目标厂区操作授权，输入 `{connectionId}` 必须匹配当前连接；连接变化时返回业务冲突，不踢后来建立的连接。Server 先记录请求审计，再使未确认设备依据失效并发送：

```json
{"version":1,"type":"agent.kick","messageId":"unique-id","requestId":"kick-request-id","occurredAt":"2026-10-21T10:00:00+08:00","payload":{"reason":"管理员踢出"}}
```

支持的客户端立即以相同 requestId 回复 `agent.kicked`（payload 为 `{}`），然后正常结束整个进程，停止自动重连；mock 的 HTTP 控制服务也结束。打印客户端须由独立接收路径处理，正在等待维护暂停或打印提交时也能接收。正常网络中断继续自动重连。踢出不永久封禁身份，手动启动或工控机重启后仍可接入。

Server 最多等待 2 秒确认，随后关闭对应连接，返回 `{disconnected, exitConfirmed}`。`exitConfirmed` 表示客户端确认收到退出指令，不能据此验证操作系统进程状态；未确认时明确显示“已断开，退出未确认”。已踢连接不再接受采集和打印回复。已成功提交业务保留，未决打印按结果未知处理，不自动重发；退出不取消 CUPS 既有作业。

### 图片上传与读取

Agent 使用同一认证头发送 `POST /api/agent/images`，`multipart/form-data` 字段：`file`、`view`（`front` 或 `rear`）。仅支持 PNG/JPEG，单图不超过 10MiB，像素不超过四千万。返回现有 API envelope：

```json
{"code":200,"message":"success","data":{"id":"Server生成的图片编号","view":"front","url":"/api/weighing/agent-images/图片编号","sha256":"内容摘要"}}
```

图片消息及采集结果中使用上述对象；Server 以图片编号重新核对归属、视角、摘要与地址，不信任上报的 URL。前后视角各一张，不能重复视角或引用其他地磅图片。

用户读取 `GET /api/weighing/agent-images/:imageId` 需要用户 Bearer、业务查询权限及图片所属厂区查询授权，浏览器使用带鉴权的图片请求。文件保存于 `weighing.image_dir`，是称重依据，不放入通用临时文件清理范围。备份和迁移必须同时保留业务数据库与该目录。

### 采集

用户通过原有操作会话及权限发起 `POST /api/weighing/samples`；浏览器只提供任务、阶段相关业务输入和人工核对信息，不提交重量或抓拍内容。

Server 按本厂业务配置下发 `capture.request`，payload 为 `{"captureRequired":true}` 或 `{"captureRequired":false}`。缺省／旧空对象仍表示 true。true 时 Agent 采集本次重量和前后抓拍，完成图片上传后返回 `capture.result`：

```json
{
  "version": 1,
  "type": "capture.result",
  "messageId": "新消息编号",
  "requestId": "原采集命令的requestId",
  "occurredAt": "2026-10-19T10:00:05+08:00",
  "payload": {
    "success": true,
    "weight": "32.56",
    "unit": "t",
    "stable": true,
    "deviceOk": true,
    "capturedAt": "2026-10-19T10:00:05+08:00",
    "images": [
      {"id":"前视角上传编号"},
      {"id":"后视角上传编号"}
    ]
  }
}
```

2026-10-23 按 [ADR 0027](../docs/adr/0027-optional-weighing-capture.md) 扩展：false 时摄像头未启用／未配置直接采重，已配置时尝试抓拍；图片失败可返回 `success:true`，但仪表及重量条件仍须满足。结果增加 `imageStatus`（`complete`／`disabled`／`capture_failed`／`upload_failed`）及脱敏 `imageError`；已有成功上传图片仍随 `images` 返回。服务端只在请求明确 false 时接受带明确状态的缺图结果，且仍验证每个已提交引用；true 和未扩展旧 Agent 结果仍要求前后两图。新 API 与 Agent 应一起升级，旧 Agent 不会因 API 关闭开关就自动支持无图。

失败时 `success:false` 并提供 `error`。Server 最多等待 10 秒；只接受当前连接、未结束请求的第一条回复，并校验重量与当前稳定状态一致。重复、旧连接、已超时回复不会生成新有效样本。采集等待期间的失稳／重量变化同样使请求失败。

Server 绑定操作者、操作会话代次、任务版本、业务摘要及抓拍策略快照（`captureRequired`／`capturePolicyRevision`）保存样本，采样不设时间有效期（`expiresAt` 为 `null`，历史值不再用于判定失效）。操作员继续通过首磅／回磅／重称接口核对确认；抓拍策略切换、断连、重量变化、失稳、故障和业务绑定变化使未确认样本失效。断网恢复先查询原提交结果，不自动补办历史确认。

### 摄像头维护测试（2026-10-23 可选扩展）

业务维护接口经既有管理权限校验并暂停新的采集／确认后，可下发 `camera.test.request`，payload 为 `{}`。真实 Agent 使用当前生效配置取得前后新图片，不读取仪表、不执行识别、不调用业务图片上传接口，以相同 requestId 回复 `camera.test.result`：

```json
{"at":"2026-10-23T10:00:00Z","views":[{"view":"front","success":true,"jpeg":"JPEG小图的base64"},{"view":"rear","success":false,"error":"摄像头测试抓拍失败"}]}
```

每张成功小图最多 320×180、40KiB，两路整包在现有 128KiB 消息限制内。Server 最多等待 12 秒，校验当前连接、请求关联、前后视角和 JPEG 尺寸；仅返回给维护请求，不更新 device.state 图片、不生成业务图片 ID 或 sample。仪表未连接／未稳定不妨碍此测试，但正式 `capture.request` 的仪表及证据条件保持。采集和测试在 Agent 内互斥；忙碌或旧 Agent 不支持时明确失败，不改用缓存。

### 打印

2026-10-19 精简纸单补充：`ticket.printSheet` 为可选的 `weighing-compact-v1` 视图，包含 `widthMm=210`、`heightMm=99`、`layers=5`、`title`、`marks` 和 `rows`（每行若干 `{label,value}`）。`layers` 表示五联纸一次复写，不得解释为打印五份。精简视图仅含最终重量及约定交接字段，Web 与 Agent 共用；完整 ticket 快照继续保留。版式及真实设备边界见 [单据查看与针打需求](../docs/history/requirements/ticket-view-print-spec.md)。

Server 先保存打印尝试，再下发 `print.request`。`requestId` 为 `print-<尝试ID>`，payload：`attemptId` 和 `ticket`。ticket 是当版单据的完整快照，包含单号、业务、毛皮净重、确认依据、状态及调整信息，Agent 不重新计算或查询当前资料覆盖它。

Agent 以相同 requestId 返回 `print.result`：`attemptId`、`status`（`printed` 或 `failed`）、可选 `reason`。`printed` 表示设备执行成功，不能仅因已收到任务而上报。只处理当前连接已下发尝试的首个未决结果，不覆盖操作员已完成的核实，也不重复计数。

无回执或断连则结果未知。Server 重启、Agent 重连、重复用户请求均不自动重发旧打印。操作员核实和补打沿用现有规则；明确失败且未出纸可重试，成功或无法排除出纸需说明原因补打。

### 错误与阶段限制

协议错误返回 `error`，payload 包含 `code`、`message`，能够关联请求时带原 requestId。HTTP 沿用统一 envelope。Agent 不缓存离线正式确认，不承担业务权限、毛皮重语义、运输任务或单据权威判断。2026-10-21 增加按配置映射管理多地磅连接及 kick，未建设通用设备注册／审批后台。本协议不提供离线正式确认或自动补传；柯力 D12 仪表已按本契约接入现有真实 Agent，摄像头 HTTP／RTSP 抓拍及独立维护测试已实现软件通道，真实设备尚待验收，实物打印及本地维护的准确交付以根 CONTEXT.md 和设备交付记录为准。

2026-10-19 操作规则修订：只要现场条件与业务绑定未变化且操作会话仍有效，操作员可持续核对，不因采集后经过固定时长使样本失效。设备上报保鲜检测、操作会话租期及采集请求超时仍按各自规则执行。

### Agent 配置维护（2026-10-23）

Agent 上报 `maintenance.state`，payload 为 `{config: 脱敏有效配置, running: 设备执行是否运行}`。配置对象不包含 Agent 密钥、旧摄像头或识别服务凭据；业务归属仍由已认证设备连接决定。

API 下发 `maintenance.request`：`{method,path,query?,body?,actorId,clientIp?}`。仅复用设备维护页面现有操作：状态、作业、配置读取／保存／导入、应用／恢复、设备执行启停、测试打印／抓拍、日志及维护记录。Agent 在本机执行，以同一 requestId 回复 `maintenance.result`：`{status,json? ,text?}`；json 是原接口 JSON，text 是文本结果，HTTP 页面契约保持。

API 每次操作复用原维护 RBAC、本站绑定及操作者审计；Agent 不另开 HTTP 维护端口。请求超时、断连或结果不明时重新读取实际配置／状态核实，不自动重放写操作。停止的是设备执行，控制进程和连接保留；Agent 整个进程离线不能远程维护。应用会使未确认旧采样失效，但不改写已提交业务或清空打印账本。详见 [ADR 0026](../docs/history/adr/0026-agent-owned-device-maintenance.md)。

# Phase 2A 称重页面覆盖说明

## 2026-10-21 多厂区入口

新增 `/weighing/sites`，采用 Detail Pattern 的状态摘要及入口变体：复用 PageHeader、ContentCard、StatusTag、EmptyState、Button 与 FormDialog，按厂区排列响应式面板。仅列已授权厂区，分别提供称重台入口及有权限时的 Agent 踢出操作；加载、失败、未知和空授权明确区分。

用户管理的厂区分配复用现有 FormDialog 和选择控件，区分未授权、仅查询及查询与操作；角色动作权限继续独立生效。列表沿用原 Pattern，仅增加厂区列与筛选。

工作台必须绑定 `scaleId`，窗口名称按地磅区分，顶栏明显显示厂区和地磅。定位任务、切换车辆和核对流程更新 URL 时保留地磅参数，工作台不静默换厂。单厂区用户也从厂区面板进入。

## 2026-10-18 操作员业务修订（前端模拟已实现）

沿用 Standard List / Form / Detail 变体。操作员可直接办理纠错、终止、单磅重称、作废重开、打印核实／补打及导出；普通隔日回磅不再阻断或要求说明。已有运输疑点保留人工核实入口，无主管审批。

已出单先在单据详情作废，再从原任务详情选择目标首次／二次（注明毛皮和装载状态）办理单磅重称，确认目标装载状态、另一磅有效及新抓拍，随后返回关联作废单重开。无法重采时直接在重开中人工调整最终值。旧单详情与打印预览采用原版快照。下文主管短操作、只下调等描述保留旧设计背景，当前规则以本节及 [交付记录](../../../docs/requirements/operator-weighing-corrections-delivery.md) 为准。

## 工作台紧凑作业变体

工作台沿用 Form / Detail 的业务变体，压缩顶部为车牌栏。运输资料使用“基本信息 / 补充运输信息（选填）/ 找不到资料？”Tab，默认基本信息；补充页显示已填摘要，资料帮助页提供维护入口。切换保留草稿，缺必填资料时回到基本信息并聚焦对应字段。回磅只读运输信息、集中核对弹窗及演示配置／历史复用同一 Tab 组件，支持方向键和 Home / End。Tab 仅切换信息分区，称重采集与人工确认沿用原顺序；详情处置表单保持原完整字段。

桌面左右分区：左侧必要业务信息／回磅依据，右侧为重量和当前操作，使用sticky保持位置。常规1366×768视口需计入240px侧栏及64px顶栏后核对首屏；窄屏正常堆叠，不使用固定高度截断内容。异常及未知提交替换当前操作内容，不挤到新的长提示区。测试标记、人工确认和资料辨认信息始终保留。

## 逐项人工核对

采集后主操作打开既有 Dialog 组成的核对交互，四步依次显示本次实际值；核对进度、上一项、不一致返回与最终汇总明确区分。各步仅记录本次局部核对进度，最终按钮才提交测试称重。核对内容变化立即结束旧会话，不把进度缓存为已确认业务状态。键盘焦点随步骤进入标题，弹窗支持关闭、焦点约束和关闭后还原。

## 模拟摄像头与抓拍

工作台左侧使用紧凑摄像头图片卡，与业务信息并排；桌面右侧重量及确认区继续固定。当前预览为静态内置示例，采集重量同步生成图片快照，不增加单独抓拍步骤。逐项核对第四步展示本次图片、关联手填车牌、采集时间和重量，图片加载后才能继续；点击缩略图使用既有 DetailDialog 放大。任务、单据详情保留逐条原始图片，打印预览展示当前首／回磅图；旧历史无图明确留空。图片放大期间暂停外层弹窗焦点约束与 Escape，关闭后恢复。所有图片标记模拟，示例画面不代表当前车辆或实时视频。

## 人工扣减与双列表

依据：[人工重量调整需求](../../../docs/requirements/manual-weight-adjustment.md)。二次称重逐项核对的最终汇总内只读展示原始重量、填写最终毛皮重及选填原因，由系统反算只读扣减量与最终净重；同一次确认出单，不增加任务状态。弹窗底部固定显示最终毛皮净重及确认按钮，内容区可独立滚动。

原始称重和最终单据为两份独立 Standard List 页面，分别按任务／单据为行，分别使用二次确认／出单日期；单据列表沿用原有路由，新增原始列表入口。详情展示扣减快照和前后值，纸质预览仅显示最终重量；预览中的模拟抓拍也隐藏关联的原始重量。

## 最终重量录入与吨制修订（已完成）

所有业务重量使用吨，精确至 0.001 吨；显示最多三位小数并省略末尾无效零，例如 5.000 吨显示为 5 吨。最终毛皮重默认带入对应原值，可手动下调。核对汇总与更正重开复用同一输入区域，扣减量仅由系统计算。列表、详情、抓拍元信息、预览、CSV、汇总、物料单位和演示重量均已同步。保留既有页面 Pattern、四步核对和固定确认区；旧 kg 缓存由数据迁移统一换算并保留来源值，详见 [交付记录](../../../docs/requirements/weight-entry-tonne-plan.md)。

## 回磅确认汇总左右布局

回磅最终汇总窗口最大宽度为 1080px，桌面左侧集中展示车辆、本次称重、业务资料、首次依据与证据状态，右侧录入最终重量。毛重和皮重各自将原始值、最终输入和系统扣减量纵向对齐，净重区域并排比较原始与最终值，最终净重突出展示；原因选填。宽度不足 768px 时改为上下排列，内容区滚动，底部操作保留可见。前四步和首磅汇总保持紧凑窗口。

原始异常或输入未通过校验时，最终净重显示“待核对重量”，具体原因统一放在固定底栏，避免在重量区重复显示。两项扣减量仍各自独立计算，原始净重与最终重量的出单规则保持不变；更正重开复用相同的重量分组。

## 单据查看与精简针打（2026-10-19）

按 [已确认需求](../../../docs/requirements/ticket-view-print-spec.md) 调整 Detail Pattern：摘要显示车牌、方向、供收方、物料及最终三重；完整业务快照、调整、称重证据和历史在原生 details 区展开。出单结果区与详情共用直接打印操作，预览为可选入口；未知核实和补打在短弹窗办理，不启动浏览器打印。

纸单是固定物理宽度的文档视图，约 210 × 99 mm，黑白、宋体、无后台卡片装饰。窄屏仅纸单容器横向滚动，不能撑破页面；业务操作保持响应式。服务端 `printSheet` 提供标题、标记与精简字段，Web 和 Agent mock 不各自计算另一份业务内容。五联一次复写，不重复渲染五张；真实针打需设备联调。
